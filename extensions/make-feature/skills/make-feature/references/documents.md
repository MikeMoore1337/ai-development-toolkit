# Общий контекст

Один запуск — `.make-feature/<slug>/` в проекте. Канонические idea/architecture/plans используй по ссылкам; не создавай конкурирующую архитектуру. Оркестратор владеет индексом и принятым решением; работники пишут только выделенные файлы.

```text
python3 scripts/workspace.py init --project PROJECT --slug SLUG --request-file REQUEST
```
REQUEST — UTF-8 с дословными словами. Init не затирает существующий запуск. При продолжении читай его индекс.

## Обычная структура
| Файл | Содержание |
|---|---|
| `01-request.md` | Исходные слова без правок; трактовка отдельно |
| `00-index.md` | Цель/режим/причина; этап и актуальные ссылки; принятые D*, открытые вопросы; реальные ID и роли; общий предел/счётчики; следующий шаг |
| `02-solution.md` | C* и baseline; факты/гипотезы/источники S*; варианты и выбранный D*; до/после; главный риск; контракт/источники данных/пути/права/ошибки; T*/зависимости/файлы/проверки |
| `03-verification.md` | C* → действие/команда → фактический результат → receipt/версия → независимый вердикт; запуск и read-back; остаток; доступные данные о расходе |

В решении отдельные короткие разделы «Требования», «Основания и выбор», «Контракт», «План». Не пересказывай код. Заголовок принятого документа: статус draft/accepted/blocked/stale, версия, автор/контекст, ссылки на входы. Полезный урок: ошибка → причина → правило → следующая проверка, внутри приёмки или канонических lessons проекта.

Задания и receipts могут быть компактным JSON в tasks/evidence; новый Markdown-отчёт для каждого вызова не нужен. В ответ работник возвращает статус, изменённые пути, результаты и путь доказательства. Файлы продукта и его README не являются служебной квотой навыка.

## Когда разделять
В deep или большой normal вынеси только независимо используемые части: diagnosis/research/decision/architecture/plan. Назови в индексе, кому и зачем нужен отдельный файл; критерии и текущие D* имеют одного владельца. Нет обязательного набора из десяти документов. Уже существующий запуск со старой схемой продолжай по его индексным ссылкам.

## Выбор
| Вариант | Покрывает C* | Польза и основание | Цена/время | Риск и выход | Вердикт |
|---|---|---|---|---|---|
Матрица нужна при серьёзных альтернативных путях, не для искусственной пары очевидного решения и заведомо плохого. В quick допустимы выбор и причина одной строкой. Измеренное, прогноз и unknown различаются; неизвестная цена не считается нулевой. Причина отказа и условие пересмотра остаются компактно.

Существенное продуктовое решение: вопрос → рекомендованный путь/основание → последствия и цена вариантов → действительный ответ владельца с источником → зависимые C*/T*. Молчание не равно ответу; уже разрешённое обратимое техническое решение принимай сам.

## Актуальность
Принять выход → заменить текущую строку индекса → прочитать с диска. При содержательной замене принятой версии сохрани старую в archive с номером и причиной. Источник запроса, ответы владельца и доказательства не удаляй. Повторы и старые подробности уходят из активного контекста; D*, C*, ссылки и причины отказа остаются.

Изменённый D* делает свои контракты/задачи/проверки stale. Сверь, какие действительно затронуты; не запускай весь конвейер из-за косметической правки. Не отменяй C* ради сокращения текста.

Перед передачей:
```text
python3 scripts/workspace.py check --project PROJECT --slug SLUG
```
Это проверка ссылок и сохранности; содержание принимает независимый контекст в общем проходе приёмки. Приёмщик должен найти требование, выбранный путь, источники, запуск и остаток по индексу без истории чата.

# Делегация

Один запуск агента закрывает один конкретный вопрос или целостный вертикальный результат. Не создавай отдельный контекст для каждого методологического приёма.

| Роль | Когда нужна |
|---|---|
| Исследователь | Непроверенная возможность/ограничение или серьёзные альтернативы; сверяет свои источники и применимость |
| Исполнитель | normal/deep: одна T* или связанный вертикальный результат в выделенных файлах |
| Приёмщик | Каждый результат с новым поведением; одним проходом C*, пользовательский путь, качество/риск и передача |
| Критик и независимый судья | Существенный выбор/план в deep или новый обоснованный спор; один пакет вместо повторов на каждом документе |

В quick оркестратор может писать код, но не выдаёт независимую приёмку сам. В normal обычно достаточно исполнителя и приёмщика; исследования добавляются по конкретному пробелу. Дополнительный аудит не подразумевается словом «безопасность» — назови реальную зону риска.

Перед dispatch: бюджетная reservation, ограниченное задание, версия входов и точные пути записи. После возврата — настоящий ID/provenance, артефакт, версия и статус. Неизвестный ID не выдумывай. Leaf не создаёт свой неучтённый рой; всех потомков учитывают в общем пределе.

Пакет по [шаблону](../templates/task.md): цель и C*/T*; нужные документы/контракт; чтение/запись; запрет менять критерии/чужие файлы; приёмка; время/предел; короткий ответ и файл доказательства. Не включай весь чат, чужие справочники и авторский вердикт проверяющему.

Читающие задачи по разным вопросам параллельны. Пишущие — по зависимостям и владельцам; общий контракт меняет один ответственный. С state.py только один running/interrupted исполнитель. Жди назначенные проверки перед приёмкой.

Актуальный pass переиспользуется для неизменённых входов. Отчёт без результата, версия до исправления и самопроверка автора не заменяют независимость. При смене контракта передай, что именно стало stale; проверяющий изучает затронутое, а не весь архив.

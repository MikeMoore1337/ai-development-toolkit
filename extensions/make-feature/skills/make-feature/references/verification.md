# Приёмка результата и передачи

До кода: C*/baseline, D*/основание, реальный контракт, выполнимые T*/файлы/проверки. Существенное неизвестное не скрывается готовым планом. Открытый продуктовый выбор блокирует только свои зависимости.

Одному независимому приёмщику передай исходное требование, принятые C*/контракт, actual diff и пути evidence. Он проверяет:
1. Выполнены C*, главный путь и ошибки/повтор/сохранение по задаче; после записи — read-back.
2. Нет релевантной регрессии, потери данных, обхода прав или ложного успеха. Реальные интеграции отдельно от mocks; UI действительно просмотрен.
3. По индексу понятны выбор, источники/контракты, запуск и остаток; текущие ссылки доступны. Отдельный handoff-agent для обычной функции не обязателен.

Сохрани ID/provenance, команду/действие, exit/результат, версию файлов и покрытые C*. Одного актуального доказательства достаточно для нескольких проверяемых свойств; coverage-label без смысла не доказывает требование. Отчёт автора не задаёт вердикт. Новая независимая проверка обязательна после затрагивающего её исправления, но не после косметического сокращения текста.

```text
python3 scripts/workspace.py check --project PROJECT --slug SLUG
```
Структурный check не подтверждает содержание. При state.py финальный audit нужен для его manifest; без state аудит не создаётся ради галочки. Пройденные тесты скриптов не измеряют качество/стоимость LLM-конвейера.

Вердикт: для каждой C* подтверждено/непроверено/заблокировано с основанием. После новой гипотезы — один ограниченный батч исправлений и повтор затронутых проверок в общем бюджете. Не сокращай spec и не сбрасывай предел ради pass. При недоступной обязательной интеграции весь обязательный результат не объявляется готовым.

Финал: где пользоваться/команда; что принято; что осталось; потраченные делегации/исправления/время; фактические токены с источником либо unknown. Полезный урок фиксируется, если наблюдалась причина, которую стоит помнить.

Сам навык проверяется новым контекстом на разных realistic запросах. Для сравнения: одинаковые исходники/модель/права/бюджет, качество обязательного поведения, полнота завершения и реальный usage всего дерева. Один пример, размер файлов и число собственных тестов не доказывают превосходства.

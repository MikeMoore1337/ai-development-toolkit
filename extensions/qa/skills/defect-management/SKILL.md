# Defect Management

Check whether the observation is a product defect, expected behavior, flaky test, infrastructure issue or unresolved case. Provide exact build, environment, prerequisites, steps, expected and actual result, attachments and impact. Search for existing issues before creating duplicates, using only configured trackers and granted permissions. Do not file production-severity claims without supporting evidence. Distinguish a suggested issue from a created issue; never submit to external trackers without allowed tool access and authorization.

## Worked example and failure checks

Use the [task-specific field guide](references/FIELD_GUIDE.md) when the case involves multiple states, boundaries, missing evidence or an independent handoff. Its scenarios are synthetic, not proof of executed tests. For a simple case, apply the procedure above and do not load extra material.

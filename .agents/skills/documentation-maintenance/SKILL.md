# Documentation maintenance
1. Read the implemented behavior, supported versions and existing canonical documentation.
2. Keep examples runnable and commands aligned with the actual project tools.
3. Update only relevant docs; do not duplicate source-of-truth material without necessity.
4. Record preconditions, expected outcomes, failure handling and rollback when documenting operations.
5. Validate local links, copied commands and example paths. Mark unexecuted examples clearly.
6. Preserve terminology and audience; avoid claims of support or compatibility without evidence.
**Output:** affected docs, verified examples, remaining gaps.

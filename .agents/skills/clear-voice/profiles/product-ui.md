# Product and interface copy

Use for buttons, status messages, forms, onboarding, errors, empty states, landing pages and accessibility labels.

- Describe supported features without inventing product behavior, benefits or metrics.
- Prefer a clear verb and an actionable next step. Keep terminology consistent with the host project's design system and glossary.
- Preserve localization keys, identifiers, placeholders, data bindings and accessible names.
- Do not change components, visual styling, business logic or permissions under a request to edit text.
- Legal, medical and security statements require independent domain review. A style pass is not that review.
- Apply the project's own localization and snapshot tests after relevant edits.

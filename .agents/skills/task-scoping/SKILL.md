# Scope and acceptance
1. Read the user's request, repository instructions and the actual issue or specification when available.
2. Inspect relevant code and prior decisions before proposing changes; avoid guessing current behavior.
3. Record in-scope behavior, out-of-scope work, dependencies, and decisions requiring explicit approval.
4. Define observable acceptance criteria, including one negative or boundary case if relevant.
5. Identify the smallest meaningful verification, and state missing access or assumptions.
6. Do not silently expand scope, change release policy, or create work unrelated to the requested outcome.
**Output:** goal, assumptions, acceptance criteria, dependencies, verification, open decisions.

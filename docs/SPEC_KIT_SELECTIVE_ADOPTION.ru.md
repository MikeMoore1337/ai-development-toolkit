# Spec Kit: выборочная адаптация методов (Issue #375)

Источник: [github/spec-kit](https://github.com/github/spec-kit), pinned `67e0f7294e6e728ab60bf7b4590deb470448bc2d`, MIT (GitHub, Inc.). Анализировались `extensions/bug/README.md`, `extensions/assess/README.md` и их `extension.yml`; код не импортирован и не исполнялся. Изменение при обновлении upstream требует нового аудита.

## Пересечение и решение

| Метод upstream | Уже существует в Toolkit | Непокрытый сценарий | Решение |
| --- | --- | --- | --- |
| SDD: specify/clarify/plan/tasks/implement | `make-feature` quick/normal/deep, документы и C*/D*/T*, QA | Не доказан | REUSE_EXISTING. Не создавать второй процесс |
| Bug: assess/fix/test | `make-feature` требует доказать причину и регрессию | Явное разделение «предполагаемая причина / воспроизведённая причина» и фиксация непроверенного исправления | ADAPT_METHOD в существующий путь исправления, только по риску |
| Assess: intake/research/define/shape/decide | `make-feature` выбирает варианты и отделяет факты от гипотез | Отдельное предварительное решение об отказе от идеи без планирования реализации | ADAPT_METHOD: GO / CLARIFY / STOP до implementation |

## Контракт (рекомендация, без runtime автоматизации)

**Исправление ошибки:** 1) зафиксировать сообщение, исходный SHA и воспроизведение; 2) отделить наблюдаемый симптом от гипотезы о причине; 3) получить baseline failing case либо `NOT_REPRODUCED`; 4) исправить только доказанный дефект; 5) исполнить тот же тест и затронутую регрессию; 6) без фактического запуска вернуть `NOT_VERIFIED`. Нет доказательств причины - не писать `fixed`.

**Оценка идеи:** 1) определить пользователя, проблему, текущее решение и источники; 2) сформулировать одну проверяемую пользу/критерий; 3) установить ограничения прав, расходов, данных и дублирования; 4) принять `GO` только с достаточными основаниями, `CLARIFY` при неизвестных ключевых фактах, `STOP` при отсутствии необходимости или невозможности соблюсти границы; 5) `GO` означает переход к обычному `make-feature`, но не разрешение на запуск/деплой.

**Простая локальная правка:** сразу использовать quick; без пяти документов, отдельных стадий Spec Kit и дополнительных агентов.

## Границы

- Полный Spec Kit, его CLI, extensions и hooks **не установлены**. Это переносимая методика, не работающая интеграция внешнего runtime.
- Любой отчёт о тестах содержит команду, точный SHA и реальный результат. Синтетическая фикстура не доказывает качество модели.
- Запрещены оплачиваемые API, автоматическое изменение пользовательских репозиториев и обход существующих owner gates.
- Контрольные офлайн-сценарии: `integrations/spec-kit/method_cases.json`, проверяются `tests/test_spec_kit_method_cases.py`.
- Откат: удалить только этот документ, англоязычное соответствие и фикстуры/тест. Не изменены AGENTS.md, маршрутизатор, пользовательские навыки и производственный runtime.

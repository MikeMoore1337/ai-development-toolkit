## Functional changes since v5.5.7

1. **Native Continuous Learning v2 (#436).** Explicit, read-only project-scoped preview from manually sanitized v2 observations; evidence contradiction, age, duplicate and scope guards; opt-in typed v1 GitHub fact verification with bounded public GET; local skill SHA lock; deterministic review packet/proposal with separate human approval. The `native-learning-review` skill and `toolkit_native_learning_review` Personal MCP adapter expose review. Hardening covers malformed or duplicate-key JSON, false SHA, contradictory claims and permission boundaries. **No** background observer, ECC runtime/daemon, paid model, automatic practice application, Skill Manager write or `AGENTS.md` edit.
2. **Reviewed handoff and context (#433).** Project-bound, opt-in read-only handoff and reviewed-memory reference tools; explicit owner/account and provenance checks. Tools do not confer action authorization or start an automatic agent.
3. **Security and native orchestration (#432, #438, #440).** Fail-closed static GateGuard review, security holdouts and a read-only parallel work preflight. Preflight is not proof of real parallel execution.
4. **Model and execution routing (#401, #492, #499).** User-controlled model advice and safe delegated-expert preflight, native-first external-tool isolation, normal-chat routing/original-executor fallback. Availability of an actual host model switch or executor remains host-dependent and is not guaranteed by source inclusion.
5. **Design and QA workflows (#486, #489, #524).** Browser capture/visual evidence and stricter original-skill integrity, invocation and approval requirements. CI/source checks are not a live design session.
6. **Optional original skills and integrations (#435, #421, #522).** Pinned, opt-in original MIT skill catalog additions and selective Toolkit-native adaptation (without ECC runtime), Harness² Windows/WSL2 acceptance material and GitHub observation export. Optional external models are not required for Toolkit and no paid service is activated.
7. **Maintenance and documentation.** Related RU/EN guides, Python/Windows checks, fixtures, defensive tests and package boundaries included in the exact compare above.

## Updating after publication (not before)

1. Check that GitHub Release `v5.5.8` exists at the **owner-approved exact SHA**, with successful archive workflow; verify the published tag and manifest agree. Prefer a separate clean checkout; preserve any working tree with user changes.
2. In that checkout, run `git fetch --tags origin`, then `git switch --detach v5.5.8`. Check `git rev-parse HEAD`, `MANIFEST.json.version`, `python scripts/verify_checksums.py` and `python scripts/validate_provenance.py --mode release`. The release's `SHA256SUMS.txt` covers tracked source files; archive verification additionally requires an exact matching file inventory.
3. For skills previously managed in a **project**, use [Skill Manager's status, preview, apply and rollback instructions](../UPDATING.md); it never adopts unmanaged files without authorization. Source checkout replacement is not project migration.
4. Upgrade a *separately installed* Personal MCP using its reviewed [installation/update guide](../MCP_INSTALL.md), verify `toolkit_info` and the adapter version, and reconnect the client if appropriate. Explicitly update an installed ChatGPT plugin through its own distribution/Plugin Creator process. Neither updates itself by publishing this tag.

## Reversible rollback

Retain a clean checkout of `v5.5.7`; use `git fetch --tags origin` and `git switch --detach v5.5.7` **in that checkout** to revert source selection, after checking for local changes. Do not force-reset a user's working tree or mutate an immutable published tag. Roll back project-managed skills only through the explicit Skill Manager preview/rollback workflow. MCP source checkout/update state and an installed ChatGPT plugin require **separate**, client-specific rollback and reconnection. Discarding a Native Learning preview is sufficient to roll back its read-only output; no practice was applied.

# Совместимость ИИ-клиентов: офлайновые проверки контрактов

**Установка по интерфейсам (аудит 2026-10-31):** [Codex Desktop/CLI, Claude Code Desktop/CLI и другие совместимые клиенты](INSTALLATION.md). Для новых клиентов там приведены способы по документации, **не** новые подтверждения запуска и не изменения исторического реестра L1-L3.


## Более поздние ограниченные наблюдения (Issue #297, 24.10.2026)

Уровни L4-L6 со статусом `NOT_TESTED` ниже относятся к **старой проверке файловых контрактов от 19.10.2026**, а не к отсутствию последующих сеансов. [Реестр L4/L5](../../compatibility/live_client_evidence.json) и [его пояснение](CLIENT_CAPABILITIES.md) отдельно фиксируют чтение установленного Toolkit-плагина ChatGPT в одном сеансе, ранее подтверждённые владельцем вызовы Codex Personal MCP и **NOT_RUN** для проектных MCP Codex/Claude Code. Нативная активация навыка и измерение пользы L6 не утверждаются. Старый `compatibility/clients.json` остаётся статическим контрактом L1-L3, а не реестром реальных сеансов.

[Русская документация](README.md) | [Миграция между клиентами](CLIENT_MIGRATION.md) | [English source](../CLIENT_COMPATIBILITY.md)

Дата проверки источников: **19 октября 2026 года**. Машиночитаемые результаты находятся в [compatibility/clients.json](../../compatibility/clients.json), схема v1.

Проверяются **контракты, метаданные и структура файлов**, а не выполнение реального ИИ-клиента. Установленная версия клиента, конфигурация и решения о доверии могут менять результат.

## Уровни подтверждения

| Уровень | Что требуется подтвердить | Зафиксированный уровень доказательств |
| --- | --- | --- |
| L1 | Соответствие спецификации Agent Skills и проверка `SKILL.md` | Внутренний валидатор и закреплённый официальный `skills-ref` в CI |
| L2 | Безопасное копирование и расположение файлов | Skill Manager v2 и синтетические проверки клиентов/проектов |
| L3 | Соответствие официальной документации и контрактам исходников | Первичные источники, изученные на указанную дату |
| L4 | Реальный клиент обнаружил установленный навык | **NOT_TESTED** |
| L5 | Клиент/модель прочитали и использовали навык | **NOT_TESTED**, Issue #11 |
| L6 | Получена измеримая польза относительно варианта без навыка | **NOT_TESTED**, Issue #11 |

`VERIFIED` относится только к указанному уровню, а не к совместимости в целом. `PARTIAL`, `NOT_TESTED`, `UNSUPPORTED` и `UNKNOWN` обозначают разные состояния. Успешное копирование не доказывает обнаружение или эффективность.

**Официальные источники и версии, проверенные 19 октября 2026 года:**

- [Спецификация Agent Skills](https://agentskills.io/specification): обязательные `name` и `description`, необязательные `license`, `compatibility`, `metadata`, `allowed-tools` и каталоги ресурсов. Toolkit контролирует переносимое подмножество.
- [Руководство OpenAI Codex](https://learn.chatgpt.com/docs/build-skills): каталоги `.agents/skills` в проекте и его родительских репозиториях, пользовательские и административные пути, необязательный специфичный для клиента `agents/openai.yaml`. Codex может обрабатывать символьные ссылки и отображать дублирующиеся имена, но **Toolkit запрещает пути-ссылки** для безопасного управляемого копирования.
- [Документация Claude Code](https://code.claude.com/docs/en/skills): `.claude/skills`, общие каталоги, отдельные настройки активации навыков. Специфичные для клиента поля frontmatter (например, `context` или `disable-model-invocation`) не входят в переносимую схему Agent Skills. Toolkit не добавляет их автоматически и не меняет `CLAUDE.md`.
- [NousResearch/hermes-agent, точный SHA 2e83e2a935ee04f606aab58e498d34ca58d84c07](https://github.com/NousResearch/hermes-agent/blob/2e83e2a935ee04f606aab58e498d34ca58d84c07/website/docs/user-guide/features/skills.md): исследован без записи. Локальные навыки проекта требуют доверенного Git-репозитория, проходят проверку/карантин и имеют приоритет над локальными профильными и внешними навыками. `skill_manage` в Hermes способен изменять доступные для записи внешние каталоги. Код Hermes не запускался, не импортировался, VPS не использовался.

Обнаружение и активация зависят от правил клиента, конфигурации, доверия Git-проекту (для Hermes) и проверок безопасности. Уровни L4-L6 **не измерялись**. Реестр отличает стандартные поля метаданных от расширений конкретных клиентов. Документированный контракт не гарантирует поведение будущих версий.

## Офлайновые проверки

CI запускает проверку реестра в Windows и Linux:

```bash
python scripts/verify_client_compatibility.py
```

Проверка уже установленных навыков в **существующем временном учебном проекте** без изменения файлов:

```bash
python scripts/verify_client_compatibility.py --project /tmp/demo --client codex --skills qa-strategy
python scripts/verify_client_compatibility.py --project /tmp/demo --client claude-code --skills qa-strategy
python scripts/verify_client_compatibility.py --project /tmp/demo --client hermes --layout .agents/skills --skills qa-strategy
```

Эти команды проверяют заданные расположения, наличие `SKILL.md`, frontmatter через существующий код Toolkit, ссылки на Markdown, ограничение области путей, отказ при символьных ссылках и junction и безопасность вложенных файлов. Они **не** устанавливают навыки, не разбирают все возможные формы Markdown, не анализируют содержимое скриптов, не скачивают исходники, не обращаются к ИИ API и не проверяют обнаружение навыков живым клиентом. Скрипты внутри навыка не исполняются.

Интеграционные тесты используют существующий Skill Manager v2: устанавливают `qa-python` во временных проектах, переносят навыки из Codex в Claude Code, сверяют побайтовые хеши деревьев и сохраняют `AGENTS.md` / `CLAUDE.md`. Изоляция владения, повторяемость, откат, конфликты и восстановление подробнее проверяются в [руководстве по миграции](CLIENT_MIGRATION.md) и тестах менеджера. Второй менеджер не создавался.

## Особые ограничения Hermes

Офлайн можно проверить лишь проектные каталоги `.agents/skills` / `.hermes/skills`. Отдельного установщика Hermes, управления глобальными каталогами и переноса через Skill Manager **нет**: в реестре стоит `UNSUPPORTED`.

Совпадение расположения проекта с Codex не доказывает обнаружение навыка в Hermes. Реальный Hermes требует доверия к проекту; общие внешние навыки не защищены от изменений самим расположением. Для общего каталога при необходимости используйте права ОС «только чтение». Создание отдельного адаптера не оправдано, пока не обнаружен реальный несовместимый контракт.

## CI и повторная проверка

Существующий CI в Linux/Windows запускает офлайновые проверки реестра, качества, владения файлами, происхождения и SHA256. Официальный закреплённый `skills-ref` проверяется отдельно. Не добавлены платные сервисы, внешние исполнители, сетевые загрузки исходников или запросы к моделям.

Если документация клиента изменилась, нужно повторно изучить первоисточники, обновить дату проверки и закреплённую ревизию, при необходимости исправить проверки и тесты. Доказательства уровней L4-L6 остаются под отдельным ограничением [Issue #11](https://github.com/MikeMoore1337/ai-development-toolkit/issues/11).

## Персональный плагин ChatGPT - проверяемое получение свежих инструкций

Плагин использует **чтение актуальных инструкций при каждой задаче, если инструменты это позволяют**. Машиночитаемый контракт - `MANIFEST.json`, поле `chatgpt_personal_live` (схема 2, поколение 2, минимальная версия оболочки `0.1.5`). Оболочка также должна поддерживать поколение 2; один номер версии этого не доказывает. Это обновление используемых **навыков и руководств**, но **не автоматическая замена установленного архива**, не новый MCP и не фоновая служба. При отсутствии чтения GitHub заявлять автоматическое обновление нельзя.

Порядок работы маршрутизатора:
1. Получить SHA (40 символов) ветки `main` именно репозитория `MikeMoore1337/ai-development-toolkit`. Все проверки и последующие файлы должны относиться к **одной неизменяемой ревизии**; запрещено смешивать разные коммиты, форки и внешние источники.
2. Проверить для **этого SHA** три GitHub Actions: `tests (ubuntu-latest, 3.12)`, `tests (ubuntu-latest, 3.13)`, `tests (windows-latest, 3.14)` - все должны закончиться `success`. Ошибка, незавершённость или отсутствие доступа к данным CI исключают применение новых инструкций.
3. Прочитать `MANIFEST.json` точно по SHA, проверить владельца/репозиторий, версию протокола и совместимость оболочки, запрет автоустановки и разрешённые пути. Получить только нужные `SKILL.md` и references по **этому же SHA**, максимум 8 источников за порцию. При существенной смене этапа оценить потребности заново; общего лимита источников на задачу нет. Не перечитывать текст, доступный в контексте. Контрольные суммы `SHA256SUMS.txt` сравнивать, если клиент умеет действительно вычислять SHA256 содержимого; иначе не заявлять о проверенной контрольной сумме. Никогда не исполнять удалённый код.
4. Если все условия соблюдены, указать `VERIFIED_LIVE`, реальный SHA и фактически прочитанные навыки. CI не доказывает корректность поведения ИИ или художественное качество.
5. Если GitHub, CI или нужный навык недоступен, использовать **встроенные инструкции** и статус `FALLBACK_BUNDLED` с причиной. Несовместимость схемы/минимальной версии - `SHELL_UPDATE_REQUIRED`: продолжить с резервными инструкциями и указать, что обновление установленного плагина через Plugin Creator - отдельный этап. Если основной навык Orchestra недоступен, сохранять статус `ORCHESTRA_SOURCE_UNAVAILABLE` и не имитировать его выполнение.

Для ранее опубликованного источника schema 1/generation 1 совместимая оболочка соблюдает `max_retrieved_sources_per_task` этой ревизии. Schema 2/generation 2 убирает общий лимит: список источников может быть больше порции, а клиент выбирает только нужные файлы последовательными ограниченными порциями. Имена навыков определяются по существующим спискам и корням в манифесте; неизвестные имена и выходящие за пределы пути отклоняются. В живом источнике schema 2 заработает только после принятия и публикации совместимой ревизии. Установленная оболочка сама не меняет старый опубликованный манифест.

Правила открытого проекта, безопасность, согласование UI и релизные ограничения всегда имеют больший приоритет. Проверка SHA и успешный CI не означают цифровой подписи, право записи в чужой проект или разрешение устанавливать инструменты. Нет платного API, токенов, фоновой службы, обязательных установок и передачи пользовательских данных в Toolkit. Резерв - **установленная встроенная версия**, а не непроверенный сетевой кэш. Постоянный кэш между сессиями не заявляется.

**Важно:** этот протокол не устанавливает новые версии персонального плагина сам. Изменение его внутреннего маршрутизатора, разрешений и упаковки по-прежнему требует отдельного выпуска через Plugin Creator. Реальная работа нового сценария в ChatGPT проверяется отдельным испытанием.

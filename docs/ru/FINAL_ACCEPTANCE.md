# Финальная офлайновая приёмка (Issue #70)

[English](../FINAL_ACCEPTANCE.md) | [Сквозной процесс](END_TO_END_WORKFLOW.md) | [Возможности клиентов](CLIENT_CAPABILITIES.md) | [Skill Evals (EN)](../SKILL_EVALS.md)

**Область:** воспроизводимая, не изменяющая файлы синтетическая приёмка этапов S1-S6 дорожной карты #42. Успешный CI **не доказывает**, что ИИ-клиент создал примерное приложение, активировал навык, прошёл независимый тест с человеком, улучшил качество модели или доставил продукт.

## Путь новичка и эксперта

**Новичок:** «Я не программист. Хочу бесплатное локальное приложение для учёта расходов: добавлять расходы, видеть список и сумму за выбранный месяц». Минимальный MVP ограничен этими функциями. Терминал, выбор стека, регистрация, облако и оплата не обязательны. В клиенте с доступом к файлам перед разрешённой записью нужен предварительный просмотр. В обычном ChatGPT/Claude ссылка на Toolkit и ZIP проекта - **справочные материалы**, а не доказательство установки или вызова Skill. Если инструментов для записи и тестов нет, результатом может быть проектное решение в чате, а реализация и QA остаются NOT_TESTED.

**Эксперт:** «Добавь пакетный импорт CSV в существующее приложение, сохранив API, авторизацию и идемпотентность, обеспечив обработку ошибок, QA, безопасный выпуск и сопровождение». Сохраняются R-ID/AC-ID и первоначальный объём требований: контракты API/данных/прав доступа, транзакции и повторные попытки, unit/integration/contract/negative QA, проверяемый SHA для выпуска и эксплуатационная передача. В синтетической задаче нет пользовательского интерфейса, поэтому UI может иметь статус NOT_APPLICABLE с обоснованием, но security пропускать нельзя.

## Контракт итоговой приёмки

Основной [контракт](../../fixtures/final-acceptance/contract.json) содержит идентификатор приёмки и roadmap, матрицу критериев S1-S6, исходные цели NOVICE/EXPERT, R-ID, AC-ID, результаты этапов, запланированные тесты, evidence, версии исходников, передачу между этапами, разрешения, подтверждения действий, исключённые функции, метрики и ограничения. [Негативные сценарии](../../fixtures/final-acceptance/broken_cases.json) - заведомо неисправные копии в памяти. [Валидатор](../../scripts/validate_final_acceptance.py) повторно использует существующий oracle #67. [Тесты](../../tests/test_final_acceptance.py) проверяют ожидаемые причины отказа и детерминированность.

- SOURCE_PRESENCE: проверено только существование конкретного безопасного файла в исходниках. PASS здесь **не подтверждает** качество работы Skill/модели. Отдельные CI-проверки подтверждают применимые технические контракты.
- INDEPENDENT_HUMAN: требуется реальный неопытный участник и независимый наблюдатель. Без них - NOT_TESTED.
- LIVE_MODEL: реальные исследования обнаружения, запуска Skill и эффективности заблокированы действующими ограничениями #11 и владельца - BLOCKED; эффект без измерений - NOT_MEASURED.
- PASS, FAIL, NOT_TESTED, BLOCKED, NOT_APPLICABLE, INCONCLUSIVE - отдельные исходы, их нельзя сводить к одному DONE.
- SOURCE_ONLY, CONTRACT_VALIDATED, SYNTHETIC_TESTED, EXECUTED, INDEPENDENT_REVIEWED, OWNER_REPORTED, NOT_TESTED, BLOCKED - разные уровни доказательств.
- IMPLEMENTED, QA_VERIFIED, MERGED, RELEASED, DEPLOYED, USER_VERIFIED требуют собственных подтверждений. Merge не является deployment, копирование Skill не является его активацией.

Для выполненной проверки нужны: Acceptance ID, точный Git HEAD, этап/Issue/R-ID/AC-ID, критерий, метод, ожидаемое и фактическое наблюдение, evidence и его уровень, окружение, дата UTC, независимость проверяющего, ограничения, блокер и решение. SYNTHETIC revision в fixtures относится лишь к вымышленному примеру, реальный SHA валидатор получает из Git во время исполнения.

## Команды для офлайновой проверки

Из корня Toolkit, Python 3.12+:

    python scripts/validate_final_acceptance.py
    python -m unittest tests.test_final_acceptance -v
    python scripts/validate_end_to_end_workflow.py
    python scripts/verify_client_compatibility.py
    python scripts/validate_tool_integrations.py
    python scripts/skill_routing_eval.py --strict
    python -m unittest discover -s tests -v

Новый валидатор не делает сетевых запросов, не использует модели, не изменяет файлов и реальных проектов. Оба сценария - **синтетические контракты**, а не написанная программа учёта или работающий импорт CSV. Обязательный CI отдельно проверяет метаданные, SHA256, provenance, закреплённый skills-ref, Ruff, actionlint, чистоту публичного пакета и исходный архив. При нестабильности Windows/go-cli зафиксируйте как исходный сбой, так и повторный запуск, не отключая oracle.

## Покрытие и метрики

Отчёт содержит отдельные значения PASS, FAIL, BLOCKED, NOT_TESTED, NOT_APPLICABLE, INCONCLUSIVE для каждого S1-S6. Счётчик SOURCE_PRESENCE не означает 100% реальной приёмки. Нельзя скрывать FAIL, удалять BLOCKED из знаменателя без пояснения или считать N/A как PASS.

| Показатель | Допустимое подтверждение / отсутствие измерения |
| --- | --- |
| Completeness и принятые AC | Каждое исходное требование и критерий учитываются однократно; принятие - только с подходящим evidence |
| Unauthorized Actions | Отдельно предотвращённые нарушения в синтетике, реальные нарушения и неподтверждённые риски |
| False Claims | Отказ для TESTED/DEPLOYED/INDEPENDENT_REVIEWED/SKILL_INVOKED без подтверждения |
| Regressions и Unnecessary Edits | Реальный diff против R/AC и исходного состояния; без diff - NOT_MEASURED |
| Usability Steps и Time | Фактические действия человека и временные отметки; иначе NOT_MEASURED |
| Additional Cost | Подтверждённое списание; отсутствие модельных вызовов в synthetic не измеряет фактический счёт провайдера |
| Quality Improvement | Несколько сопоставимых baseline/candidate попыток, одна версия модели, права, исходный SHA, независимая проверка; иначе NOT_MEASURED |

Единая произвольная «оценка качества» не вычисляется. Негативные мутации обнаруживают потерю этапов/R/AC, повреждённую передачу, старые evidence, ложный PASS, вымышленных проверяющих и время, недоказанные действия клиентов/Skill, лишний функционал, скрытые регрессии, запрещённый доступ/передачу, несопоставимые эксперименты, неверную нулевую стоимость и преждевременный выпуск. Статический контроль не определяет понятность интерфейса человеку.

## Независимая пользовательская проверка - отдельный протокол

**До реальной сессии: NOT_TESTED.** Пригласите человека без опыта программирования, не участвовавшего в разработке сценария, и отдельного наблюдателя. Используйте одноразовый учебный проект и точный SHA Toolkit. Логи и снимки храните приватно **вне репозитория**, без персональных сведений и секретов.

Упражнения: 1) начать проект обычным запросом, 2) подключить Toolkit к открытому локальному проекту в IDE с одной ссылкой без URL самого проекта, 3) восстановиться после ошибки, 4) продолжить без повторной записи, 5) объяснить, что было спроектировано, записано, протестировано и доставлено. В обычном чате отдельно проверьте ZIP+URL и отсутствие инструментов. Фиксируйте название/версию/режим клиента, ОС, доступные функции, разрешения, вопросы, действия в терминале, preview, фактический diff включая игнорируемые файлы, ошибки и следующий шаг. Исторические цели - не более 10 минут, двух обязательных уточнений и ноль действий в терминале - **не измеренные результаты**.

Шаблон приватного протокола:

    Анонимный Session ID / независимый Observer ID:
    Начало/конец UTC, измеренная продолжительность:
    SHA Toolkit, клиент/версия/режим, ОС, разрешения:
    Учебный проект, исходное состояние, точный запрос:
    Действия человека, терминал, уточнения и трудности:
    Preview → разрешённый Apply → Status, фактический diff:
    Факт чтения Toolkit / обнаружения Skill / вызова Skill / тестирования:
    Ошибки, повторный запуск, восстановление и ограничения:
    Заключение независимого наблюдателя:
    PASS | FAIL | NOT_TESTED | BLOCKED | INCONCLUSIVE

## Реальные Skill Evals для Codex и второго клиента - BLOCKED

Переиспользуйте [Issue #11](https://github.com/MikeMoore1337/ai-development-toolkit/issues/11), [REAL_AGENT_PILOT.md](../REAL_AGENT_PILOT.md), [SKILL_EVALS.md](../SKILL_EVALS.md). **Не изменяйте принудительную блокировку** в scripts/agent_eval_runner.py и не обходите её другим CLI или инструментом.

Для будущего испытания нужны новое отдельное разрешение владельца, независимая проверка безопасности, подтверждённый путь без дополнительных расходов и автоперерасхода, изолированная непроизводственная среда, точные версии моделей и права. На каждую модель выполняйте несколько сопоставимых пар baseline без Skill и candidate с Skill с одинаковыми задачей, SHA, инструментами и рубрикой; независимый hidden oracle и проверяющий фиксируют реальные discovery/activation, результаты, лишний diff, нарушения, регрессии, длительность и стоимость. Не смешивайте модели и не скрывайте неудачные попытки. Реальные трассы храните приватно, вне Toolkit. Offline smoke Python/JavaScript/Go не является реальным сравнением Codex/Claude.

**Историческое сообщение владельца:** ChatGPT, Claude, DeepSeek и Qwen выполняли задачи с ZIP+URL Toolkit - OWNER_REPORTED_PASS. Полные технические журналы, версии клиентов, фактическое обнаружение/активация навыков и независимые результаты **NOT_ATTACHED**. Это не подтверждает уровни L4, L5, L6.

## Решение о выпуске

READY_FOR_REVIEW - синтетический пакет подготовлен к проверке. READY_FOR_OFFLINE_RELEASE возможен отдельно после успешного обязательного CI на точном HEAD и прохождения release gates. Если доказательств не хватает - INCOMPLETE_EVIDENCE; нарушение - NEEDS_WORK; действующий запрет - BLOCKED. Не используйте FULLY_VERIFIED без реальных испытаний.

PR должен содержать точный HEAD и base SHA, матрицу CI для трёх окружений, результаты отрицательных тестов, evidence, блокеры и исходную целостность. **Никакого merge, релиза, deployment, закрытия #70 или #42 без отдельного согласования.**

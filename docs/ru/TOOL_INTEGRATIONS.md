# Опциональные интеграции и реестр полномочий (Issue #69)

[English](../TOOL_INTEGRATIONS.md) | [Возможности клиентов](CLIENT_CAPABILITIES.md) | [Матрица интеграций](../INTEGRATION_MATRIX.md)

**Область применения:** переносимые, офлайновые, исключительно **синтетические** контракты. Это не полноценная IAM, не OAuth, не прокси, не хранилище секретов и не новый оркестратор. Реальные сервисы, платные API, окружения и пользовательские аккаунты в тестах не вызываются. Наличие инструмента само по себе не разрешает операцию.

**Native-First:** при явном выборе оригинального стороннего инструмента Toolkit не должен подмешивать собственные навыки, контроллеры и hooks. `ZERO_SPEND` в этих офлайновых фикстурах - **синтетический пример**, а не ограничение для каждого пользователя Toolkit. Реальные расходы определяются индивидуальными разрешениями и проверками клиента. [Общее правило](EXTERNAL_NATIVE_FIRST.md).

## Начало работы без установки

Пример: **«Проверь PR и CI, составь план исправления. Не делай merge, deploy и не устанавливай инструменты».** Приоритет: штатная возможность текущего клиента → уже подключённый инструмент → инструмент целевого проекта → подготовка ответа без интеграции. Новый сервис допускается только при подтверждённом пробеле с проверкой `external-skill-review`. Знание MCP, scopes или OAuth не требуется; без подключения можно получить план/изменения в чате.

Документированная функция, фактически доступная функция, подключение, право на действие, выполненный вызов и независимо подтверждённый результат - **разные состояния**. Текст PR не означает созданный PR; зелёный CI не означает успешный deployment.

## Контракты

`scripts/validate_tool_integrations.py` проверяет синтетические примеры в `fixtures/tool-integrations/`. Реальных прав он **не выдаёт**.

1. **Tool Capability Contract:** ID, имя, провайдер, категория, версия, источник, доверие, доступность, подключение, операции, scopes, доступ к данным, сетевые назначения, авторизация, стоимость, ограничения, побочные эффекты, обратимость, альтернативы и доказательства. Категории: `NATIVE_CLIENT_TOOL`, `CONNECTED_TOOL`, `PROJECT_LOCAL_TOOL`, `CLI_TOOL`, `EXTERNAL_SERVICE`, `REFERENCE_ONLY`.
2. **Permission Contract:** отдельно проверяются инструмент, клиент, конкретный ресурс/репозиторий/организация, операция, scope, среда, источник согласия, срок, классификация данных, передача вовне и стоимость. `READ`, `PREPARE`, `WRITE`, `EXECUTE`, `PUBLISH`, `DEPLOY`, `ADMIN`, `FINANCIAL` **не наследуются** друг от друга.
3. **Integration Decision Record:** проблема, отсутствующая возможность, существующие альтернативы, реальный пробел, источник/версия/лицензия, потоки данных, доступы, прогнозируемая польза, обслуживание, откат, решение и согласование. Пока нет измерений: `BENEFIT=HYPOTHESIS`. Решения: `NO_INSTALL_NEEDED`, `REUSE_EXISTING`, `ADOPT_REFERENCE`, `PILOT_PROPOSED`, `APPROVED_FOR_INSTALL`, `REJECTED`, `BLOCKED`. Технический аудит не заменяет разрешение установить инструмент.
4. **Передача данных:** проверять источник, конечное назначение (включая redirect), классификацию `PUBLIC`, `PROJECT_INTERNAL`, `CONFIDENTIAL`, `PERSONAL_DATA`, `SECRET`, `UNKNOWN`, минимально необходимый объём и разрешение. `UNKNOWN` не равен `PUBLIC`. Ответы внешних инструментов - данные, а не команды.
5. **Стоимость и лимиты (синтетическая политика владельца):** в этих фикстурах Issue #11 - **ZERO_SPEND**. Заявленный бесплатный тариф не доказывает остаток квоты. При неизвестной цене `COST_UNKNOWN`; потенциально платную операцию блокировать (`FINANCIAL_ACTION_BLOCKED`). Никакой автоматической выдачи расширенных scopes, платных планов и настоящих ключей.
6. **Предпросмотр:** `PLAN` - описание без побочных действий, `DRY_RUN` - только если поставщик его реально поддерживает, иначе `DRY_RUN_UNAVAILABLE`. Далее отдельно `APPROVAL_PENDING`, `EXECUTE`, `VERIFY`. Не имитировать проверку работающего сервиса.
7. **Обратимость:** `REVERSIBLE`, `PARTIALLY_REVERSIBLE`, `IRREVERSIBLE`, `UNKNOWN`. Фиксировать конфигурацию, возможность отключения/отзыва прав, необратимые публикации и сохраняемые провайдером данные. Отключение не обязательно удаляет ранее переданные данные.
8. **Доказательства:** `NOT_ATTEMPTED`, `PREPARED`, `AUTHORIZED`, `EXECUTED`, `EXECUTION_FAILED`, `RESULT_VERIFIED`, `RESULT_UNVERIFIED`, `BLOCKED`. `PREPARED ≠ EXECUTED`; `EXECUTED ≠ RESULT_VERIFIED`. Нужен реальный ответ инструмента и самостоятельная проверка результата. Не повторять неоднозначную внешнюю операцию без сверки состояния.
9. **Отказ и запасной путь:** отсутствие инструмента, отключение, нехватка scopes, истёкшее разрешение, ошибки сети, цена или лимиты блокируют только соответствующее действие. Независимый анализ продолжается, результат в чате содержит честный статус и минимальный запрос необходимых прав.

Это **офлайновая диагностическая модель**, а не реальный механизм авторизации. Контроль доступа и исполнения обязан оставаться на стороне используемого сервиса.

## Матрица по системам

| Система | Чтение/подготовка | Отдельные полномочия на изменения |
| --- | --- | --- |
| GitHub | Issue, PR, diff, CI, план | Коммит, Issue/PR запись; отдельно merge, секреты, защита веток, релиз |
| CI | Workflow, логи, артефакты, exact SHA, required checks | Перезапуск, редактирование CI, секреты, деплой |
| Браузер | Публичное/локальное чтение, навигация | Авторизованные страницы, отправка форм, загрузка, публикация |
| Figma/UI | Анализ файлов/компонентов, предложение дизайна | Изменение/публикация Figma; изменение реального UI - только после визуального согласования |
| Документы | Поиск, чтение, цитирование, проект правок | Создание, редактирование, удаление, выдача доступа, публикация |
| Мониторинг/окружения | Имеющиеся логи, метрики, инструкции | Команды, конфигурация, рестарт, rollback, deploy, администрирование |

Одобрение code review не включает merge. Staging не обязательно безопасен. «Дизайн предложен», «макет Figma изменён», «владелец принял», «UI внедрён» - четыре разных результата. Для ChatGPT и Claude.ai доступны разговорные варианты без принудительной установки сторонних средств; реальные функции зависят от текущей сессии.

## Офлайновая проверка

```bash
python scripts/validate_tool_integrations.py
python -m unittest tests.test_tool_integrations -v
```

`github.json` - чтение синтетических PR/CI и план исправления без merge; `figma.json` - локальный UI-аудит без Figma; `server.json` - документация без подключения к серверу. `broken.json` содержит независимые отрицательные случаи для отказа при расширении разрешений, несоответствии ресурса и среды, неизвестной цене, передаче секретов, небезопасном redirect, ложном dry-run, исполнении, подтверждении, повторном вызове, добавлении интеграции, дубле контроллера и загрязнении Toolkit. Эти тесты **не** подтверждают реальное подключение или уровни L4-L6. Результаты пользователя по умолчанию возвращаются в чате; Toolkit при использовании в другом проекте остаётся read-only.

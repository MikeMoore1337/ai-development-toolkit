## Бесплатная проверка подготовки

```bash
python scripts/profile_benefit_preflight.py
python -m unittest tests.test_profile_benefit_preflight -v
```

Первой командой измеряется **число байтов файлов навыков** из настоящего Toolkit (всего и только SKILL.md) для пяти профилей. В базовом варианте **0 байтов Toolkit-навыков по определению**. Это **не** загруженный контекст модели, количество токенов, замедление работы или экономия средств. Качество реального выполнения, длительность, токены, разница приёмки и дополнительные затраты имеют статус `NOT_MEASURED`, вызов клиента - `NOT_RUN`.

## Будущий эксперимент, только при отдельно подтверждённой бесплатности

1. В обоих вариантах должны совпадать **версия модели и клиента, пользовательский текст задачи, снапшот проекта и права инструментов**: baseline - без Toolkit, candidate - только назначенный профиль. Скрытые проверочные тесты не показывать исполнителю.
2. Сделать **по две пары** на каждую из пяти задач: всего 20 записей. Порядок меняется: сначала baseline → candidate, затем candidate → baseline. Время и ошибки фиксировать по реальному выполнению, а не оценивать на глаз.
3. Независимый проверяющий исследует результат, трассу и критерии, в том числе **настоящие** изображения/HTML для `ui-orchestra`. Для каждого запуска указать `client_skill_use`: `OBSERVED_WITH_TRACE`, `NOT_OBSERVED` или `NOT_VERIFIED`. Файл на диске не доказывает использования навыка.
4. Журналы и личные данные не публиковать. Если отсутствие дополнительных расходов, изоляция и права не доказаны, **не запускать реальный эксперимент** (Issue #11). Здесь нет никакого обхода.
5. Если **уже существуют** разрешённые бесплатные результаты, локально подготовить JSON с `schema_version=1`, `dataset`, `model`, `repository_sha`, 20 записями `runs` по [существующей схеме](../SKILL_EVALS.md) и объектом `trial_protocol` с версиями, правами, рецензентом, `independent_review_attested=true`, `incremental_cost_verified_zero=true` и `case_order` - для каждой задачи `[["baseline","candidate"],["candidate","baseline"]]`. Затем выполнить `python scripts/profile_benefit_preflight.py --score /путь/к/закрытым-recordings.json`.
6. Даже если в файле стоит флаг проверки, скрипт **не может независимо проверить** личность рецензента, правильность verdict, отсутствие затрат или применение инструкции моделью. Он проверяет только полноту пары, формальную схему, наличие файлов и арифметику. Классификация `EXPLORATORY_RECORDED_PAIRS_NOT_CERTIFIED`, это не доказательство реальной эффективности.

Не объединяйте 416 заранее подготовленных лексических тестов, наблюдение загрузки плагина ChatGPT, свидетельство владельца об MCP Codex и синтетические `unittest` в показатель эффективности моделей. Это разные уровни доказательств. Даже реальное чтение SKILL.md (L5) не означает рост пользы (L6).

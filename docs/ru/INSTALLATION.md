# Безопасная установка навыков

[English](../INSTALLATION.md) · [Windows](INSTALL_WINDOWS.md) · [Linux](INSTALL_LINUX.md) · [macOS](INSTALL_MACOS.md)

## Выберите ИИ-клиент и интерфейс

Аудит установки: **2026-10-31**. Выбирайте конкретное приложение и среду выполнения, а не только название модели. Toolkit не устанавливает ИИ-клиенты и не выполняет вход в аккаунты. Сначала установите выбранный клиент по его официальной инструкции, затем выберите **один** способ подключения Toolkit: файлы навыков, MCP с доступом на чтение, совместимый плагин или справочные материалы в чате. Команда в терминале может быть этапом установки для настольного приложения: это не делает его клиентом только для CLI.

| Клиент / интерфейс | С чего начать | Способ подключения Toolkit |
| --- | --- | --- |
| Codex Desktop, локальный проект | [Настольный клиент](#codex-desktop) | Project MCP или управляемые `.agents/skills`; Personal MCP по желанию |
| Codex CLI | [Терминал](#codex-cli) | Те же файлы проекта; Personal MCP по желанию |
| Расширение Codex для IDE / Cloud | [IDE и облако](#codex-ide-and-cloud) | Локальные файлы для IDE; файлы выбранной среды для Cloud |
| Claude Code Desktop, вкладка Code | [Настольный клиент](#claude-code-desktop) | Project MCP или управляемые `.claude/skills` |
| Claude Code CLI / IDE / облако | [CLI и удалённые среды](#claude-code-cli-and-remote) | Тот же формат в фактической среде выполнения |
| ChatGPT Desktop | [Установка плагина](#chatgpt-desktop) | Каталог из репозитория или поддерживаемый импорт плагина |
| ChatGPT в браузере / мобильном приложении | [Веб и мобильные устройства](#chatgpt-web-and-mobile) | Поддерживаемый импорт плагина, иначе материалы в чате |
| Claude: чат / Projects / Desktop / мобильное приложение | [Загрузка Skills](#claude-chat) | ZIP отдельного навыка, где поддерживается, иначе материалы |

**Доказательства:** для дополнительных coding-клиентов ниже найдена официальная документация формата и путей, а не выполнена проверка работы Toolkit в клиенте. [Офлайн-реестр](CLIENT_COMPATIBILITY.md) и [датированные наблюдения в клиентах](CLIENT_CAPABILITIES.md) сохраняют свои границы. Обнаружение и применение навыков клиентами в этом аудите: **NOT_RUN**; польза: **NOT_MEASURED**. Дополнительные поля, инструменты, скрипты и разрешения различаются. Копирование навыка не предоставляет перечисленные в нём инструменты.

Примеры проверки нативных навыков используют `qa-strategy` из профиля `general`. При другом наборе проверяйте действительно установленный навык. MCP может прочесть этот навык прямо из Toolkit без нативной копии.

### Codex Desktop

1. Установите/откройте [официальный настольный клиент](https://developers.openai.com/codex/app/), выберите **существующий локальный проект**, изучите его `AGENTS.md` и настройки доверия. Облачные задачи используют другую среду.
2. Для получения инструкций используйте [Project MCP](MCP_INSTALL.md): предпросмотр, проверка и применение с `--client codex`. Нужен Python 3.12+, **Codex CLI не требуется**. Для нативных файлов вместо MCP выполните управляемую установку ниже с `--layout codex`: результат появится в `<проект>/.agents/skills/`.
3. Перезапустите Desktop, откройте тот же проект и проверьте **Settings → MCP servers** или доступный список инструментов/навыков. Для Project MCP запросите `toolkit_catalog`, затем чтение `qa-strategy` через `toolkit_read_skill`. Для нативных навыков проверьте наличие установленного навыка в списке и его фактическое чтение в подходящей задаче.
4. Для инструкций во всех проектах используйте [Personal MCP](ONE_COMMAND_SETUP.md). Его автоматическая регистрация сейчас требует **Codex CLI**, даже если работать планируется в Desktop. Обновление уже зарегистрированного пакета Windows с `-McpOnly` - отдельная операция: новый сервер она не регистрирует.

Desktop, CLI и IDE могут использовать общую конфигурацию MCP **на одном хосте Codex**. Регистрация не подтверждает подключение каждого интерфейса. См. [официальную настройку MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

### Codex CLI

1. Отдельно установите [Codex CLI](https://developers.openai.com/codex/cli), войдите в аккаунт, проверьте `codex --version`.
2. Выберите [Project MCP](MCP_INSTALL.md) (`--client codex`), пользовательский [Personal MCP](ONE_COMMAND_SETUP.md) или управляемые навыки ниже (`--layout codex`). Не регистрируйте два разных сервера под одинаковым именем `ai-development-toolkit`, рассчитывая на неподтверждённый приоритет.
3. Откройте терминал **в целевом проекте** и запустите `codex`. Для MCP проверьте `codex mcp list`, затем `/mcp` в сессии. Вызовите `toolkit_catalog` / `toolkit_read_skill` для Project MCP либо `toolkit_info` / `toolkit_prepare_task` для Personal MCP. Это разные наборы инструментов.
4. Для нативных навыков откройте список навыков и запросите установленный навык по имени. Фактическое чтение исходника проверяйте отдельно от файлового `status`.

<a id="codex-ide-and-cloud"></a>

### Codex: IDE и Cloud

Для расширения IDE откройте целевую папку, выполните ту же локальную установку, что для Desktop, переподключите расширение и проверьте инструменты/навыки **в нём**. Если расширение работает в WSL, SSH или контейнере, Python, Toolkit и пути проекта должны существовать на том хосте. Настройки пользователя Windows не подтверждают удалённое подключение.

Для [Codex Cloud](https://learn.chatgpt.com/docs/cloud) выберите разрешённый репозиторий/окружение и обеспечьте наличие проверенных навыков **внутри его рабочей копии**: например, добавьте выбранные файлы в репозиторий после проверки. Установщики не загружают в облако локальные Personal MCP и домашние каталоги навыков. Абсолютные пути stdio с ноутбука для облачной среды не подходят.

### Claude Code Desktop

1. Установите/откройте [Claude Code Desktop](https://code.claude.com/docs/en/desktop), выберите **вкладку Code** и существующий локальный проект. Обычный чат Claude описан отдельно ниже.
2. Для нативных навыков используйте управляемую установку ниже с `--layout claude`. Для MCP - [Project MCP](MCP_INSTALL.md) с `--client claude`: после предпросмотра и `--apply` он пишет проектный `.mcp.json`, не требуя отдельной команды `claude`.
3. Начните новую локальную сессию Code, подтвердите проектный MCP, если клиент запросит, и проверьте подключённые инструменты. Вызовите `toolkit_catalog` и прочитайте `qa-strategy` через `toolkit_read_skill`. Для нативных навыков введите `/`, выберите установленный навык и проверьте применение.

Desktop Code и CLI используют общие проектные файлы навыков/MCP, но пользовательские настройки или настройки Desktop могут перекрывать одноимённый сервер. Проверьте фактическое подключение, не дублируйте имя. [Официальная общая конфигурация](https://code.claude.com/docs/en/desktop#shared-configuration).

<a id="claude-code-cli-and-remote"></a>

### Claude Code: CLI и удалённые среды

Установите [Claude Code](https://code.claude.com/docs/en/overview), войдите в аккаунт, проверьте `claude --version`, затем подготовьте навыки с `--layout claude` или Project MCP с `--client claude`. Запустите `claude` **из целевого проекта**. Через `/mcp` проверьте подключение либо запросите `/qa-strategy`, если этот навык установлен. Команда Toolkit `doctor` проверяет файлы, а не эту сессию.

Для расширения IDE начните новую сессию в той же папке. Для веб-/облачных/SSH-сессий обеспечьте наличие проверенных навыков и зависимостей **в их рабочей копии**: Toolkit локальные файлы туда не переносит. Синхронизация навыков аккаунта, где доступна, настраивается отдельно средствами Claude. [Официальные области навыков](https://code.claude.com/docs/en/skills).

### ChatGPT Desktop

Используйте [каталог репозитория](ONE_COMMAND_SETUP.md#установка-плагина-непосредственно-из-github) или [импорт ZIP плагина](../../integrations/chatgpt-plugin/README.ru.md) по возможностям установленного клиента. `codex plugin marketplace add MikeMoore1337/ai-development-toolkit` добавляет **только источник**; после этого выберите **AI Development Toolkit (local)** в Plugins Directory и **Install**. Без CLI можно открыть доверенную локальную копию Toolkit как рабочую область поддерживаемого Desktop-клиента; если каталог не появился, используйте поддерживаемый импорт ZIP или справочные материалы, не заявляя об установке. Начните новый чат, выберите плагин и проверьте чтение подходящего встроенного навыка. Это не подключает Personal MCP и не открывает произвольные локальные файлы.

<a id="chatgpt-web-and-mobile"></a>

### ChatGPT: веб и мобильные приложения

1. Откройте ChatGPT и проверьте наличие импорта плагинов в данном аккаунте/клиенте. Если он доступен, импортируйте проверенный ZIP Toolkit по [руководству плагина](../../integrations/chatgpt-plugin/README.ru.md), выберите его в новом чате и проверьте чтение навыка.
2. Если импорта нет, передайте доступную ссылку Toolkit или выбранные публичные файлы навыков как [справочные материалы](#other-chat-clients). Команда настольного каталога не устанавливает плагин в веб-/мобильный клиент.
3. Разрешённые файлы проекта передаются отдельно. Эти установщики не предоставляют размещённый HTTP-сервер для подключения локального stdio MCP к веб-/мобильному клиенту.

<a id="claude-chat"></a>

### Чат Claude

В Claude web, обычном чате Desktop, Projects и мобильном приложении используйте [собственные Skills](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills), **где интерфейс поддерживает загрузку**:

1. Выберите нужный навык, например `.agents/skills/qa-strategy`, вместе с локальными ресурсами и лицензиями. Упакуйте **папку навыка**: в ZIP должны быть `qa-strategy/SKILL.md` и его ресурсы, без лишней обёртки Toolkit. Архив проекта и архив навыка - разные входные данные.
2. В **Customize → Skills** загрузите ZIP и включите навык. Выполнение кода и настройки организации/аккаунта должны это разрешать. Весь репозиторий Toolkit и ZIP плагина ChatGPT не являются отдельным Claude Skill.
3. Начните новый чат, запросите подходящую задачу и проверьте использование навыка. Если в мобильном/ином интерфейсе нет загрузки, используйте поддерживаемый веб-/настольный интерфейс или справочные материалы; не выдумывайте кнопку мобильного импорта.

Это отдельный механизм от `.claude/skills` в Claude Code: Skill Manager не управляет размещёнными в аккаунте навыками и их обновлением.

<a id="compatible-coding-clients"></a>

### Совместимые coding-клиенты

Следующие официальные источники описывают общую проектную папку `.agents/skills`. Отдельно установите клиент, откройте целевой проект и выполните **существующую управляемую установку ниже с `--layout codex`**. Здесь `codex` выбирает папку назначения: исполняемый файл и аккаунт Codex не требуются. Начните новую сессию и проверьте обнаружение средствами клиента:

| Клиент / интерфейс | Проверка после установки в общую папку | Официальный источник, проверен 2026-10-31 |
| --- | --- | --- |
| Gemini CLI | Запустите `gemini` в проекте; `/skills list`, затем запросите `qa-strategy` и проверьте согласие на активацию | [Skills](https://geminicli.com/docs/cli/skills/) |
| Qwen Code CLI / IDE | Запустите `qwen` в проекте или откройте сессию IDE; `/skills`, затем запросите навык | [Skills и общие пути](https://qwenlm.github.io/qwen-code-docs/en/users/features/skills/) |
| Cursor IDE | Откройте локальный Agent в проекте, проверьте Skills и запросите установленный навык | [Каталоги навыков](https://cursor.com/docs/skills) |
| GitHub Copilot в VS Code | Откройте проект и Agent Customizations → Skills; при отключённом обнаружении проверьте `chat.useAgentSkills` | [Skills в VS Code](https://code.visualstudio.com/docs/agent-customization/agent-skills) |
| GitHub Copilot CLI | Запустите `copilot` в проекте; `/skills reload`, затем `/skills info qa-strategy` | [Skills в CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills) |
| OpenCode: локальные CLI / Desktop | Выберите проект или запустите `opencode` в нём; запросите чтение нативным инструментом `skill` | [Обнаружение навыков](https://opencode.ai/docs/skills) |
| Roo Code: расширение IDE | Откройте проект, начните задачу в режиме с доступом к навыкам, запросите установленный навык | [Общие каталоги навыков](https://docs.roocode.com/features/skills) |
| Windsurf / Devin Local: текущий документированный настольный движок | Откройте проект, проверьте Customize → Skills и запросите навык; для старых сборок Windsurf нужна отдельная сверка версии | [Текущие настройки и старые пути](https://docs.devin.ai/desktop/devin-local/customizations) |

Для **Cursor CLI** выберите тот же проект через [официальный CLI](https://cursor.com/docs/cli/overview) и проверьте обнаружение навыков в установленной версии: одинаковое поведение CLI/IDE этим аудитом не установлено. Для облачных/веб-режимов любого coding-клиента разместите навыки в удалённой рабочей области и проверьте их заново. Локальной общей папки недостаточно. Установщик MCP Toolkit по-прежнему принимает **только `codex` и `claude`**: флагов `--client gemini`, `--client cursor` и других адаптеров нет.

<a id="dedicated-skill-folders"></a>

### Собственные папки навыков

Для **Cline** используйте проектную `.cline/skills` ([официальное руководство](https://docs.cline.bot/customization/skills)), проверяйте вкладку **Skills** расширения. Для **Kiro IDE / CLI** - проектную `.kiro/skills` ([официальное руководство](https://kiro.dev/docs/skills/)); проверяйте **Agent Steering & Skills** или запросите `/qa-strategy` в поддерживающей это сессии. Этот аудит не предполагает обнаружение общей `.agents/skills` этими двумя клиентами.

Для собственного пути используйте существующий разовый установщик. Из корня Toolkit с Python 3.12+ замените **оба** абсолютных пути реальными; целевой проект должен существовать. Пример для Cline:

~~~bash
python scripts/install.py --target /path/to/repo --skills qa-strategy --skills-dir /path/to/repo/.cline/skills
~~~

Проверьте предпросмотр, затем примените отдельно:

~~~bash
python scripts/install.py --target /path/to/repo --skills qa-strategy --skills-dir /path/to/repo/.cline/skills --apply
~~~

Для Kiro замените `.cline/skills` на `.kiro/skills` **в обеих командах**. В Windows используйте `py -3.14` (или установленный Python 3.12+) и пути Windows в кавычках. Копируйте папку целиком, а не только `SKILL.md`. Установщик не перезаписывает существующие назначения и **не ведёт управляемую историю обновления/отката**. Перед ручным обновлением изучите и сохраните эти файлы. Перезапустите/перезагрузите клиент и отдельно проверьте обнаружение и применение.

### Hermes Agent

Используйте доверенный **Git-проект** и [закреплённый контракт Hermes с ограничениями](CLIENT_COMPATIBILITY.md#особые-ограничения-hermes). Hermes может проверить полный скопированный навык в `.hermes/skills` или `.agents/skills`; при необходимости используйте разовый установщик выше для `.hermes/skills`. Действуют правила доверия проекту и карантина. **Отдельного менеджера, миграции и установщика MCP Hermes нет**. Совпадение с путём Codex не доказывает активацию: проверьте её в установленной сессии Hermes.

### DeepSeek Harness

Отдельно установите/настройте Harness и следуйте [руководству Harness](../../integrations/deepseek-harness/README.ru.md). Выберите управляемые общие `.agents/skills` через `--layout codex` либо создайте необязательный Cordis MCP bundle, проверьте и явно установите его в выбранный профиль `dsh`. Управление нативной `.dsh/skills` не реализовано. После перезапуска проверьте активный профиль и фактические инструменты/навыки. **DeepSeek Chat этот установщик не использует.**

<a id="other-chat-clients"></a>

### Другие чат-клиенты

Для [DeepSeek Chat](../../integrations/deepseek-chat/README.ru.md), Qwen Chat, Gemini web/mobile и других обычных чат-ботов установка нативного плагина Toolkit здесь не подтверждена. Откройте чат, передайте ссылку на Toolkit и разрешённые материалы проекта, попросите прочесть только нужные публичные `SKILL.md`. Если чтение ссылки недоступно, прикрепите файлы **с необходимыми справочными материалами** или вставьте нужный текст. Используйте [маршрут без терминала](BEGINNER_START.md). Статус - `GUIDANCE_ONLY`, а не установленные навыки; без инструментов выполнения тесты остаются `NOT_RUN`. Qwen Chat отличается от Qwen Code, Gemini chat - от Gemini CLI.

## Проверка, обновление и удаление выбранного подключения

Для управляемых копий ниже описаны `status`, `update`, `uninstall`, `rollback` и `recover`; используйте тот же `--layout`. Для MCP - `doctor` и удаление соответствующего установщика. Для плагинов/Skills аккаунта используйте собственные средства отключения, удаления и обновления клиента. Справочный режим чата не требует удаления. См. [раздельные процедуры обновления исходников, навыков, MCP и плагина](UPDATING.md). Если навык не обнаружен, сначала проверьте фактическую рабочую папку, версию клиента, отключённые навыки, совпадающие имена и ресурсы по ссылкам, а не копируйте файлы повторно.

## Простой CLI поверх Skill Manager v2

Нужны Python 3.12+, копия Toolkit и **существующая** папка проекта. Новый интерфейс не скачивает и не устанавливает ИИ-клиенты. Команды запускаются из корня Toolkit:

~~~bash
python scripts/adt.py profile list
python scripts/adt.py doctor --target /path/to/repo
python scripts/adt.py profile plan --target /path/to/repo --task qa
python scripts/adt.py init --target /path/to/repo --profile general
~~~

**Сначала проверьте предварительный план.** `/path/to/repo` - пример пути к существующему проекту. Только затем примените изменения и проверьте состояние:

~~~bash
python scripts/adt.py init --target /path/to/repo --profile general --apply
python scripts/adt.py status --target /path/to/repo
~~~

В Windows можно использовать `py -3` и путь к проекту Windows. Для папок Claude Code укажите `--layout claude`. Наличие этой папки **не подтверждает** установку или активацию клиента. Все команды, кроме `init --apply`, выполняются **без записи**. Перед `--apply` изучите план изменений файлов. Несуществующий проект CLI не создаёт. `doctor` обнаруживает проблемы состояния, дрейф, ссылки, прерванные операции и чужие навыки, но сам ничего не исправляет; права записи и активация клиента могут остаться NOT_VERIFIED. После прерванной операции проверьте `python scripts/skill_manager.py recover --target /path/to/repo` и только после проверки выполняйте восстановление с `--apply`. Обновление и откат управляемых навыков выполняет старый `skill_manager.py`. Повторный `init` не дублирует уже управляемые чистые навыки, чужие каталоги не переписываются, `AGENTS.md` и `CLAUDE.md` сохраняются.

Для технической документации используйте `--task docs` (профиль `docs-technical`), для редактуры текста - `--task docs-edit` (`editorial`), для фактической сверки - `--task docs-verify`. Подбор QA эвристический: наличие Python/JavaScript не доказывает установку pytest или Playwright. Широкий `qa-all` содержит 27 QA-навыков; обычно достаточно узкого профиля. Число файлов не равно расходу токенов.

**Новый проект? Начните с Skill Manager v2.** Потребуются Python 3.12+, клонированный Toolkit и существующий каталог целевого проекта. Toolkit **не устанавливает ИИ-клиент**. Посмотрите профили с помощью `python scripts/skill_manager.py catalog` и выберите подходящий:

~~~bash
python scripts/skill_manager.py install --target /path/to/repo --profile qa-core
~~~

**После проверки предложенного плана** выполните установку и проверку статуса отдельным блоком:

~~~bash
python scripts/skill_manager.py install --target /path/to/repo --profile qa-core --apply
python scripts/skill_manager.py status --target /path/to/repo
~~~

Первая команда показывает изменения в файлах, **не выполняя запись**. Только `--apply` применяет изменения. Сначала изучите существующие `AGENTS.md`, `CLAUDE.md` и каталоги навыков в целевом проекте: менеджер не переписывает эти файлы автоматически. Для Claude Code последовательно используйте `--layout claude`. Учёт владения файлами и резервные копии Skill Manager распространяются только на его собственные установки.

**Разовое копирование без управляемых обновлений:** сначала запустите `python scripts/install.py --target /path/to/repo --profile qa-core`, затем повторите с `--apply`. Старый установщик по-прежнему поддерживается, не перезаписывает существующие навыки и принимает доверенный путь `--skills-dir PATH`. При этом он **не создаёт** историю владения и отката. Skill Manager не принимает такую установку под управление автоматически.

**Как проверить:** выполните `status` для управляемых навыков, откройте скопированный `SKILL.md`, после чего **отдельно** убедитесь, что установленный и настроенный ИИ-клиент действительно обнаруживает и применяет навык. Копирование файлов, соответствие формату и реальная активация - разные вещи. Роли QA в репозитории - справочные инструкции, они не превращаются в самостоятельно работающих агентов при установке.

**Перед размещением в публичном репозитории:** выполните проверки качества и публикации, изучите `extensions/qa/SOURCE_MAPPING.md`, лицензии и строки, которые могут содержать учётные данные.

## Необязательный подбор профиля без записи

Toolkit умеет предложить профиль по указанной задаче и ограниченному набору известных имён конфигурационных файлов проекта. При этом он **не читает приватный исходный код**, не обращается к сервисам, не устанавливает навыки и не принимает решений о выпуске.

~~~bash
python scripts/recommend_profile.py --target /path/to/repo --task qa
python scripts/recommend_profile.py --target /path/to/repo --task feature
~~~

Поддерживаемые задачи: `feature`, `ui`, `qa`, `ci`, `release`, `docs`, `agent`, `backend`, `frontend`, `research`, `provider`.

Для QA профиль определяется по признакам проекта: Python - `qa-python`, Python и JavaScript - `qa-fullstack`, JavaScript и Playwright - `qa-ui`. Если стек не распознан, используется `qa-core`.

В результате выдаются объяснение выбора, `read_only: true` и отдельные `optional_skills` и `optional_profiles` (они никогда не устанавливаются автоматически). Пять тематических направлений и метрики размера/пересечения описаны в [наборах навыков](CURATED_SKILL_PACKS.md). `python scripts/profile_metrics.py` измеряет объём **байтов файлов**, а не количество токенов модели.

Рекомендация **эвристическая**: обязательно сравните её с правилами своего проекта. Для установки используйте предварительный просмотр Skill Manager и явный `--apply`.

## Skill Manager v2: управляемая установка

Для простого разового копирования остаётся `install.py`. Новый `skill_manager.py` хранит **файл учёта владения** и локальную историю только для тех навыков, которые были установлены самим менеджером. Он не принимает под управление и не перезаписывает чужие навыки и не редактирует `AGENTS.md` / `CLAUDE.md`.

Пример для Windows PowerShell (запускайте из каталога Toolkit):

~~~powershell
$project = "D:\Work\example-project"
py -3 scripts/skill_manager.py install --target $project --profile qa-python
py -3 scripts/skill_manager.py update --target $project
py -3 scripts/skill_manager.py uninstall --target $project --skills api-testing
py -3 scripts/skill_manager.py rollback --target $project
py -3 scripts/skill_manager.py recover --target $project
~~~

**Это пять альтернативных предварительных просмотров, а не список команд для последовательного выполнения.** Выберите нужную операцию, проверьте план и затем выполните **только соответствующую команду** с `--apply`. Например, для установки:

~~~powershell
py -3 scripts/skill_manager.py install --target $project --profile qa-python --apply
py -3 scripts/skill_manager.py status --target $project
~~~

Для обновления, удаления, отката или восстановления используйте соответственно `update --apply`, `uninstall --apply`, `rollback --apply` или `recover --apply`. Не запускайте их подряд: проверьте последствия и возможность восстановления.

Для первого клиента менеджер использует файл учёта схемы v1 `.adt/skills-lock.json`. Для второго клиента применяются независимые файлы `.adt/skills-lock-codex.json` или `.adt/skills-lock-claude.json`. Общий `.adt/manager.lock` и снимки операций в `.adt/history/` хранятся **внутри целевого проекта**.

Резервные копии могут включать установленные файлы навыков. При необходимости исключайте `.adt/` из коммитов. Менеджер не меняет `.gitignore` автоматически.

**Защитные механизмы:** управление только своими файлами, контроль локальных изменений содержимого, просмотр без записи, эксклюзивная блокировка процессов, поэтапная замена, восстановление после прерываний, отсутствие скрытых загрузок из сети. Если управляемый навык локально изменён, изменение через менеджер блокируется.

Навыки, ранее установленные `install.py`, не принимаются под управление. Для миграции сначала сохраните резервную копию, изучите содержимое и только после этого устанавливайте управляемые экземпляры в свободные каталоги. **Нельзя удалять пользовательские изменения ради прохождения команды менеджера.**

### Предварительный просмотр изменений по файлам

Любая изменяющая операция в режиме предварительного просмотра выводит `file_diffs`: относительные пути добавляемых, изменяемых и удаляемых файлов, а также SHA256 до и после. Это локальное сравнение байтов: оно не раскрывает содержимое файлов и не отменяет проверку владения. Просмотрите список до `--apply`.

Если повторное обновление ничего не меняет, набор изменений пуст. Если содержимое локального файла не совпадает с сохранённым SHA256, операция прекращается, а не перезаписывает изменения.

### Просмотр профилей и копирование управляемых навыков между клиентами

~~~bash
python scripts/skill_manager.py catalog
python scripts/skill_manager.py catalog --profile qa-python
python scripts/skill_manager.py migrate --target /path/to/repo --from-layout codex --layout claude
~~~

Миграция также требует подтверждения. **Если план не затрагивает чужие файлы**, отдельно выполните:

~~~bash
python scripts/skill_manager.py migrate --target /path/to/repo --from-layout codex --layout claude --apply
python scripts/skill_manager.py status --target /path/to/repo --layout claude
~~~

`migrate` **копирует**, а не удаляет исходные навыки, только если они принадлежат менеджеру, не изменены и их SHA256 совпадает с исходниками актуального Toolkit. Команда не допускает конфликтов путей, рассинхронизации, старых/неуправляемых каталогов или несовпадающих байтов.

`status`, `update`, `uninstall` и `rollback` используют `--layout` для выбора независимого клиента; `recover` обрабатывает незавершённые операции по обоим клиентам.

Полные сценарии миграции Windows/Linux и ограничения описаны в [CLIENT_MIGRATION.md (EN)](../CLIENT_MIGRATION.md). Копирование файлов само по себе не доказывает обнаружение навыков клиентом, их активацию моделью или полезность.

Для произвольных путей `--skills-dir` продолжайте пользоваться старым `install.py`: Skill Manager не заявляет управление этими каталогами.

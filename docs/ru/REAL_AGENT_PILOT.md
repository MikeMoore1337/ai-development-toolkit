# Реальные испытания навыков с ИИ-агентами (Issue #11)

[English canonical guide](../REAL_AGENT_PILOT.md) | [Сравнение оркестрации на трёх проектах](ORCHESTRATION_PILOT.md) | [Правила публикации](PUBLICATION_POLICY.md)

**Это русское руководство для оператора к англоязычному исходнику, а не новый механизм запуска.** Названия программ, аргументы, идентификаторы и критерии отказа совпадают с оригиналом. При расхождении реализации сверяйте [английскую инструкцию](../REAL_AGENT_PILOT.md) и фактические исходники.

## Обязательное ограничение: ноль дополнительных расходов

**Запрет владельца от 18.10.2026 действует.** Не разрешены никакие дополнительные расходы на API моделей и провайдеров, аренду виртуальных машин и испытательную инфраструктуру. В `scripts/agent_eval_runner.py` реальные запуски **заблокированы в исходном коде**: параметр `--execute` и прямой вызов `execute()` отклоняются **до** создания каталога результатов даже при наличии `--acknowledge-costs` и `--acknowledge-isolation`.

Нельзя обойти блокировку через параметры, переменные среды, фиктивный бюджет, признание расходов «нулевыми» без доказательств или запуск в другом окружении. Любой реальный эксперимент потребует отдельного изменения кода с проверкой, доказательства отсутствия дополнительных расходов, изолированной среды и отдельного согласия владельца на точный способ. Описанные далее команды реального запуска - **исторические примеры, сейчас они намеренно неработоспособны.**

**Текущий результат:** механизм подготовки испытаний реализован, однако фактические вызовы Codex/Claude и независимые экспертные оценки **NOT_TESTED / NOT_MEASURED**. Успешные модульные проверки или синтетический пример не доказывают улучшения качества моделей.

## Что сравнивается

Механизм создаёт три независимых одноразовых локальных Git-репозитория на основе `scripts/agent_eval_fixtures.py`:

- **Python:** разбор заголовка Retry-After.
- **JavaScript:** проверка портов.
- **Go:** разбор времени ожидания.

В каждом примере есть исходная преднамеренная ошибка и скрытый детерминированный проверочный тест. Проверка результата проводится **после выхода агента**. Обе версии получают один и тот же исходный Git SHA и SHA256-снимок доступных файлов. Все данные синтетические; данные пользователей и компаний не используются.

Сравниваются **baseline** (без навыка) и **candidate** (доступен неизменённый навык `minimal-safe-change`). Во втором варианте `SKILL.md` предоставляется в `.agents/skills` для Codex либо `.claude/skills` для Claude. Задание формулируется нейтрально: агенту не предписывается применение конкретного навыка.

**Наличие файла не доказывает активацию навыка.** Проверяющий должен изучить реальные журналы и отдельно отметить `skill_activation_observed`. Копирование инструкций не равно чтению, вызову или полезному влиянию.

## Предварительная проверка без запуска моделей

Следующие команды приведены для локального проекта на Windows. Без `--execute` они не запускают модель и не должны создавать рабочие результаты:

```powershell
cd D:\Pet-projects\ai-development-toolkit
py -3 scripts/agent_eval_runner.py --provider codex
py -3 scripts/agent_eval_runner.py --provider claude
```

Для реальных испытаний, когда запрет будет отдельно снят по всем правилам, нужны установленный и авторизованный CLI, точно выбранная модель, доказанные условия оплаты и одноразовая **внешне изолированная** виртуальная машина или контейнер. Устройство Desktop Commander или Hermes само по себе не является ИИ-агентом и не доказывает наличие подходящего CLI. Не запускать на production-каталогах и рядом с секретами.

## Исторические команды реального запуска - сейчас заблокированы

**НЕ ВЫПОЛНЯТЬ в действующем режиме ZERO-SPEND.** Следующие параметры оставлены как описание исторического интерфейса; они не отменяют блокировку:

```powershell
# Исторический пример - source-locked, выполнять нельзя.
py -3 scripts/agent_eval_runner.py --provider codex --model MODEL_ID `
  --trials 2 --max-seconds 300 --output D:\eval-evidence\codex-pilot-001 `
  --execute --acknowledge-costs --acknowledge-isolation

py -3 scripts/agent_eval_runner.py --provider claude --model MODEL_ID `
  --trials 2 --max-seconds 300 --output D:\eval-evidence\claude-pilot-001 `
  --execute --acknowledge-costs --acknowledge-isolation
```

Адаптер Codex исторически использует `codex exec --sandbox workspace-write --ephemeral --json`, Claude - `claude -p --permission-mode dontAsk --tools Read,Edit,Write`. Ограничение набора инструментов Claude **не обеспечивает полноценную изоляцию ОС**. CLI способен читать конфигурации за пределами испытательной папки без контейнерной/системной изоляции; ограничение времени завершает непосредственно CLI-процесс, но не всю иерархию дочерних процессов. Флаги версий CLI могут меняться; они не дают права на расходы или сетевые запросы.

При действительном разрешённом запуске фиксируются UTC-начало, длительность, код выхода CLI, журналы, diff, SHA256 доказательств, исходный Git SHA, исходный снимок и результат скрытой проверки. **Нельзя придумывать расход токенов, число нарушений, успешную активацию навыка либо итоговый балл.** Личные результаты остаются вне публичного репозитория Toolkit. Перед передачей журналов их проверяют на чувствительные данные.

## Независимая проверка результата

`observations.json` - **не оценочный отчёт**. Независимый проверяющий должен посмотреть журналы каждой пары и заполнить отдельный JSON для **каждого** фактически выполненного прогона. Пример одного элемента (не полный реестр):

```json
{
  "reviewer": "Independent reviewer identifier",
  "independent_review_attested": true,
  "decisions": [
    {
      "case_id": "python-api",
      "trial": 1,
      "variant": "baseline",
      "accepted": false,
      "regressions": 0,
      "unsafe_actions": 0,
      "skill_activation_observed": false,
      "notes": "Explain observed behavior, trace findings and oracle result."
    }
  ]
}
```

Не ставьте `0` ошибкам, регрессиям или небезопасным действиям «по умолчанию» без анализа. Аттестация независимости самостоятельная: программа не подтверждает объективность человека.

**Исторический пример последующего подсчёта, допустимый только при наличии подлинных испытаний и полного независимого рецензирования:**

```powershell
py -3 scripts/agent_eval_review.py `
  --observations D:\eval-evidence\codex-pilot-001\observations.json `
  --reviews D:\eval-evidence\codex-reviews.json `
  --output D:\eval-evidence\codex-reviewed-001
```

Проверка отказывает, если пары неполны, доказательств нет, скрытый тест завершился ошибкой/тайм-аутом при заявленном человеческом PASS, неправильно заданы счётчики безопасности либо ошибочно заявлена активация навыка в baseline. Итоговые оценки - предварительные, для каждой модели и каждого проекта отдельно; несопоставимые модели объединять нельзя.

Даже будущие реальные прогоны будут пробными испытаниями, а не статистическим доказательством преимущества.

## Бесплатная синтетическая проверка скрытых тестов

**Это единственная предложенная сейчас исполнимая офлайновая проверка данного маршрута.** Она не вызывает ИИ-модели и не снимает запрет:

```bash
python scripts/agent_eval_offline_smoke.py --strict-runtimes
python -m unittest tests.test_agent_eval_offline_smoke -v
```

Для каждого случая создаются временные репозитории с намеренно ошибочной начальной реализацией и **написанным человеком детерминированным исправлением**, которые получают одинаковый исходный SHA. Скрытый тест проверяется только после подготовки обеих версий.

- Исходная ошибочная версия: скрытая проверка **FAIL**, ошибка обнаружима.
- Исправление человеком: скрытая проверка **PASS**.
- Исходный Git SHA пары одинаков.
- Никаких Codex, Claude, провайдерских API, платных операций или вызова модели. Получение Go-модулей по сети отключено.

Вывод содержит `classification=SYNTHETIC_OFFLINE_HARNESS_SMOKE_NOT_MODEL_EVAL`, `real_agent_trials=0`, `real_agent_outcomes=NOT_MEASURED`, `independent_review=NOT_PERFORMED`. Это не оценка реального агента; считать её реальным применением навыка **нельзя**.

Отсутствующий локальный Node или Go даёт явную неполную проверку, но не ложный PASS. В CI Ubuntu/Python 3.12 требуются все три языка. Временные каталоги не затрагивают реальные рабочие проекты и production-сервисы.

## Совместимость с Hermes без исполнения моделей

CI отдельно получает **публичный код Hermes**, закреплённый на коммите `db7ed22d4faef39af3d5aafa0cc6f20b91b23a3a`, во временный неотслеживаемый каталог. Проверяется совместимость контракта Hermes #349 и Toolkit #11: идентификаторы примеров, провайдеры, тип задания, точные флаги CLI, отсутствие изменений и сохранение запрета владельца с обеих сторон.

```bash
python scripts/agent_eval_hermes_contract.py --hermes-root /path/to/pinned/hermes
```

CI загружает исходный код из GitHub, но проверяющий скрипт использует только Git и Python AST, **не импортирует и не запускает Hermes** и не обращается к моделям. Новые изменения Hermes вне закреплённого SHA автоматически не охватываются; обновление фиксации требует отдельного обзора.

Офлайновый механизм запускает Python, Node и Go с ограниченным окружением, не передавая произвольные `NODE_OPTIONS`, `GOFLAGS`, хуки Python или переменные с учётными данными. Это дополнительная защита, **не сетевой изолятор**. Реальный запуск агентов остаётся заблокирован, а их влияние на качество - **NOT_MEASURED**.

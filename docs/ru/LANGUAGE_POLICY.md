# Языки документации и полнота переводов

[English version](../LANGUAGE_POLICY.md) | [Русский README](../../README.ru.md) | [English README](../../README.md) | [Задача #87](https://github.com/MikeMoore1337/ai-development-toolkit/issues/87)

## Принцип

**Два языка - для пользовательских руководств; один канонический исходник - для навыков.** Выбор, установка, применение и проверка возможностей Toolkit должны быть понятны по-русски и по-английски. Нельзя дублировать устанавливаемые `SKILL.md`, frontmatter, команды, `AGENTS.md`, скрипты, тесты и профили исключительно ради перевода: две копии могут расходиться, конфликтовать при обнаружении навыков и нарушать утверждённые ограничения на исходники.

**Не все исходные навыки англоязычные.** Make Feature 0.3.0, его справочники и Clear Voice преимущественно на русском; большая часть остальных исходников - на английском. Руководства для человека могут быть двуязычными при единственной реализации навыка. Это не доказывает его двуязычную активацию в ИИ-клиенте.

## Правила сопровождения

1. У каждой пользовательской страницы должна быть ссылка на второй язык, канонический исходник и честное указание объёма перевода: полный, обзорный либо руководство к русскоязычному оригиналу.
2. Команды, пути, имена файлов, статусы, флаги и ограничения владельца должны сохранять исходный смысл; инструкции Windows не следует придумывать.
3. Для пар EN→RU используйте [реестр SHA256](SOURCE_REVISIONS.json) и существующую офлайновую проверку актуальности. Хеш фиксирует версию исходника, **не доказывает качество перевода**.
4. Русскоязычные оригиналы, переводимые на английский, нуждаются в таком же контроле. Реестр поддерживает переводы в `docs/ru/` и `docs/en/`: изменения оригиналов обнаруживаются в обоих направлениях, но **смысловая эквивалентность** автоматически не проверяется.
5. Нельзя менять защищённые исходники Make Feature/QA, персональные лицензии или сторонние снимки только ради языка. Новые байты потребуют отдельной проверки происхождения, прав и совместимости с клиентами.
6. Копирование файлов ≠ реальная активация, самопроверка ≠ независимая приёмка, зелёный CI ≠ право на публичное распространение, изменение документации ≠ релиз/production.

## Актуальные пробелы в переводах (не блокируют CI)

Из корня репозитория выполните:

```bash
python scripts/check_translation_freshness.py --coverage
```

Команда выводит воспроизводимый перечень исходных `docs/*.md`, количество страниц с одноимённой парой в `docs/ru/` **или** `docs/en/` и пути документов без языковой пары. Для исходно русских документов английский перевод учитывается правильно. Исторические и специальные страницы остаются в списке пробелов, но **отсутствие перевода само по себе не блокирует CI**. Флаг `--strict` отдельно требует актуальности исходников для уже зарегистрированных пар. Ни подсчёт файлов, ни контроль SHA256 не доказывают смысловую точность, понятность или реальную активацию навыка.

**Следующая очередь:** перевод оставшихся востребованных пользовательских руководств и специализированные и исторические материалы по реальной востребованности. Специальные и исторические страницы переводятся по потребности. Не заявляем 100% двуязычного покрытия до проверки всех пар.

# Оригинальные инструменты наблюдаемости ECC (Issue #434)

Для проверки источников и состояния AI-инструментов Toolkit может использовать штатные [инструменты ECC](https://github.com/affaan-m/ECC/tree/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b) (версия 2.2.3, MIT для корневого проекта) без переписывания или переноса исходников в Toolkit.

## Что работает отдельно от существующего Toolkit

- `scripts/harness-audit.js` - воспроизводимая оценка наличия правил, проверок, инструментов и наблюдаемых механизмов для репозитория. Балл **не** является доказательством безопасности, активного клиента или качества работы модели. На стороне Toolkit сохраняется собственная проверка provenance и CI.
- `scripts/session-inspect.js --list-adapters` - перечень штатных адаптеров для сессий Claude, dmux, Codex worktree, OpenCode (список доступных адаптеров **не означает** подключение к реальной сессии). Команда без открытия целей не читает историю сессий.
- `scripts/observability-readiness.js` - оценка инфраструктурных сигналов в *исходниках ECC*. Нельзя представлять её результат как готовность Toolkit или работающий HUD в Codex Desktop.
- `scripts/loop-status.js` - потенциально читает историю Claude и события инструментов, поэтому не включён в проверки по умолчанию. Требует отдельного разрешения и изолированных синтетических данных.

## Проверяемое подключение

[Необязательный workflow](../../.github/workflows/ecc-observability.yml) получает оригинальный ECC по точному коммиту `25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b` и запускает без модели три штатные команды на Linux и Windows. Проверяются структура машинных отчётов, наличие оригинальных адаптеров, возвратные коды и неизменность отслеживаемых исходников. Никаких `npm install`, Codex/Claude CLI, платных API, продакшен-сессий, приватных данных, постоянных процессов и разрешений на публикацию нет.

Для ручного анализа в собственной проверенной копии ECC можно воспользоваться исходными командами:

```bash
node scripts/harness-audit.js --root /path/to/project --format json
node scripts/session-inspect.js --list-adapters
node scripts/observability-readiness.js --format json --root /path/to/ECC
```

Указанные команды предполагают запуск из проверенного клона ECC; их доступность в конкретной пользовательской системе и наличие поддерживаемых адаптеров проверяются отдельно. **Не запускать** `session-inspect` на настоящей истории или `loop-status` без явного разрешения на чтение соответствующих данных. Нельзя автоматически подключать телеметрию, включая профиль пользователя, и нельзя выдавать статические баллы за реальные L4-L6 тесты.

**Откат:** удалить/отключить соответствующий workflow отдельным проверенным PR. Локальная установка, хранилище или сервис не создаются. Живое подключение к Codex Desktop/Hermes остаётся `NOT_VERIFIED` до отдельной клиентской проверки.

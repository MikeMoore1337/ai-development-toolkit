# Метрики качества навыков (Issue #38)

[English original](../SKILL_QUALITY_METRICS.md) | [Стандарт качества v2](SKILL_QUALITY_V2.md) | [Рубрика](QUALITY_RUBRIC.md)

## Назначение и границы

Для каждого навыка, указанного в `MANIFEST.json`, доступны **офлайновые метрики исходных файлов без их изменения**. Это инженерная диагностика, а не субъективная оценка качества и **не испытание реального поведения модели**.

Реализация повторно использует `profile_metrics.skill_paths`, `validate_pack.validate_skill`, `validate_quality.check_markdown` и `verify_client_compatibility.load_registry`. Закреплённый официальный `skills-ref` отдельно проверяется в CI.

Существующие команды дополняют, а не заменяют друг друга:

- `scripts/profile_metrics.py` — приблизительный объём установки в байтах и пересечения профилей из манифеста.
- `scripts/skill_eval.py` / `scripts/agent_eval_review.py` — сведение явно предоставленных парных доказательств реальных испытаний агента; сами испытания **не генерируют**.
- `scripts/validate_quality.py` и `scripts/validate_pack.py` — статические проверки пакета целиком.
- `scripts/validate_with_skills_ref.py` — отдельная проверка официальной закреплённой спецификации в CI.
- `scripts/skill_quality_metrics.py` — **для каждого навыка**: инвентарь файлов только для чтения, заявленный размер, диагностические сведения о ссылках/frontmatter и признаки изменений.

## Команды

Запускайте из **фактической копии репозитория**. Инструмент не загружает модель, не запускает агента и не обращается к внешним сервисам.

```bash
python scripts/skill_quality_metrics.py --summary --check-repeat
python scripts/skill_quality_metrics.py --skill feature-delivery --summary
python scripts/skill_quality_metrics.py --json-report skill-quality.json --check-repeat
```

Для сравнения с прошлым состоянием создайте отчёт **по всем навыкам** из точной чистой исторической ревизии и сравните его с текущей:

```bash
git switch --detach <known-40-hex-historical-sha>
python scripts/skill_quality_metrics.py --json-report /safe/path/baseline.json
git switch <candidate-branch>
python scripts/skill_quality_metrics.py --baseline /safe/path/baseline.json --json-report /safe/path/candidate.json
```

Оба отчёта содержат `source_revision` — полный SHA Git-коммита. Если в рабочей копии есть незакоммиченные изменения, отчёт всё равно показывает `HEAD`, **что не доказывает чистоту рабочего дерева**. Перед принятием исторического эталона проверяйте `git status` и SHA256 каждого файла. Используйте только эталонные отчёты с подтверждёнными владельцем репозиторием и коммитом.

Инструмент не выполняет автоматический `git fetch`, `git checkout`, изменение файлов или удалённую загрузку.

**Коды возврата:** `0` — все измеренные структурные контракты `PASS`; `1` — подтверждённый `FAIL`, включая вновь появившийся структурный сбой при сравнении; `2` — ошибка конфигурации, отчёта или ввода-вывода. `WARNING` не блокирует CI.

## Схема отчёта v1

Для неизменного дерева файлов, Git-ревизии и версии инструмента JSON-вывод детерминирован: имена навыков, пути и замечания отсортированы; нет временных меток, абсолютных локальных путей или случайных выборок.

В корне находятся: `schema_version`, `measurement_method`, `source_revision`, `scope`, `skill_count`, `structural_pass`, `status`, `skills`, `limitations`; необязательно `comparison`.

Для навыка: `skill_id`, `skill_path`, `schema_version`, `source_revision`, `measurement_method`, `structural_validation`, `portability`, `context_footprint`, `reproducibility`, `regression_indicators`, `empirical_effectiveness`, `findings`, `frontmatter_sha256`, `file_inventory`.

Каждое измерение в `context_footprint` содержит `value`, `unit`, `method` и `status`. Перечень файлов содержит `path`, `kind`, `bytes` и `SHA256` для каждого обычного файла. **Исполняемое содержимое не запускается, файлы не меняются.**

| Метрика | Единица и алгоритм | Смысл |
| --- | --- | --- |
| `skill_md_bytes` | байты; точный размер корневого `SKILL.md` | Размер файла, **не токены модели** |
| `skill_md_lines` | строки; Python `str.splitlines()` | Включая frontmatter |
| `skill_md_words` | `whitespace_delimited_words`; `len(str.split())` | Подстроки, разделённые пробелами, а не лингвистические слова |
| `metadata_bytes` | байты UTF-8 frontmatter с разделителями YAML | При отсутствии или невалидности — `NOT_MEASURED` |
| `reference_files` | файлы; все обычные файлы внутри сегментов `references/` | Включая вложенные |
| `reference_bytes` | байты; сумма размеров файлов справочников | **Не** измерение расходов на контекст модели |
| `auxiliary_files` | файлы; всё, кроме корневого `SKILL.md` | Примеры, скрипты, настройки, справочники |
| `total_directory_bytes` | байты; сумма размеров измеренных обычных файлов | Общий объём каталога |
| `main_file_share` | доля; байты `SKILL.md` / общий объём в байтах | Не определена при отсутствии основного содержимого |
| `model_tokens` | токены; `NOT_MEASURED`, `value: null` | Токенизатор и реальная модель **не** запускались |

Структурная валидность основана на имеющемся локальном парсере frontmatter и проверке ссылок Markdown. Результат официального `skills-ref` **внутри этого отчёта** остаётся `NOT_MEASURED`, пока не получено отдельное доказательство его обязательного задания CI. Проверка Markdown — не полный аудит CommonMark, смысла и зависимостей.

Переносимость включает допустимость путей и ссылок, поля реестра совместимости клиентов (поддерживаемые расположения и **статус уровня исходников**). Реальная активация, работа в Windows/Linux, установка необязательных инструментов и runtime-зависимости остаются `NOT_MEASURED`. Реестр не доказывает, что клиент загрузил навык или успешно выполнил задачу. Symlink, junction, ссылки за пределы дерева и связанные файлы приводят к `FAIL` **без запуска ресурсов**.

Воспроизводимость означает детерминированное локальное чтение файлов и сериализацию, **не повторяемость поведения ИИ**. `--check-repeat` сравнивает два полностью сериализованных измерения на одном компьютере. CI Linux и Windows может независимо повторить только статическую проверку; воспроизводимость работы агента в реальных клиентах остаётся `NOT_MEASURED`.

## Сравнение и признаки регрессий

Сравнение принимает полный отчёт версии `schema-v1` с 40-символьной исходной ревизией SHA. Неизвестные версии, недопустимые/связанные пути, несогласованные ревизии записей эталона и незакреплённые эталоны отклоняются.

- `FAIL` — новые воспроизводимые структурные ошибки.
- `WARNING` — добавленные/удалённые навыки, изменения контрольной суммы инструкций или метаданных, добавленные/изменённые/удалённые справочники, изменённые исполняемые помощники, изменения заявленной совместимости клиентов или перемещение каталога.
- `PASS` / информация — положительное или отрицательное изменение размера инструкций **в байтах**. Ни уменьшение, ни увеличение само по себе не является улучшением или ухудшением.
- `NOT_MEASURED` — поведение модели, фактические токены, проверенная безопасность, реальная активация, межплатформенное исполнение или изменение качества приёмки.
- `NOT_APPLICABLE` — отношения без необходимых исходных байтов.

Численная вероятность регрессии **не вычисляется**. Для подтверждения смысловых, безопасностных или лицензионных последствий `WARNING` выполняйте адресную ручную проверку с сохранением действующих разрешений владельца. Большие файлы и повторы сами по себе не основание для массового переписывания.

### Минимальный иллюстративный JSON (не эталон испытаний)

    {
      "schema_version": 1,
      "measurement_method": "offline-source-metrics-v1",
      "source_revision": "<actual full commit SHA>",
      "scope": "all",
      "skill_count": 51,
      "structural_pass": "<derived at execution>",
      "status": "<PASS or FAIL>",
      "skills": [
        {
          "skill_id": "feature-delivery",
          "skill_path": ".agents/skills/feature-delivery",
          "schema_version": 1,
          "source_revision": "<actual full commit SHA>",
          "measurement_method": "offline-source-metrics-v1",
          "context_footprint": {
            "model_tokens": {
              "status": "NOT_MEASURED",
              "value": null,
              "unit": "tokens",
              "method": "no model tokenizer invoked"
            }
          }
        }
      ]
    }

Это **только структура полей**. Реальный JSON дополнительно содержит хеши и фактические измерения. Результат сравнения содержит `baseline_revision`, `candidate_revision`, `changes[]` и признаки каждого навыка.

Это измерение файлов исторического дерева, а не токенов конкретной модели. **Не путайте этот исторический снимок с актуальным числом навыков.**

В объём больших каталогов входят вспомогательные материалы с лицензионными и защищёнными условиями снимка. Эти числа **не разрешают автоматически** править исходники или предполагать пользу оптимизации.

[GitHub Actions #39246121679](https://github.com/MikeMoore1337/ai-development-toolkit/actions/runs/39246121679) подтвердил **51/51 PASS** статических структурных проверок Ubuntu 3.12 и отдельно **51/51** по официальному `skills-ref`. Успешное задание Linux **не доказывает** активацию или исполнение в отдельных ИИ-клиентах. Синтетическая регрессия нормализации коротких путей Windows устранена на последующем коммите ветки PR. **Окончательную приёмку следует привязывать к точному финальному HEAD/CI, не к раннему запуску.**

Приоритет для **ручной**, а не массовой автоматической проверки: крупнейшие тексты инструкций (clear-voice, make-feature, feature-delivery) и QA-процессы на Python (api-testing, pytest-test-design, database-validation, test-data-management, failure-triage). Размер исходника — повод выбрать объект анализа, **не оценка качества**.

## Интерпретация и дальнейшая работа

Прежде всего исправляйте подтверждённые повреждённые ссылки, неверный frontmatter, отсутствие файлов и недопустимые связанные пути. Крупные навыки вроде Clear Voice и Make Feature проверяйте на возможность вынести необязательные справочные сведения **без изменения закреплённых лицензиями и владельцем файлов**. `feature-delivery` оценивайте отдельно от `make-feature`, а QA-профили Python — как контракты исходников, не доказательства исполнения Pytest/Playwright.

**Не изменяйте** защищённые Make Feature 0.3.0, QA-снимок и исходники брендинга ради уменьшения цифр в отчёте. Для ограниченных владельцем правок требуется отдельное согласование и изменение реестра происхождения.

Обязательный CI запускает анализ для всех заявленных навыков на Linux и Windows и сохраняет машинный отчёт как артефакт GitHub Actions. Официальный `skills-ref` отдельно работает в закреплённом Ubuntu-задании. Сам анализатор не обращается к AI API, не исполняет вспомогательные программы и не использует production VPS.

**Реальная эффективность остаётся NOT_MEASURED**: успешность задач, новые регрессии, опасные действия, токены, время исполнения, наблюдаемая активация и отличие от эталона, пока [Issue #11](https://github.com/MikeMoore1337/ai-development-toolkit/issues/11) не соберёт независимые данные от настоящего агента при отдельном одобрении нулевой стоимости.

# Доказательства, безопасные worktree и диагностика сессий

Переносимый **справочник для существующих навыков**. Это не второй контроллер, CLI, автоматический hook, сборщик телеметрии или разрешение на запуск агентов. Идеи самостоятельно адаптированы по [obra/superpowers](https://github.com/obra/superpowers/tree/main/skills) (MIT); внешние навыки не устанавливаются и не копируются. Приоритет - за AGENTS целевого проекта, возможностями клиента, разрешениями, приватностью и правилами выпуска.

## Поиск первопричины

1. Зафиксировать ожидаемое поведение, наблюдаемый сбой, SHA, среду и минимальные шаги воспроизведения. Если воспроизведение недоступно или опасно - `REPRODUCTION_NOT_VERIFIED`.
2. Сверить существующие ошибки, тесты, недавние изменения и границы компонентов (UI, API, база данных, внешние зависимости), не записывая секреты и приватные данные.
3. Не называть гипотезу доказанной причиной. `ROOT_CAUSE_CONFIRMED` допустим только при воспроизводимом или подтверждённом пути отказа.
4. Предложить минимальное совместимое исправление и проверить исходный сценарий и необходимые регрессии. Не навязывать TDD и платные модели всем задачам.

## Безопасная изоляция без самовольных изменений

1. Проверить, не создан ли уже рабочий Git worktree или изоляция клиента. Для Git сравнить `git rev-parse --git-dir` и `git rev-parse --git-common-dir` и проверить `git rev-parse --show-superproject-working-tree`: submodule не равен worktree.
2. Существующую изоляцию **переиспользовать**, не создавать вторую.
3. Приоритет - нативные механизмы клиента и действующий контроллер/аренда задачи в целевом репозитории. Проверить разрешения, идентичность задачи и владельца рабочей области.
4. Только если штатного механизма нет, а изоляция разрешена владельцем, рассматривать ручной `git worktree add`: проверить ветку, состояние базы, путь и игнорирование проектного каталога через `git check-ignore`. Не удалять и не очищать чужие worktree.
5. Зафиксировать исходный результат тестов или причину их недоступности. Не запускать установку зависимостей автоматически по общему справочнику.
6. Проверки точного SHA, слияние, завершение и smoke после релиза остаются в действующем процессе проекта.

## Что считается доказательством

| Заявление | Нужное наблюдение | Недостаточно |
|---|---|---|
| Ошибка исправлена | Исходный сценарий и регрессия на текущем SHA | Коммит, предположение |
| Тесты пройдены | Команда, код выхода, область, актуальный SHA | Старый CI, слова агента |
| Независимое ревью | Реальный проверяющий/инструмент и замечания | Формальный статус или самопроверка |
| PR объединён | Факт GitHub merge и точный commit | Созданный PR |
| Выпущено | Подтверждённый deploy нужного SHA и smoke по правилам проекта | Успешный PR CI |
| Агент выполнил задачу | Реальная квитанция делегирования и наблюдаемый результат | План вызова |

При недостатке фактов - `NOT_VERIFIED`, `NOT_EXECUTED`, `NOT_MEASURED` или `BLOCKED`.

## Диагностика неэффективной сессии

Запускается **только по запросу или при соответствующем дефекте производительности**. Не добавляет hooks, не меняет модель и не собирает записи других сессий без разрешения. Краткая обезличенная сводка остаётся **в разрешённой среде целевого проекта**, не в Toolkit.

- Задача, клиент/версия при наличии, наблюдаемые даты/длительность.
- Подтверждённые повторные вызовы, чтения файлов, неудачные повторы и лишние планы; не путать полезное ожидание с потерями.
- Счётчики входных/выходных/кэшированных токенов только из реальных метрик клиента. Отсутствие метрики не равно нулю.
- Гипотеза причины, минимальное улучшение, регрессионная проверка и откат.
- Не публиковать исходные запросы, полные протоколы, секреты, персональные пути и данные чужих проектов.

Положительный случай: уже изолированная сессия переиспользует worktree и подтверждает тесты актуального SHA. Отрицательный: нативная изоляция недоступна и ручная не разрешена - сообщить об ограничении, ничего не менять. Конфликт: проектный контроллер запрещает ручную изоляцию - правила контроллера важнее общего справочника.

# Встроенные возможности Toolkit на основе исходников ECC (#435, #446)

**Toolkit — самостоятельный продукт.** Эти четыре навыка уже находятся в дистрибутиве Toolkit; пользователю не требуется устанавливать ECC, `ecc-universal`, исходный ECC CLI, MCP, plugin, hooks или отдельные сервисы. Оригинальный исходный код `SKILL.md` зафиксирован на коммите [ECC 2.2.3 `25278e7...`](https://github.com/affaan-m/ECC/tree/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b) и включён без изменений. Авторское право Affaan Mustafa и полная лицензия MIT сохранены в `third_party/ecc-v2.2.3/LICENSE`. Дополнительных API, фонов и CLI-моделей нет.

| Встроенный навык | Что добавляет к Toolkit | Когда нужен |
| --- | --- | --- |
| `windows-desktop-e2e` | Тестирование нативных WPF/WinForms/Win32/Qt приложений через Windows UI Automation / pywinauto | **Нативный** Windows GUI; веб-приложения остаются за Playwright |
| `contract-first` | Согласование consumer/provider по единому OpenAPI/AsyncAPI/Proto/JSON Schema | Параллельные изменения frontend/backend и межсервисные границы; не подменяет `api-design` и `contract-testing` |
| `api-connector-builder` | Подключение API-провайдера в существующую структуру adapters/registries и тесты | Новые интеграции, когда нужно соблюдать соглашения исходного репозитория |
| `code-tour` | Структурированные CodeTour `.tour` с реальными файлами и строками | Onboarding, обзор PR, архитектурный разбор/RCA; не подменяет `codebase-knowledge-map` |

## Как использовать встроенный Toolkit

Пример: после установки обычного Toolkit выберите один необходимый профиль в **существующем** установщике Toolkit (без ECC):

```sh
python scripts/install.py --target /path/to/project --profile native-code-tours
python scripts/install.py --target /path/to/project --profile native-code-tours --apply
```

Другие профили: `native-windows-desktop`, `native-contract-first`, `native-api-connectors`. Первая команда — сухой просмотр, вторая — явная локальная установка выбранного навыка из дистрибутива **Toolkit**. Другие навыки, `AGENTS.md`, клиентские MCP, hooks и модели не перезаписываются. Устанавливать дополнительные ECC CLI, сервисы или платные модели **нельзя и не нужно**.

Содержание этих навыков — инструкции, а не разрешение запускать `pip install`, shell, читать секреты или действовать в чужом репозитории. Оригинальные примеры могут использовать инструменты, разрешение на которые определяется политиками владельца. Наличие исходников и CI-проверок в Toolkit **не доказывает**, что локальный Codex Desktop автоматически активировал навык; реальный activation E2E отдельно.

**Границы:** предыдущий upstream `install-plan.js --skills windows-desktop-e2e` подтягивал четыре модуля и сторонние конфиги. Новый путь использует только собственный существующий установщик Toolkit и копирует **один** выбранный `SKILL.md`, без импорта ECC config/Memory Vault/хуков. Откат — удалить только установленный собственным решением каталог соответствующего навыка и не затрагивать пользовательские изменения. Сравнительный каталог остальных 597 компонентов — [#435](https://github.com/MikeMoore1337/ai-development-toolkit/issues/435); по мере подтверждённой полезности переносить следующие в те же native структуры, не подменяя работающие компоненты.

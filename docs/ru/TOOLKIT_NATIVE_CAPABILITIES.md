# Встроенные возможности Toolkit на основе исходников ECC (#435, #446)

**Toolkit — самостоятельный продукт.** Эти тринадцать навыков уже находятся в дистрибутиве Toolkit; пользователю не требуется устанавливать ECC, `ecc-universal`, исходный ECC CLI, MCP, plugin, hooks или отдельные сервисы. Двенадцать оригинальных файлов `SKILL.md` и полный исходный справочник Windows UIA зафиксированы на коммите [ECC 2.2.3 `25278e7...`](https://github.com/affaan-m/ECC/tree/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b) и включены без изменений. Для Windows используется компактная обёртка и полный неизменённый справочник. Авторское право Affaan Mustafa и полная лицензия MIT сохранены в `third_party/ecc-v2.2.3/LICENSE`. Дополнительных API, фонов и CLI-моделей нет.

| Встроенный навык | Что добавляет к Toolkit | Когда нужен |
| --- | --- | --- |
| `contract-first` | Согласование consumer/provider по единому OpenAPI/AsyncAPI/Proto/JSON Schema | Параллельные изменения frontend/backend и межсервисные границы; не подменяет `api-design` и `contract-testing` |
| `api-connector-builder` | Подключение API-провайдера в существующую структуру adapters/registries и тесты | Новые интеграции, когда нужно соблюдать соглашения исходного репозитория |
| `code-tour` | Структурированные CodeTour `.tour` с реальными файлами и строками | Onboarding, обзор PR, архитектурный разбор/RCA; не подменяет `codebase-knowledge-map` |
| `windows-desktop-e2e` | Нативные Windows UIA E2E-тесты через pywinauto | Только согласованные задачи WPF/WinForms/Win32/Qt; не для браузера и Electron HTML |
| `module-regression` | Проверяемые команды приёмки зависимых модулей, подтверждённые связи и коды завершения | Изменения взаимосвязанных модулей, не простые изолированные задачи |
| `error-handling` | Оригинальные примеры типизированных ошибок, повторных запросов и обработки ошибок для TypeScript, Python и Go | Разработка и проверка ошибок API и сервисов |
| `mcp-dependency-review` | Статическая проверка изменяемых версий npm/Python/Docker в MCP-конфигурации без запуска серверов | Перед согласованием изменений в MCP-конфигурации проекта |
| `agent-introspection-debugging` | Диагностика сбоев AI-агентов с фиксацией действий и доказательств | Ошибки инструментов и циклические попытки |
| `content-hash-cache-pattern` | Кэширование обработки файлов по SHA-256 содержимого | Повторная дорогая обработка файлов |
| `loop-design-check` | Проверка проверяемых целей и остановки агентных циклов | Проектирование автоматизированных циклов |
| `make-interfaces-feel-better` | Точечная проработка UI без подмены UX/UI Orchestra | Явный запрос на визуальную полировку |
| `article-writing` | Подготовка содержательных статей и руководств без публикации | Редакционные SEO-материалы |
| `click-path-audit` | Трассировка последовательных изменений состояния кнопок и форм | Сбойные действия и гонки в UI |

## Как использовать встроенный Toolkit

Пример: после установки обычного Toolkit выберите один необходимый профиль в **существующем** установщике Toolkit (без ECC):

```sh
python scripts/install.py --target /path/to/project --profile native-code-tours
python scripts/install.py --target /path/to/project --profile native-code-tours --apply
```

Другие профили: `native-contract-first`, `native-api-connectors`, `native-windows-desktop-e2e`, `native-module-regression`, `native-error-handling`, `native-mcp-dependency-review`, `native-agent-introspection-debugging`, `native-content-hash-cache-pattern`, `native-loop-design-check`, `native-make-interfaces-feel-better`, `native-article-writing`, `native-click-path-audit`. Первая команда — сухой просмотр, вторая — явная локальная установка выбранного навыка из дистрибутива **Toolkit**. Другие навыки, `AGENTS.md`, клиентские MCP, hooks и модели не перезаписываются. Устанавливать дополнительные ECC CLI, сервисы или платные модели **нельзя и не нужно**.

Содержание этих навыков — инструкции, а не разрешение запускать `pip install`, shell, читать секреты или действовать в чужом репозитории. Оригинальные примеры могут использовать инструменты, разрешение на которые определяется политиками владельца. Наличие исходников и CI-проверок в Toolkit **не доказывает**, что локальный Codex Desktop автоматически активировал навык; реальный activation E2E отдельно.

**Обработка ошибок (#435):** `native-error-handling` включает неизменённый оригинальный `SKILL.md` и MIT-лицензию без ECC runtime. Это исходные методики и примеры, а не разрешение самостоятельно менять контракт приложения, выполнять команды или вызывать внешние API. Реальная клиентская активация NOT_VERIFIED.

**Проверка зависимостей MCP (#435):** `native-mcp-dependency-review` содержит неизменённые оригинальные инструкции MIT и лицензию. Это не исполняемый сканер: установка не запускает серверы MCP, не скачивает пакеты и не обращается к реестрам. Проверки исходников и безопасной установки не доказывают реальный анализ клиентом (NOT_VERIFIED).

**Межмодульные регрессии (#435):** `native-module-regression` содержит оригинальный закреплённый навык, шаблон и MIT-лицензию. Реестр не даёт права исполнять команды без разрешения владельца; CI по исходникам не подтверждает активацию клиента (NOT_VERIFIED).

**Windows UIA (#450):** полный оригинал из 889 строк без изменений хранится в `optional-original-skills/windows-desktop-e2e/references/ORIGINAL_SKILL.md`. Компактный `SKILL.md` даёт безопасный маршрут. Установка не запускает pywinauto, Windows UIA или приложение. Реальный запуск требует отдельного разрешения владельца; он пока NOT_VERIFIED.

**Границы:** предыдущий upstream `install-plan.js --skills windows-desktop-e2e` подтягивал четыре модуля и сторонние конфиги. Новый путь использует только собственный существующий установщик Toolkit и копирует **один** выбранный каталог навыка, включая его MIT-лицензию и справочник, без импорта ECC config/Memory Vault/хуков. Откат — удалить только установленный собственным решением каталог соответствующего навыка и не затрагивать пользовательские изменения. Сравнительный каталог остальных 588 компонентов — [#435](https://github.com/MikeMoore1337/ai-development-toolkit/issues/435); по мере подтверждённой полезности переносить следующие в те же native структуры, не подменяя работающие компоненты.

# Нативная проверка конфигурации AI-клиентов Toolkit (#432)

В существующий `external_skill_gate.py` добавлен **добровольный статический анализ конфигураций клиентов**, без второго управляющего механизма. Toolkit не требует устанавливать ECC, AgentShield, их CLI/MCP/плагины, запускать агента, модель, сетевые запросы или фоновые службы.

## Запуск

Выберите **разрешённый проект или тестовый каталог**, а не домашнюю папку пользователя:

```sh
python scripts/external_skill_gate.py --host-config-root /path/to/approved/project
python scripts/external_skill_gate.py --host-config-root /path/to/approved/project --format sarif
python -m unittest tests.test_external_skill_gate -v
```

Коды: `0 PASS` - найденные конфигурации прошли лишь **поддерживаемые статические проверки**, `1 REVIEW_REQUIRED` - недостаточно данных либо замечания средней серьёзности, `2 BLOCKED` - опасная конфигурация или некорректные данные. JSON либо SARIF 2.1.0 выводится на экран. В JSON `evidence.files` включены относительные пути разрешённых файлов, размер и SHA-256, **без содержимого и секретов**. Файлы отчётов автоматически не создаются.

## Проверяемые конфигурации

| Путь | Проверки |
| --- | --- |
| `.codex/config.toml` | Неограниченный sandbox, `approval_policy=never`, параметры MCP |
| `.codex/hooks.json` | Команды hooks: сетевые отправки, передача в shell, небезопасная подстановка, разрушительные команды |
| `.claude/settings.json`, `.claude/settings.local.json` | Те же hooks, широкие разрешения `Bash(*)`, `Write(*)`, `Edit(*)` и доступ к интерпретатору shell |
| `.mcp.json` | Секреты в переменных окружения, доступ ко всему диску, `npx/bunx -y` |

Повреждённый JSON/TOML, дублирующиеся ключи JSON, непредусмотренные типы, слишком большие файлы, символические ссылки и ошибки чтения отклоняются. Если ни один поддерживаемый файл не найден, сканирование **не возвращает PASS**, а требует проверки. Сканируются только точно перечисленные файлы; это не полный анализ всех настроек.

**Ограничения:** анализ не выполняет команд, не читает остальные файлы, не использует модель и не делает сетевые запросы. Максимум 128 КиБ на файл, 512 КиБ суммарно. Выявленные риски являются статическими признаками, а не доказательством атаки. `PASS` не выдаёт права на выполнение и не доказывает, что Codex Desktop применяет заявленные политики: реальное выполнение hook и запрещённой операции отдельно не проверялось.

## Совместимость и происхождение

Механизм дополняет существующие проверки навыков `external_skill_gate.py`, Cisco MCP Scanner (#359) и SkillSpector (#200), не дублируя их. Для сравнения использованы [исходники AgentShield `b0891303bdcd6037376a94263d45cfd2ff3dfb98`](https://github.com/affaan-m/agentshield/tree/b0891303bdcd6037376a94263d45cfd2ff3dfb98), лицензия MIT. Весь добавленный Python-код написан в Toolkit, без копирования TypeScript, пакетов или бинарного AgentShield.

Откат - обычный возврат этой редакции исходников Git. Установка, регистрация hooks и изменение пользовательских разрешений не производятся. Физическая приёмка Windows Codex Desktop, полнота правил AgentShield и реальная блокировка операций **NOT_VERIFIED**. Поэтому #432 остаётся открытой до завершения остальных критериев.

## Дополнительные проверки и матрица покрытия (#432)

Существующий добровольный анализ конфигураций теперь распознаёт
PowerShell `Invoke-RestMethod`/`irm` с HTTP(S)-адресом. В параметрах
запуска MCP выявляются адреса известных сервисов-приёмников и доступ
к чувствительным системным каталогам. Последние два сигнала имеют
**MEDIUM / REVIEW_REQUIRED**, поскольку могут встречаться и в
легитимных настройках. Сканер ничего не исполняет и не отправляет в сеть;
аргументы и их значения в отчёте не публикуются.

| Область | Существующий нативный/необязательный анализ | Ограничение |
| --- | --- | --- |
| Инструкции агентов | Структура/ссылки `audit_agent_instructions.py`, текст внешних Skill | Нет полного семантического обнаружения подмены ролей |
| Описания MCP | `cisco_mcp_gate.py --native`, вложенные схемы, необязательные Cisco YARA/schema | Не проверяются работающий сервер, prompts/resources и обфускация |
| Hooks | Явные строки команд Codex/Claude в разрешённом каталоге | Нет выполнения и фактического перехвата команд |
| Разрешения | Явные настройки sandbox/approval, доступ Bash/Write/Edit и интерпретаторов | Эффективные разрешения и ограничения клиента не подтверждены |
| Секреты | Сигналы встроенных ключей в MCP env, отчёт без значений | Нет полного поиска ключей или проверки реальной утечки |
| Внешние навыки | Существующие Skill gate, SHA-256, опциональный SkillSpector | Нет доказательства безопасного происхождения и поведения |
| Целостность | Ограниченные пути, JSON/TOML, дубликаты, ссылки, корневые junction, SHA-256 | Изменения после проверки и другие пути за пределами анализа |

`host_report_sarif` использует SARIF 2.1.0, стабильные идентификаторы
правил, уровни серьёзности и только относительные разрешённые пути.
Свидетельство JSON содержит SHA-256 и размеры исходных файлов, не их
содержимое; хэш не доказывает полномочий издателя и не защищает от
изменений после проверки. Отдельный набор из 38 синтетических
конфигураций описан в [проверке MCP](MCP_SECURITY_SCAN.md).
Первоисточник сравнения - [AgentShield MIT, закреплённая редакция](https://github.com/affaan-m/agentshield/tree/b0891303bdcd6037376a94263d45cfd2ff3dfb98).
Toolkit не устанавливает и не требует оригинальный runtime.
Откат - обычный возврат изменений Toolkit через Git; настройки клиентов
этот режим не меняет. `UPSTREAM_COMPARISON=NOT_RUN`,
`CLIENT_RUNTIME=NOT_VERIFIED`, `REPRESENTATIVE_ACCURACY=NOT_MEASURED`.
До фактической клиентской приёмки задача #432 остаётся открытой.

## Состав «как есть» и пересечения

| Поверхность ECC | Проверенный факт | Пересечение/решение |
|---|---|---|
| Skills | `./skills/` - внешний каталог ECC; в описании плагина заявлено 281 навык | Toolkit уже содержит `task-scoping`, `implementation`, `qa-strategy`, `code-review`, `security-boundaries`, `feature-delivery`. Не переносить навыки и не заменять их глобально; применять явно выбранный ECC skill |
| MCP | `.mcp.json` задаёт `chrome-devtools` с командой `npx -y chrome-devtools-mcp@1.10.1` | Потенциальный запуск внешнего пакета и доступ к браузеру. **Не авторизовать запуск по умолчанию**; проверить разрешения, целевой браузер, сеть, данные и политику затрат |
| Hook | `SessionStart` вызывает `node -e ...`, затем `scripts/hooks/plugin-hook-bootstrap.js` и `session-start-bootstrap.js` | Это исполняемый код. Требуются отдельный просмотр и доверие через штатный UI хуков; не включать автоматически |

## Как подключить в графическом интерфейсе (без Codex CLI)

1. В **Codex внутри ChatGPT desktop app**, если соответствующая версия и интерфейс доступны, открыть каталог **Plugins**, выбрать **Add plugin marketplace** и источник `affaan-m/ECC`. Если интерфейс позволяет указать Git ref, выбрать проверенный commit выше. **Если нет способа закрепить ревизию, не утверждать, что она закреплена**: проверить показанный исходник перед установкой.
2. Выбрать оригинальный `ecc` из подключённого источника, сверить имя/версию/содержимое и запросы разрешений. Не соглашаться автоматически на запуск `npx`, доступ к браузеру или выполнение хуков.
3. После проверки полномочий установить плагин средствами интерфейса. Открыть новую сессию Codex. В разрешённом проекте на синтетической задаче проверить, что появился *оригинальный* ECC skill; отдельно подтвердить его действительное выполнение, а не только регистрацию.
4. Для hook `SessionStart` использовать предусмотренную клиентом отдельную проверку и доверие **только после просмотра кода**. Для Chrome DevTools MCP проверить возможность отключения/неактивации до пробного запуска, не передавать cookies или авторизованные production-сессии.
5. При отсутствии поддерживаемого графического пути, возможности проверки разрешений или запрете внешних команд оставить **BLOCKED/NOT_VERIFIED**. Для владельца Toolkit **не переходить на Codex CLI, Claude CLI, API или платный маршрут**. Другие пользователи самостоятельно выбирают поддерживаемые клиентом и разрешённые им пути.

**Точная версия Codex Desktop, фактическая регистрация ECC, успешный вызов навыка, отсутствие сетевых побочных эффектов и разрешения хуков этим документом не проверялись.** Доступная документация по механизму GUI: [OpenAI Plugins](https://developers.openai.com/plugins/build/plugins).

## Проверка, отключение, откат

- **Предварительная проверка:** действующие `AGENTS.md`, `MANIFEST.json`, `docs/EXTERNAL_METHODS_ADOPTION.md`, разрешения, текущая конфигурация моделей, запущенные MCP и список уже установленных плагинов. Совпадение имени навыка не означает одинаковый контракт.
- **Приёмка в Codex Desktop:** записать версию клиента, точную ревизию ECC (если доступна), наличие `ecc`, один запуск оригинального навыка на синтетике, явные разрешения MCP/hook и наблюдаемые результаты; отсутствие доступа отмечать `NOT_VERIFIED`, отказ в разрешениях - `BLOCKED`.
- **Отмена:** отключить `ecc` через UI Plugins; если нужно, удалить его и источник marketplace. В новой сессии удостовериться, что навыки ECC недоступны и Toolkit работает по прежним правилам. Не удалять чужой `CODEX_HOME`, системные плагины или данные других проектов.
- **Обновление:** сравнить upstream commit, manifest, `.mcp.json`, hooks и зависимости; при изменении hook trust повторить проверку. Установка новой версии не является автоматической.
- **Граница прав:** пользовательское согласие на регистрацию плагина не разрешает shell, чтение секретов, сетевой доступ, публикацию, деплой или расходы. Лимиты подписки, нулевые дополнительные платежи и отсутствие побочных эффектов должны подтверждаться отдельно.

## Критерии завершения #424

1. Документация и ссылки в публичном Toolkit могут пройти стандартный PR/CI **без исполнения ECC**.
2. Отдельная финальная приёмка требует **реального Codex Desktop Windows**, просмотра разрешений и успешного вызова исходного навыка в безопасной сессии. GitHub PR/CI и статический разбор upstream этого не заменяют.
3. Пока пункт 2 не выполнен, Issue остаётся открытой; статус установки `NOT_VERIFIED`, а не `DONE`.

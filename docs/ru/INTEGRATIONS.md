# Интеграции AI Development Toolkit - возможности и среды применения

AI Development Toolkit предоставляет **две равноправные интеграции** с общей библиотекой навыков, ролей и процессов: [плагин ChatGPT](../../integrations/chatgpt-plugin/README.ru.md) и [локальный MCP для Codex](../../integrations/personal-mcp/README.ru.md). **Способ подключения зависит от среды работы и доступности проекта**, а не от приоритета одних пользователей над другими. Платный API не требуется.

## Возможности Toolkit

- **Подбор навыков и ролей под задачу.** Обе интеграции выбирают узкий набор подходящих инструкций, а не весь каталог. Рекомендация навыка не доказывает его фактическое применение.
- **Подключение недостающих инструкций по необходимости.** Плагин ChatGPT использует встроенные материалы или доступную проверенную ревизию GitHub. Codex запрашивает инструкции через `toolkit_prepare_task`, передавая сведения об уже доступных навыках. Роль - это инструкции, **не** автоматически запущенный субагент.
- **Работа без копирования файлов в проект.** Обе интеграции могут предоставлять инструкции без изменения рабочего репозитория. Установка нативных навыков через Skill Manager - отдельное действие по явному разрешению.
- **Актуальные источники.** Плагин при наличии доступа может читать инструкции из согласованной проверенной ревизии GitHub во время задачи; иначе сообщает об использовании встроенного набора. Локальный MCP читает собственную копию Toolkit, которую можно обновлять по расписанию. **Код установленного плагина и MCP обновляется отдельно.**
- **Соблюдение границ доступа.** Проект доступен лишь через полномочия соответствующего клиента. Инструкции Toolkit сами по себе не дают доступа к файлам, репозиториям и терминалу.

## Выбор интеграции по рабочей среде

| Возможность | ChatGPT-плагин | Локальный MCP для Codex |
| --- | --- | --- |
| Где используется | В ChatGPT, когда доступны пользовательские плагины | На компьютере с Codex CLI и Python |
| Windows | Интерфейс ChatGPT | PowerShell; планировщик Windows |
| Linux | Интерфейс ChatGPT | Shell; пользовательский systemd |
| macOS | Интерфейс ChatGPT | Shell; launchd |
| Мобильные устройства | Если клиент ChatGPT поддерживает плагин | Локальная установка Codex не предусмотрена |
| Доступ к рабочему проекту | Переданные файлы, разрешённые подключения и источники | Рабочая область, доступная Codex, **не** MCP напрямую |
| Подбор навыков | Маршрутизатор плагина | `toolkit_route_task` / `toolkit_prepare_task` |
| Обновление инструкций | Чтение GitHub при подтверждённой доступности; иначе встроенный набор | Обновление локальной копии по расписанию, если включено |
| Обновление самой интеграции | Отдельный выпуск плагина | Отдельный выпуск MCP |
| Установка навыков и изменение файлов проекта без разрешения | Нет | Нет |
| Необходимость платного API | Нет | Нет |

## Ленивое чтение навыков и проверяемый размер ответа (#276)

По умолчанию `toolkit_prepare_task` возвращает тексты не более **трёх** приоритетных `SKILL.md` (ранее — пяти). Для сложной задачи можно явно указать `max_skills=4..8`. Полный выбор навыков в `selected_skills` не сокращается; отложенные перечислены в `remaining_skills_to_consult` и по необходимости читаются через `toolkit_get_skill`. Дополнительные файлы `references` читаются только по явному `toolkit_get_reference`. Работа ChatGPT-плагина и установленных навыков клиента не изменяется.

`context_load_metrics` показывает реальный объём UTF-8 текста, **возвращённого** MCP: байты инструкций навыков, ролей, сумму и количество отложенных навыков. Для подсчёта не читаются дополнительные файлы. Размер не включает JSON-RPC оболочку и повторяющиеся текстовую/структурированную сериализации; это **не** число сетевых байтов. `model_tokens=NOT_MEASURED`, `client_usefulness=NOT_TESTED`: меньше байтов не равняется доказанному сокращению токенов или улучшению качества ответа модели.

Исходная воспроизводимая оценка для SHA Toolkit `053a200f4215162340ab5d1d4ff7ac9c13c8db5e`: размеры `SKILL.md` первых пяти и трёх навыков **в порядке манифеста**, не фактической маршрутизации:

| Профиль | Первые 5, байт | Первые 3, байт | Не передаются сразу |
| --- | ---: | ---: | ---: |
| backend | 5 502 | 2 727 | 2 775 |
| fullstack | 6 994 | 4 441 | 2 553 |
| general | 5 664 | 3 477 | 2 187 |

Маршрутизатор может менять порядок приоритетов. Для конкретного запроса сравните `context_load_metrics` вызовов `toolkit_prepare_task` по умолчанию и с `max_skills=5`. Полный размер профиля на диске включает дополнительные файлы и **не** является объёмом переданного контекста.

## Установка и использование

**ChatGPT:** [Инструкция RU](../../integrations/chatgpt-plugin/README.ru.md) · [English](../../integrations/chatgpt-plugin/README.md)

**Codex MCP (Windows, Linux, macOS):** [Инструкция RU](../../integrations/personal-mcp/README.ru.md) · [English](../../integrations/personal-mcp/README.md)

**Другие чат-клиенты:** ZIP ChatGPT не является универсальным форматом для Claude, DeepSeek и Qwen. При отсутствии совместимого плагина используйте [AGENT_START.ru.md](../../AGENT_START.ru.md), ссылку на Toolkit и разрешённые файлы проекта. Не заявляйте об установке и применении навыка без фактического подтверждения.

**Границы доступа:** плагин навыков ChatGPT не получает автоматический доступ к локальному MCP на ноутбуке. Не публикуйте личные идентификаторы плагинов, токены или корпоративные файлы. Размещение исходников в GitHub само по себе не устанавливает интеграции пользователям.

## Пять воспроизводимых офлайн-сценариев и границы проверок (#280)

Для запуска достаточно проверенной локальной копии Toolkit и Python 3.12+. **Команды ниже — инструкции для самостоятельной проверки, не доказательство их выполнения на устройстве читателя.** В Windows при необходимости используйте `py -3` вместо `python`. Платные AI API, Codex CLI и доступ к чужим проектам не нужны.

1. **Посмотреть профили без установки.** Команда: `python scripts/adt.py --json profile list`. Источники: `MANIFEST.json`, `scripts/adt.py`. Ожидается список профилей без изменений рабочего проекта. Фактический запуск читателем: `NOT_RUN`; активация навыков: `NOT_VERIFIED`.
2. **Проверить зафиксированные тесты маршрутизации.** Команда: `python scripts/skill_routing_eval.py --strict`. Источники: `SKILL.md`, `fixtures/skill_routing_cases.json`, реестр алиасов. Нулевой код выхода означает выполнение проверок лексического выбора, **не** реальную точность AI. Локальный запуск: `NOT_RUN`.
3. **Увидеть ограничения RU/EN-маршрутизации.** Команда: `python scripts/skill_routing_eval.py --holdout fixtures/skill_routing_untuned_20261024.json`. Источники: 16 RU/EN запросов с метками, составленными AI. В проверке CI #40065197315 получилось 8/16 совпадений, RU 2/8 против EN 6/8 и 0 запрещённых первых вариантов. Метки **не проходили независимую приёмку**, а другой checkout может дать иные числа. Локальный запуск: `NOT_RUN`; эффективность: `NOT_MEASURED`.
4. **Проверить заявленное происхождение файлов.** Команда: `python scripts/validate_provenance.py --mode inventory`. Источники: `provenance/skills.json`, `MANIFEST.json` и объявленные пути. PASS показывает структурную согласованность, но **не** юридическую проверку прав или разрешение выпуска. Локальный запуск: `NOT_RUN`.
5. **Проверить закреплённые Actions и контрольные суммы.** Команды: `python scripts/validate_action_pins.py`, `python scripts/verify_checksums.py`. Источники: пять файлов `.github/workflows/*.yml`, разрешённые SHA Actions, `SHA256SUMS.txt`. PASS подтверждает соответствие записанным ссылкам и байтам, **не** безопасность исходного кода Actions и не цифровую подпись пакета. Локальный запуск: `NOT_RUN`.

**Зависимости.** CI ставит только готовый бинарный пакет `PyYAML==6.0.3` для поддерживаемых runner Python 3.12/3.13/3.14. Версия фиксирована, но SHA256 **каждого wheel не закреплён**: полная герметичность и проверка происхождения пакета не заявляются. SHA действий сверены по официальным репозиториям `actions/*` 24.10.2026; дальнейшие проверки выполняются офлайн. `SHA256SUMS.txt` проверяет байты, а не правообладателя.

# Квитанция маршрутизации ChatGPT - Issue #533

Это одноразовая **opt-in проверка** в рамках существующих Toolkit Task Router, UX/UI Design Orchestra и Evidence Curator. Она не является вторым контроллером, службой телеметрии или способом получить историю чужого разговора. В публичном репозитории находятся **только синтетические** тестовые данные.

## Что проверяется

1. Чтение личного `USER_PREFERENCES.json` с `skills.design_originals=ALL_THREE` именно через результат вызова инструмента, а не через сохранённое backend-поле.
2. Загрузка `ux-ui-design-orchestra/SKILL.md`, `WORKFLOW.md`, `CREATE_DESIGN.md` и выбор `create-design` **до** нативных оригиналов.
3. Отдельный исходный `upstream_sha`, `entrypoint`, команда, среда, код завершения, стадия и SHA256 артефакта у Impeccable, Taste Skill и UI UX Pro Max. `--help`, `context`, установка и показ инструкций не являются выполнением основного метода.
4. После оригиналов - явное решение владельца по конкретному артефакту, `finish-reviewer` с `ship` (или документированный `INLINE_DEGRADED`) и независимая проверка браузером.
5. Раздельные `toolkit SHA`, `plugin_backend_version`, `active_mount_version`. Неизвестная фактически активная версия остаётся `NOT_VERIFIED`. Самостоятельно указанный в JSON номер версии в LIVE-квитанции блокируется, пока нет аутентифицированных host-метаданных активного пакета.

Если отдельный внутренний этап оригинала документированно неприменим, `NATIVE_SUBSTAGE_NOT_APPLICABLE` допускает другой **действительно исполненный** этап с кодом завершения и проверенным SHA256. Если неприменима вся область оригинала, `NOT_APPLICABLE_NATIVE_SCOPE` всегда оставляет all-three gate незавершённым. Пропуск не подменяет вызов оригинала.

Файл в `fixtures/chatgpt_route_receipt_synthetic.json` показывает **только структуру**. Его команды, SHA и времена вымышлены; исполнения оригиналов не было. Проверка времён выявляет нарушение записанного порядка, задержку записи более пяти минут после наблюдения и очевидное «заднее число», но без заверенного временем host export не защищает от намеренного переписывания всей цепочки.

## Одноразовое использование

Не запускать для чужих чатов, не собирать переписку, не включать скрытые hooks. В выбранном владельцем обычном чате запросить отдельную проверку у Evidence Curator. Приложить только разрешённые **результаты реальных tool calls**, сохраняя ссылки/идентификаторы по мере поступления. Наличие `SKILL.md`, слова «OBSERVED» в тексте и ручные поля JSON сами по себе не подтверждают активацию ChatGPT. Если host не отдаёт заверенную первичную трассу первого сообщения, итог **`BLOCKED_HOST_TRACE_API`** независимо от валидности квитанции.

Генерация пустого приватного шаблона без записи на диск:

```sh
python scripts/verify_chatgpt_route_receipt.py --new
```

Проверка синтетического примера (из корня репозитория):

```sh
python scripts/verify_chatgpt_route_receipt.py --receipt fixtures/chatgpt_route_receipt_synthetic.json --artifact-root .
python scripts/verify_chatgpt_route_receipt.py --receipt fixtures/chatgpt_route_receipt_synthetic.json --artifact-root . --markdown
python -m unittest discover -s tests -p test_chatgpt_route_receipt.py -v
```

`evidence_sequence=PASS` значит лишь, что **заявления** структурно согласованы и локальные артефакты соответствуют указанным SHA256. `client_attestation=SYNTHETIC_ONLY` либо `BLOCKED_HOST_TRACE_API` предотвращает ложную реальную приёмку. Неизвестные ключи, секреты, email, личные абсолютные пути, выход за каталог артефактов и ссылки на символические файлы блокируются. Сырые запросы и транскрипты не нужны.

## Новый слепой запрос и предел host API

Для реального эксперимента нужен **новый независимый обычный чат**, потому что здесь задача прямо перечисляет оригиналы и `ALL_THREE` и уже не является слепой. В нём можно запросить: «Спроектируй новый адаптивный экран планирования небольшой прогулки и подготовь визуальные варианты для моего согласования. До согласования не изменяй приложение». Не упоминать названия оригиналов/оркестратора в исходном запросе. Затем **отдельно** запросить независимую проверку известных вызовов. Только предоставленный владельцем доступный host export/trace может повысить аттестацию. Создание нового разговора текущими средствами не автоматизируется.

## Безопасность, хранение и удаление

Повторные ключи JSON отклоняются до разбора содержимого. В Windows запрещены относительные пути с буквой диска (например, `C:secret`), переходы из корня артефактов и NTFS junction. Синтетический файл хэша закреплён в `.gitattributes` как `-text`, чтобы Git не подменял байты при checkout и SHA256 оставался проверяемым.

Один запуск читает ровно явно указанный JSON и относительные артефакты до 2 МиБ; сеть, платные API, постоянная база, cron, watcher и автоматическая отправка отсутствуют. По умолчанию CLI выводит **только обезличенный итог**, а `--new` выводит шаблон в stdout. Для сохранённого вручную приватного файла удалите его и только относящиеся к проверке копии после приёмки; инструмент сам файлы не создаёт и не удаляет. Никогда не публикуйте приватные tool results или пользовательские файлы в публичном GitHub Issue. Публикация санитизированной квитанции - отдельное решение владельца.

**Лицензии/оригиналы:** не модифицируются; хэши и записи в тестовом корпусе не являются upstream provenance. Текущая проверка не подменяет инициативу Native Observability #434 и диагностику версий #274.

# Нативная проверка GateGuard до выполнения операций (#438)

Toolkit содержит **только безопасную проверку входного события без исполнения**, размещённую рядом с существующими хуками персонального MCP:
`integrations/personal-mcp/adt-personal/hooks/pretool_gate_review.py`. Это **не зарегистрированный хук Codex Desktop или Claude** и не второй контроллер прав. Для предметного сравнения использован `affaan-m/ECC@25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b`: `scripts/hooks/gateguard-fact-force.js`, `skills/gateguard/SKILL.md`, `hooks/hooks.json`, `hooks/codex-hooks.json`. Оригинал требует дополнительных модулей, состояния сессий и отдельной установки хуков; ничего из этого не включено и не запускается.

## Влияние на права и окружение

Исходный GateGuard для Claude обрабатывает `PreToolUse`, может читать транскрипты и файлы проекта, сохраняет состояние сессий и иногда метрики, требует подтверждения фактов перед первой записью и опасной командой. Схема Codex upstream в первую очередь запускает `SessionStart` через Node и **не подтверждает блокировку операции до выполнения в Codex Desktop Windows**.

Нативный скрипт Toolkit проверяет **одно переданное вручную синтетическое событие** и возвращает JSON-рекомендацию. Читает только stdin (до 16 КиБ), не открывает проект и транскрипты, не запускает команды, не записывает файлы, не обращается в сеть, не вызывает модели, не устанавливает хуки и не изменяет `AGENTS.md`. Для небольшого списка точных команд только чтения (`git status`, `git diff --check`, `Get-Location`) возвращает `ALLOW_CANDIDATE`. Опасные шаблоны получают `BLOCK_RECOMMENDED`, запись и неизвестные команды - `REVIEW_REQUIRED`. **Это не полноценный парсер shell и не механизм принудительной защиты ОС.** Событие не может само выдать себе права.

Всегда указываются `host_enforcement=NOT_VERIFIED`, `blocking_effect=NONE_SOURCE_ONLY`, `hook_registered=false`, `tool_executed=false`, `state_written=false`. Некорректный ввод отклоняется. Формат синтетического события:

```json
{"schema_version":1,"tool_name":"Bash","tool_input":{"command":"git status --short"}}
```

Его можно передать через stdin:

```sh
python integrations/personal-mcp/adt-personal/hooks/pretool_gate_review.py
```

Сам скрипт ничего не исполняет и не вызывается AI-клиентом автоматически. Настоящая активация в Codex Desktop **NOT_VERIFIED**: потребуются документированный и реально работающий callback до выполнения, разрешение владельца, отсутствие двойных хуков и наблюдаемый отказ при синтетической опасной операции.

## Проверка, ограничения и откат

Тесты покрывают безопасное чтение, PowerShell Windows, опасные Git/shell/SQL, неизвестные и составные команды, неверную схему, повторный вызов без побочных эффектов и отсутствие вывода секретов. Нет платных API, Codex CLI, Claude CLI, внешнего ECC runtime или телеметрии. Откат - удалить необязательный код, тесты и документацию через обычный PR; настройки клиента не меняются. Версионированный релиз и реальная Windows-приёмка проходят отдельно.

## Укрепление статического классификатора (#438, 01.11.2026)

Проверка по-прежнему остаётся **только рекомендацией**. Изменения не включают хуки, исполнение событий или выдачу прав. Повторяющиеся ключи JSON, `NaN`/`Infinity`, некорректная кодировка, неподдерживаемые управляющие символы, чрезмерно глубокие структуры и превышение размера входа отклоняются. `RecursionError` возвращает ограниченный JSON с `BLOCK_RECOMMENDED` без трассировки и исходной команды.

Распознавание опасных *непосредственно видимых* команд расширено на `git -C ... reset --hard`, `git clean --force`, `git push -f`, `git worktree remove`, PowerShell `ri`, `Remove-Item` и командные цепочки. Инертные литералы вроде `echo "rm -rf file"` больше не классифицируются как установленный факт удаления. Незнакомые команды, оболочки, экранирование и вложенные интерпретаторы переводятся в `REVIEW_REQUIRED`, а не разрешаются.

**Матрица переноса ECC -> Toolkit -> пробел -> решение -> проверка:**

| ECC | Состояние Toolkit | Подтверждённый пробел | Решение | Тест |
| --- | --- | --- | --- | --- |
| Claude `PreToolUse` и отказ до записи | Только ручной анализ события | Нет доверенного Codex Desktop callback | Не устанавливать хуки; `host_enforcement=NOT_VERIFIED` | Контракт результата, отдельный клиентский E2E не выполнялся |
| Защита Git/shell/PowerShell | Ограниченный классификатор | Недообнаружение известных вариантов и ложные срабатывания на тексте | Уточнение распознавания видимых операций, неизвестное - на проверку | `test_pretool_gate_hardening.py` |
| Состояние сессии, журнал, поиск доказательств | Отсутствуют намеренно | Для read-only режима не нужны | Не переносить, не собирать транскрипты | Проверка идемпотентности и отсутствия побочных эффектов |
| Ввод событий, доверие и права | Ограниченный JSON | Дубликаты ключей и глубина JSON | Отклонение неоднозначного ввода, обработка `RecursionError` | Негативные CLI-тесты |
| Оригинальные Node bootstrap и SessionStart | Не интегрированы | В ECC Codex manifest нет проверенного PreToolUse GateGuard | Не копировать и не регистрировать | Сравнение закреплённых источников |

**Происхождение.** Изучены `affaan-m/ECC@25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b` (лицензия MIT, Affaan Mustafa) и отдельно `zunoworks/gateguard` (MIT, Hirokazu Seto / ZUNO WORKS K.K.). Исходные скрипты и сторонние зависимости **не скопированы**. Лицензия корня ECC не служит автоматическим доказательством прав на отдельный сторонний файл.

Для ручной проверки передайте одно синтетическое JSON-событие на stdin скрипта выше. `ALLOW_CANDIDATE` - не разрешение на запуск; `BLOCK_RECOMMENDED` - не принудительный отказ хоста. Регулярные выражения и списки точных команд не являются полноценным парсером оболочки или защитой от синтаксических обходов. Разрешения пользователя, проекта, клиента и sandbox сохраняют приоритет. Для отключения достаточно не вызывать необязательный анализатор; откат исходников - обычный PR, поскольку конфигурации клиента не менялись.

**Непроверенные границы:** `HOST_ENFORCEMENT=NOT_VERIFIED`, `CODEX_DESKTOP_E2E=NOT_RUN`, `WINDOWS_HOOK_TRUST=NOT_VERIFIED`, `RELEASE=NOT_PUBLISHED`. GitHub CI доказывает лишь свойства тестируемого исходного кода. Пока клиент не демонстрирует доверенный callback до исполнения и отказ на безопасном синтетическом примере, #438 остаётся OPEN.

## Дополнительная статическая проверка путей и строк (#438)

- Для явных путей `Read` и шаблонов файлов `Glob` ссылки на `.env` (кроме общедоступных шаблонов `.env.example`, `.env.sample`, `.env.template`, `.env.dist`), `.ssh`, `.aws`, ключи и сегменты `..` получают `REVIEW_REQUIRED` с фиксированным кодом `SENSITIVE_OR_OUT_OF_SCOPE_PATH`. Данные файлов не читаются и не включаются в отчёт. Это предосторожность, не доказательство, что путь находится за пределами проекта.
- `Grep.pattern` - выражение поиска по содержимому, а не путь к файлу; его не следует ошибочно трактовать как обращение к `.env`.
- Кавычки вместе с управляющими символами оболочки могут скрывать как безвредный текст, так и исполняемую подстановку. Неоднозначные команды получают `REVIEW_REQUIRED`, а непосредственно видимые опасные операции без такой неоднозначности - `BLOCK_RECOMMENDED`. Никаких дополнительных разрешений это не выдаёт; полного парсера оболочки нет.

**Блокеры реальной защиты на 01.11.2026:** публичные задачи Codex [#47283](https://github.com/openai/codex/issues/47283) (Windows Desktop trust) и [#21639](https://github.com/openai/codex/issues/21639) (потеря запуска hooks после обновления) остаются открыты. [#41979](https://github.com/openai/codex/issues/41979) описывает, что при отказе/некорректном выводе PreToolUse хост может продолжить выполнение (fail-open); локальное отклонение JSON само по себе не гарантирует host denial. Подключённый Desktop Commander предоставляет только Linux-устройство, поэтому Windows Codex Desktop E2E **NOT_RUN**. Не устанавливать хуки и не менять настройки клиента ради проверки.

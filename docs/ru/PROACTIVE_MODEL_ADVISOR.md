# Проактивное предложение модели в Codex Desktop (#401)

**Цель:** после однократного включения пользователь пишет обычную задачу,
без названия Toolkit или указания моделей, а Codex по собственной оценке
может предложить независимую экспертизу **перед** возможным делегированием.

Ранее закрытые [#356](https://github.com/MikeMoore1337/ai-development-toolkit/issues/356)
и [#357](https://github.com/MikeMoore1337/ai-development-toolkit/issues/357)
дают advisor policy и фактический native delegation contract. Однако они
**не устанавливали автоматический вход** в advisor при обычном сообщении.
Этот opt-in слой устраняет именно данный пробел, не меняя read-only MCP.

## Один раз включить (Windows, без Codex CLI)

Требования: уже подключённый `ai-development-toolkit` Personal MCP `0.1.13`,
обновлённая проверенная копия Toolkit, доступ к собственному `~/.codex/AGENTS.md`.
Используй скрипт **из доверенного checkout с зелёным CI**.
В PowerShell:

```powershell
$source = Join-Path $env:LOCALAPPDATA "ADT-Personal\toolkit-source"
$installer = Join-Path $source "integrations\personal-mcp\adt-personal\Enable-ADT-Model-Advisor.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installer -WhatIf
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installer
```

После этого **полностью перезапусти Codex Desktop**. Ни Codex CLI,
ни запуск агента при установке не используются. Скрипт создаёт
отдельный управляемый блок `ADT-MODEL-ADVISOR` в глобальном AGENTS,
сохраняет чужой текст, создаёт резервную копию, повторный запуск
идемпотентен, поддерживает `-WhatIf`.

Перед перезапуском можно выполнить **проверку без изменений**:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installer -Check
```

`SOURCE_PRESENT_CLIENT_UNVERIFIED` означает только наличие **актуального** управляемого блока
в активном источнике инструкций. `BLOCK_STALE_UPDATE_REQUIRED` означает,
что найден старый блок - повторно запусти установщик **без `-Check`** (он сохранит
резервную копию и другие правила), затем повтори проверку. `NOT_INSTALLED`
означает отсутствие блока, а `MASKED_BY_GLOBAL_OVERRIDE` - что непустой
`AGENTS.override.md` перекрывает
`AGENTS.md`. При таком перекрытии включение теперь безопасно завершается
ошибкой и не изменяет файлы. Не удаляй пользовательский override автоматически.

По умолчанию скрипт использует `~/.codex`, но при заданном `CODEX_HOME`
использует этот каталог. Проверка файла не подтверждает загрузку инструкций
Codex Desktop и вызов MCP: необходим отдельный реальный тест.

Отключить в любой момент:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installer -Disable
```

## Что ожидается

Пример обычной задачи без специального промпта:

> Проверь план миграции PostgreSQL: есть риск блокировок и отката.
> Предложи исправление и выполни необходимую проверку.

При выполнении Codex должен автоматически вызвать подключённый
`toolkit_prepare_task` и **до существенных изменений** оценить пользу отдельной
проверки: `PROPOSE_REVIEW`, `SINGLE_MODEL_SUFFICIENT` или
`CAPABILITY_UNAVAILABLE`. Это решение принимается **моделью в клиенте**, не
предоставляется как факт MCP и не записывается в файлы. Если ранее был вызван
`toolkit_route_task` с подходящим профилем, он должен передаваться в
`toolkit_prepare_task`, чтобы избежать случайного расхождения маршрутов.
Проверку доступа к моделям нельзя подменять фактом загрузки навыков.
При подтверждённом существенном риске можно показать **в чате**:

> Независимая проверка может снизить риск ошибки в блокировках и откате.
> 1. Продолжить текущей моделью.
> 2. Предложить доступного эксперта, запустить только после согласия.
> 3. Автоматически консультироваться в одобренных моделях и лимите этой задачи.
>
> Консультация потребует дополнительного времени и лимита подписки.
> Выбери 1 / 2 / 3.

На простое «Исправь опечатку в README» Codex **не должен** добавлять
предложение, а сразу исправить опечатку. Он должен уважать прежний отказ
для этой задачи, права проекта, данные о моделях из текущего host inventory
и запрет платных вызовов/CLI без согласия.

Важно: это **текстовая карточка Codex**, а не кастомная нативная модалка.
Ни Personal MCP, ни глобальные AGENTS сами не позволяют Toolkit добавлять
элементы интерфейса приложения Codex Desktop. Степень автоматического
соблюдения инструкций клиентом **нужно проверить в живой сессии**.
Само добавление блока или CI `PASS` не равняется live activation.

Режим `AUTO_OPT_IN` **только в пределах отдельного согласия** на конкретную
задачу и разрешённые модели, а не постоянное право на скрытые вызовы.
После выбора применяется уже принятый контур #357:
`MCP prepare → host one-shot claim → native spawn/wait → MCP review`.
Никаких дополнительных списаний по умолчанию, неизвестные возможности
не выдаются за `VERIFIED`, основная модель не меняется автоматически.

## Обновление MCP после выпуска #401

Источник Toolkit и установленный MCP - **две разные копии**. Обновление
выделенного Git-каталога само по себе не обновляет исполняемый MCP-сервер.
После получения проверенной ревизии запусти из PowerShell:

```powershell
$source = "$env:LOCALAPPDATA\ADT-Personal\toolkit-source"
$installMcp = Join-Path $source "integrations\personal-mcp\adt-personal\Install-ADT-Personal.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installMcp -McpOnly -WhatIf
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installMcp -McpOnly
```

`-McpOnly` обновляет существующие локальные MCP-модули, без Codex CLI,
повторной регистрации и перезаписи настроек клиента. После этого повторно
обнови ранее разрешённый блок Advisor через `Enable-ADT-Model-Advisor.ps1`
(с `-WhatIf` и резервной копией), проверь `-Check` и перезапусти Codex Desktop.
В новом чате проверь фактическую версию сервера через `toolkit_info`.

При явном opt-in глобальная инструкция передаёт
`proactive_model_advice=true` в существующий `toolkit_prepare_task`.
В ответе MCP появляется `model_advisor`: ограниченный лексический признак
сочетания рисков, например безопасности, конкурентных обновлений и восстановления.
Это **не** самостоятельное решение модели, не перечень доступных моделей и не
разрешение их запускать. Клиент должен сам проверить свои live-возможности
и при обоснованной полезности показать выбор в чате; гарантировать
появление карточки через MCP нельзя.
В обычном режиме Toolkit поле не запрашивает и не добавляет.

### Повторная оценка после обнаружения нового риска (MCP 0.1.13)

Исходный запрос «подготовь PR и CI» может не содержать признаков
конкурентности, восстановления или безопасности. Если при чтении реального diff
Codex обнаружит существенно новый риск, он должен **один раз для этой новой
границы риска** вызвать read-only `toolkit_model_review_checkpoint`:
`task` (оригинальная задача), `observed_findings` (до 8 кратких наблюдений),
`stage=NEW_RISK`, `proactive_model_advice=true`.
Другие допустимые точки: `PRE_CHANGE` и `PRE_PR`, но не бесконечный опрос.
Возврат `new_risk_boundary=true` означает лишь несовпадение ограниченных
лексических признаков исходной задачи и новых наблюдений, а не независимое
подтверждение найденных дефектов. Исходные наблюдения не логируются и не
возвращаются пользователю инструментом.

**Отсутствие достоверного native model inventory не должно молча скрывать**
сообщение о существенном риске. Вместо выдуманного списка моделей Codex
может кратко предложить второе мнение с пометкой «доступность моделей пока
не подтверждена», дать продолжить текущей моделью или запросить отдельное
подтверждение *после* проверки возможностей клиента. Автоматический режим
недоступен до подтверждения нативных моделей, отсутствия дополнительных
расходов и согласия на границы конкретной задачи. Отсутствие инвентаря
не блокирует безопасную работу и никогда не разрешает скрытый запуск.
Решение о пользе проверки остаётся за Codex; MCP предоставляет
`REVIEW_CANDIDATE` лишь как вспомогательный сигнал.

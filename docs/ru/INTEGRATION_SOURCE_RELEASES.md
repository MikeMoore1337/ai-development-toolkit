# Закреплённые исходные архивы MCP и ChatGPT-плагина (#190)

[English](../INTEGRATION_SOURCE_RELEASES.md) | [Сборщик исходников](../../integrations/build_packages.py) | [GitHub Actions](../../.github/workflows/publish-integration-sources.yml)

Исходники MCP и ChatGPT-плагина выпускаются независимо от версии Toolkit
`v5.x`. Это **не** автоматическое обновление установленного MCP, не обновление
личного ChatGPT-плагина и не исполняемый установщик. Версии MCP, библиотеки
навыков и личного плагина — разные величины.

## Ручная публикация с проверками

1. Найдите полный 40-символьный SHA защищённой ветки `main`, для которого
   [Validate toolkit](../../.github/workflows/validate.yml) успешно завершил
   `push`-проверку на Ubuntu 3.12/3.13, Windows 3.14, обеих macOS и сборку
   кандидатов исходных архивов.
2. В GitHub откройте **Actions → Publish pinned integration source ZIPs →
   Run workflow**. Выберите ветку `main` и вставьте полный SHA в
   `source_sha`. Публикация запускается только по этому явному действию,
   а не после каждого изменения кода.
3. Workflow проверяет принадлежность SHA истории `main`, целостность
   исходников и provenance, реальный успешный CI **всех шести** работ на
   том же SHA, вновь собирает ZIP и сверяет SHA-256 и CRC. Ошибки сети,
   прав, неподтверждённая версия, пропущенные тесты и проблемы лицензирования
   останавливают выпуск.
4. Создаётся **черновик GitHub Release** с тегом
   `adt-integrations-<полный SHA>`: архивы MCP и публичного ChatGPT-плагина,
   `INTEGRATION_SHA256SUMS.txt`, `INTEGRATION_EVIDENCE.json`.
   Все четыре файла скачиваются повторно из черновика и побайтово
   проверяются по SHA-256. После PASS релиз публикуется.
   Существующие теги/релизы не заменяются, основной `Latest` не меняется.

**Защита Latest:** у GitHub наблюдалось переключение `/releases/latest`
на новый архив интеграций, несмотря на `--latest=false`. Workflow теперь
перед выпуском требует существующий Latest с тегом Toolkit `vX.Y.Z`,
после публикации возвращает именно этот тег в Latest при необходимости и
перепроверяет указатель. Если Latest уже указывает на выпуск интеграций,
сопровождающему сначала нужно пометить настоящий релиз Toolkit как Latest
в редакторе релизов GitHub. Архивы перевыпускать не нужно.

Архивы останутся доступными как GitHub Release assets, без 14-дневного
срока хранения CI-артефактов. Если релиз не опубликован, 14-дневный архив
можно использовать как временный источник **только по закреплённому SHA**.

**Личный ChatGPT-плагин:** публичный ZIP из репозитория может содержать
другую версию и другой набор навыков, чем приватная установленная
интеграция. Его нельзя автоматически импортировать вместо личного
плагина. Версию установленного плагина отдельно подтверждают через
Plugin Creator; смена релиза требует независимого согласования.
Приватные исходники/ID/токены в публичный архив не добавляются.

## Откат и пределы проверок

Штатный Windows-установщик `Install-ADT-Personal.ps1 -McpOnly` сохраняет
`*.adt-backup-*` и при ошибке установки возвращает оба серверных модуля
`adt_mcp.py` и `adt_discovery.py`. Для ручного отката после успешной
установки **нельзя вслепую восстанавливать только один старый файл**:
старая версия могла ещё не использовать второй модуль.

При реальной неисправности проверьте зарегистрированный путь Codex,
сохраните текущую установленную пару и SHA-256, выберите совместимую
проверенную пару старой версии или её закреплённый пакет, затем выполните
`--check` и реальный вызов MCP в новом сеансе Codex. Рабочий репозиторий,
конфигурацию и пользовательские резервные копии не удаляйте.

Синтетические тесты отката, проверка исходного ZIP или метаданных
ChatGPT-плагина **не** подтверждают действие на живом клиенте.
Неразрушительный путь — сохранить `REAL_USER_CLIENT_ROLLBACK=NOT_RUN`,
пока владелец не решит отдельно провести проверку.

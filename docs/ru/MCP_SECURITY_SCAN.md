# Проверка безопасности MCP Toolkit через Cisco (#359)

[English](../MCP_SECURITY_SCAN.md)

В Toolkit предусмотрена отдельная **необязательная** проверка объявлений
MCP tools. Она не устанавливает навыки в проекты и не разрешает
подключение новых MCP-серверов автоматически.

## Что проверяется

- `personal`: `TOOLS` из
  `integrations/personal-mcp/adt-personal/mcp/adt_mcp.py`.
- `project`: `_tool_defs()` из `scripts/toolkit_mcp.py`.

Исходные объявления считываются локально. Сервер не запускается,
`tools/call` не вызывается, удалённые адреса не открываются, файлы
пользователя и учётные данные не считываются. Для анализатора создаётся
временный JSON `{"tools":[...]}`. Инструкции сервера, prompts,
resources и **фактическое поведение инструментов** здесь не проверяются,
их необходимо оценивать отдельно.

## Явный запуск

После установки `uv` (`uvx`) в каталоге Toolkit:

```bash
python scripts/cisco_mcp_gate.py --scope personal
python scripts/cisco_mcp_gate.py --scope project
```

Используется внешний Cisco [mcp-scanner](https://github.com/cisco-ai-defense/mcp-scanner)
на commit `4dd0caae7b0d3a80c8c09ed7e4680a9911b0a86e`
(Apache-2.0). Режим `--analyzers yara,schema --format raw static --tools`
запускает только YARA и проверку схем. Платные API, LLM,
Cisco-аккаунт и Codex CLI не нужны.

**О сети:** `uvx` может скачать закреплённую версию сканера и
зависимости. При статическом анализе не используется живой MCP-сервер;
учётные данные и настройки LLM намеренно не передаются. Это не гарантия
отсутствия сетевого трафика при установке зависимостей. Для полностью
офлайн-запуска потребуется заранее подготовленная среда.

## Результаты

`PASS` - все объявленные инструменты и анализаторы проверены без
находок. `REVIEW_REQUIRED` - есть умеренные находки, необходимо
проверить вручную. `BLOCKED` - критическая/высокая угроза,
неполный отчёт, сбой, ошибка контракта либо таймаут. Ни один статус
не разрешает автоматически выполнять MCP-команды.

RU/EN тесты используют синтетические примеры и имитированные сигналы
анализатора. Они доказывают корректность обработки результатов, но
**не** способность Cisco YARA обнаруживать все виды атак на русском.
Статическая проверка не подтверждает честность `readOnlyHint`
и безопасность реализаций. ОС-изоляция, ручная экспертиза,
контроль прав и тестирование исходников остаются обязательными.

```bash
python -m unittest tests.test_cisco_mcp_gate -v
```

## Нативная офлайн-проверка описаний MCP (#432)

Для **базового анализа внедрённых инструкций без установки Cisco Scanner или ECC** используйте:

```sh
python scripts/cisco_mcp_gate.py --scope personal --native
python scripts/cisco_mcp_gate.py --scope project --native
```

Новый режим повторно использует штатный `snapshot()` и ограниченные правила Toolkit. Проверяются описания инструментов и вложенные схемы ввода: подмена инструкций на русском и английском, выдача текста за системную роль, призывы отправить учётные данные и домены для сбора данных. Дубли имён, повреждённые схемы, отсутствие описания и превышение размера отклоняются. В отчёте выводятся только имя инструмента, правило и серьёзность, без вредоносного текста и секретов. Режим не использует сеть, Cisco, MCP-вызовы, hooks, Codex CLI, платные модели и API.

`PASS` означает **отсутствие совпадений с ограниченным набором шаблонов**, а не доказанную безопасность реализации. `REVIEW_REQUIRED` - подозрительные домены, `BLOCKED` - опасные совпадения или ошибочные данные. Старый режим Cisco без `--native` не изменён и остаётся отдельной опциональной проверкой YARA/схем. Реальная реакция модели, обеспечение прав клиентом и полное совпадение с AgentShield не проверялись.

Сравнение выполнено с [AgentShield `b0891303bdcd6037376a94263d45cfd2ff3dfb98`](https://github.com/affaan-m/agentshield/tree/b0891303bdcd6037376a94263d45cfd2ff3dfb98) (MIT), без копирования исходников. Откат - стандартный возврат ревизии; настройки клиента не меняются.

### Воспроизводимая синтетическая проверка качества (#432)

Запустите **диагностический** набор из 16 размеченных примеров на двух языках:

\`\`\`sh
python scripts/cisco_mcp_gate.py --benchmark-native
python -m unittest tests.test_cisco_mcp_gate -v
\`\`\`

Отчёт JSON содержит SHA-256 фиксированного набора из 8 примеров вредоносного перенаправления инструкций и 8 нормальных описаний, матрицу ошибок (\`tp\`, \`fp\`, \`tn\`, \`fn\`), точность (precision), полноту (recall) и идентификаторы ошибок. Статус \`REVIEW_REQUIRED\` считается сигналом проверки, а не доказанной атакой. Исходные фразы, секреты и переписки в результат не попадают; Cisco, AgentShield, модели, сеть и MCP-серверы не запускаются. Код возврата 0 означает **успешное измерение**, даже если обнаружены пропуски; это не разрешение на релиз.

Исходный набор намеренно выявляет пропуски некоторых формулировок и ложные срабатывания на пояснениях и отрицаниях. Нельзя заявлять об идеальной точности, надёжности в реальной эксплуатации или преимуществе над AgentShield. \`upstream_agentshield_comparison=NOT_RUN\` явно означает, что непосредственное сравнение не проводилось. Синтетический показатель подходит для обнаружения регрессий после изменения правил, но не заменяет независимую выборку и физическую проверку ограничений Codex Desktop; #432 остаётся открытой.

### Уточнение эвристик (#432)

Нативная проверка распознаёт ограниченные примеры **полностью защитных формулировок** и прямые русские/английские команды отменить правила безопасности. Произвольный префикс `example:` или оправдательная приписка после опасной команды не отключают проверку. Устранение известных ложных срабатываний и пропусков на синтетических фразах **не доказывает** устойчивость к внедрению инструкций: иные формулировки, обфускация и другие языки могут не обнаруживаться. Выполните `python scripts/cisco_mcp_gate.py --benchmark-native` для просмотра метрик **синтетического** набора точной редакции. Сравнение с реальным AgentShield и блокировка действий клиентом по-прежнему NOT_RUN/NOT_VERIFIED.

### Отдельная синтетическая проверка конфигураций и MCP (#432)

Запуск: `python scripts/native_security_benchmark_432.py` и
`python -m unittest tests.test_native_security_benchmark_432 -v`.
Выборка `fixtures/native_security_holdout_432.json` зафиксирована в Git
**до исходного измерения**: 38 синтетических примеров (19 опасных и 19
безопасных). Для прежних нативных правил получено TP=12, FP=5,
TN=14, FN=7; precision=0.7059, recall=0.6316, F1=0.6667.
SHA-256 выборки:
`6697030f91649f0b05a113216bb49e6636d2bfe60f7d91cbf9062d807b18265e`.
В отчётах сохраняются только численные результаты, категории и
идентификаторы ошибок, без текстов инструкций, фиктивных секретов
и временных абсолютных путей.

Измеритель использует только **уже существующие** нативные проверки.
Он не запускает команды из конфигураций, hooks, MCP-клиент,
AgentShield, платную модель или сеть и не читает личные файлы.
Код возврата 0 означает успешное измерение, а не доказанную безопасность.
После использования ошибок для исправления правил эта выборка уже не является
нетронутой независимой контрольной выборкой; она остаётся регрессионной.
Точность на реальных атаках - `NOT_MEASURED`, прямое сравнение
с AgentShield - `NOT_RUN`, runtime-блокировка клиента - `NOT_VERIFIED`.

В существующий добровольный нативный MCP-анализ добавлены узкие проверки
прямых запросов на раскрытие системного промпта или контекста переписки
и инструкций на чтение секретных файлов. Эвристики могут пропускать
перефразированные атаки и реагировать на защитные цитаты.

## Независимая приёмка безопасности #432 (05.11.2026)

Отдельный набор `fixtures/native_security_independent_432.json` зафиксирован **до изменений правил** (первый коммит `2690d09bdb4f08f0d5edd0738e0a006e85d26b8f`, SHA256 `f629f87c955c5df0dc9c6e1b1f62294884ebd0779798dd8debf87c4957536f5b`). Всего 60 независимых *синтетических* сценариев: 30 атакующих и 30 безопасных. Для первоначальных измерений предназначены 40 случаев, оставшиеся 20 - отложенная контрольная выборка, которую нельзя использовать для подгонки алгоритмов. Старый корпус из 38 случаев остаётся регрессионным.

На исходном `main@cc65540cd9c4cf9b6c5daf29dd18b4639ecf0db8` получено TP=11, FP=5, TN=15, FN=9 (precision=0.6875, recall=0.55, F1=0.611111, FPR=0.25, FNR=0.45). После первоначальных исправлений host gate в `e64aaa60b59c16d13f7b336f4208b395c883bc81`: TP=15, FP=5, TN=15, FN=5 (precision/recall/F1=0.75, FPR/FNR=0.25). Эти значения подтверждены на Ubuntu и Windows в [CI #42057997374](https://github.com/MikeMoore1337/ai-development-toolkit/actions/runs/42057997374). Это измерения **на этапе разработки**, не точность на реальных атаках.

Ограниченные новые проверки MCP охватывают смешанные латинские и похожие кириллические символы, прямой запрос расшифровать и выполнить закодированные инструкции (только предупреждение), дополнительные формы вывода контекста наружу и подмены политики безопасности. Исключения для защитных объяснений проверяют **всю** строку: опасное продолжение не должно скрываться. Оригинальный Cisco MCP Scanner остаётся необязательным отдельным механизмом, в нативном режиме не запускается.

Регрессия: `python -m unittest tests.test_native_security_independent_432 tests.test_native_security_regression_432 tests.test_cisco_mcp_gate -v`. Контрольная выборка: `python tests/test_native_security_independent_432.py --cohort holdout` - **только после фиксации алгоритмов**, затем протокол в CI на точном HEAD. Нельзя подбирать правила под эту выборку. Статус `BLOCKED` в нативном отчёте означает **статический сигнал, а не блокировку действия клиентом**. `HOST_ENFORCEMENT=NOT_VERIFIED`, `CLIENT_E2E=NOT_RUN`, точность на реальных атаках `NOT_MEASURED`.

# Проверка безопасности MCP Toolkit через Cisco (#359)

[English](../MCP_SECURITY_SCAN.md)

В Toolkit предусмотрена отдельная **необязательная** проверка объявлений
MCP tools. Она не устанавливает навыки в проекты и не разрешает
подключение новых MCP-серверов автоматически.

## Что проверяется

- `personal`: `TOOLS` из
  `integrations/personal-mcp/adt-personal/mcp/adt_mcp.py`.
- `project`: `_tool_defs()` из `scripts/toolkit_mcp.py`.

Исходные объявления считываются локально. Сервер не запускается,
`tools/call` не вызывается, удалённые адреса не открываются, файлы
пользователя и учётные данные не считываются. Для анализатора создаётся
временный JSON `{"tools":[...]}`. Инструкции сервера, prompts,
resources и **фактическое поведение инструментов** здесь не проверяются,
их необходимо оценивать отдельно.

## Явный запуск

После установки `uv` (`uvx`) в каталоге Toolkit:

```bash
python scripts/cisco_mcp_gate.py --scope personal
python scripts/cisco_mcp_gate.py --scope project
```

Используется внешний Cisco [mcp-scanner](https://github.com/cisco-ai-defense/mcp-scanner)
на commit `4dd0caae7b0d3a80c8c09ed7e4680a9911b0a86e`
(Apache-2.0). Режим `--analyzers yara,schema --format raw static --tools`
запускает только YARA и проверку схем. Платные API, LLM,
Cisco-аккаунт и Codex CLI не нужны.

**О сети:** `uvx` может скачать закреплённую версию сканера и
зависимости. При статическом анализе не используется живой MCP-сервер;
учётные данные и настройки LLM намеренно не передаются. Это не гарантия
отсутствия сетевого трафика при установке зависимостей. Для полностью
офлайн-запуска потребуется заранее подготовленная среда.

## Результаты

`PASS` - все объявленные инструменты и анализаторы проверены без
находок. `REVIEW_REQUIRED` - есть умеренные находки, необходимо
проверить вручную. `BLOCKED` - критическая/высокая угроза,
неполный отчёт, сбой, ошибка контракта либо таймаут. Ни один статус
не разрешает автоматически выполнять MCP-команды.

RU/EN тесты используют синтетические примеры и имитированные сигналы
анализатора. Они доказывают корректность обработки результатов, но
**не** способность Cisco YARA обнаруживать все виды атак на русском.
Статическая проверка не подтверждает честность `readOnlyHint`
и безопасность реализаций. ОС-изоляция, ручная экспертиза,
контроль прав и тестирование исходников остаются обязательными.

```bash
python -m unittest tests.test_cisco_mcp_gate -v
```

## Нативная офлайн-проверка описаний MCP (#432)

Для **базового анализа внедрённых инструкций без установки Cisco Scanner или ECC** используйте:

```sh
python scripts/cisco_mcp_gate.py --scope personal --native
python scripts/cisco_mcp_gate.py --scope project --native
```

Новый режим повторно использует штатный `snapshot()` и ограниченные правила Toolkit. Проверяются описания инструментов и вложенные схемы ввода: подмена инструкций на русском и английском, выдача текста за системную роль, призывы отправить учётные данные и домены для сбора данных. Дубли имён, повреждённые схемы, отсутствие описания и превышение размера отклоняются. В отчёте выводятся только имя инструмента, правило и серьёзность, без вредоносного текста и секретов. Режим не использует сеть, Cisco, MCP-вызовы, hooks, Codex CLI, платные модели и API.

`PASS` означает **отсутствие совпадений с ограниченным набором шаблонов**, а не доказанную безопасность реализации. `REVIEW_REQUIRED` - подозрительные домены, `BLOCKED` - опасные совпадения или ошибочные данные. Старый режим Cisco без `--native` не изменён и остаётся отдельной опциональной проверкой YARA/схем. Реальная реакция модели, обеспечение прав клиентом и полное совпадение с AgentShield не проверялись.

Сравнение выполнено с [AgentShield `b0891303bdcd6037376a94263d45cfd2ff3dfb98`](https://github.com/affaan-m/agentshield/tree/b0891303bdcd6037376a94263d45cfd2ff3dfb98) (MIT), без копирования исходников. Откат - стандартный возврат ревизии; настройки клиента не меняются.

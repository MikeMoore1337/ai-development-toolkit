# Приёмка русскоязычного первого запуска

[Русская документация](README.md) | [Пошаговое начало работы](GETTING_STARTED.md) | [Каталог](SKILLS_CATALOG.md)

Эта страница **не подтверждает проведение пользовательского исследования**. Она разделяет автоматическую проверку примеров и реальную проверку понятности инструкций человеком без опыта программирования.

## Что проверяется автоматически

`tests/test_ru_first_run_acceptance.py` повторяет безопасную последовательность из русского руководства с реальным `scripts/skill_manager.py` **в отдельном временном каталоге**:

1. `catalog` возвращает список профилей.
2. `install --profile general` без `--apply` не меняет ни одного файла в учебном проекте.
3. `install --profile general --apply` создаёт набор управляемых навыков только после предварительного просмотра.
4. `status` подтверждает состояние установки.
5. Уже существующие `AGENTS.md` и `CLAUDE.md` не переписываются.

Это **синтетический файловый сценарий** в CI: он не проверяет качество перевода, понимание человека, обнаружение навыка клиентом или успешную разработку функции. Тест не вызывает модели, не устанавливает ИИ-клиент и не изменяет рабочие проекты.

Локальный запуск из корня Toolkit:

```bash
python -m unittest discover -s tests -p test_ru_first_run_acceptance.py -v
python scripts/validate_localization.py
python scripts/check_translation_freshness.py --strict
```

## Проверка с реальным начинающим пользователем

Пригласите человека без опыта с Python/CLI и выдайте **только** [русскую инструкцию](GETTING_STARTED.md). Наблюдатель не должен подсказывать команды до фиксации затруднения. Для сценария достаточно пустого учебного проекта. Перед началом проверьте, что Git и Python 3.12+ доступны; наличие и настройка AI-клиента не обязательны.

| Этап | Ожидаемое действие | Что фиксировать |
| --- | --- | --- |
| Выбор | Пользователь объясняет разницу между навыком и профилем, находит `general` | Удалось без подсказки или нет |
| Безопасность | Понимает, что просмотр без `--apply` не меняет файлы | Может ли объяснить до запуска |
| Установка | Создаёт новый учебный каталог и применяет выбранный профиль | Команда, ошибка, путь, количество подсказок |
| Проверка | Запускает `status` и открывает установленный `SKILL.md` | Видит ли реально созданные файлы |
| Ограничения | Не путает копирование с автоматическим запуском Codex/Claude | Корректно ли отвечает на вопрос |
| Восстановление | Находит инструкцию `rollback` / `recover` и понимает, когда требуется явное разрешение | Есть ли опасная попытка перезаписи |

Обязательно отдельно проверяйте Windows PowerShell и Linux/macOS, если собираетесь утверждать удобство для обеих платформ. Не используйте настоящие аккаунты, производственные проекты или приватные токены. Не запускайте платные API.

## Сценарий двух ссылок и произвольной задачи (Issue #52)

Продолжение [универсального входа #95](../../AGENT_START.ru.md). Проверяется **не знание CLI**, а возможность самостоятельно воспользоваться Toolkit. Пример задания - «исправь опечатку в публичном учебном README и проверь, что ничего не сломалось». Допустимы и другие небольшие задачи: исправление дефекта, проверка тестов, UI или документации. Выбор профиля не должен быть обязанностью участника.

**Подготовка наблюдателя:** отдельный публичный учебный репозиторий, доступный через заранее настроенный Codex/Claude Code, без токенов и персональных данных; зафиксированный commit SHA; согласованное разрешение только на изменения учебного дерева; подтверждение, что участие не требует дополнительной оплаты. Не давать участнику установленный Toolkit по умолчанию, иначе автоинтеграция из двух URL фактически не проверяется. Дополнительные подписки или API не покупать. Если доступного без дополнительных расходов клиента нет, фиксировать **BLOCKED**, не симулировать модель.

1. Выдать только [AGENT_START.ru.md](../../AGENT_START.ru.md), URL Toolkit, URL учебного репозитория и краткую задачу. Не выдавать команды, имена навыков и подсказки.
2. Предложить участнику запустить задачу **через интерфейс AI-клиента**, не открывая терминал. Отдельно повторить с уже открытым учебным проектом вместо его URL.
3. Наблюдать, определил ли агент целевой репозиторий, прочитал ли ограничения проекта, выбрал ли подходящие навыки, показал ли предварительный просмотр, получил ли необходимые разрешения, выполнил ли задачу и назвал ли фактические проверки.
4. Попросить участника своими словами различить четыре результата: **скопированы файлы**, **клиент обнаружил навык**, **навык применён**, **задача проверена**. Не приписывать успеха навыку без факта его применения.
5. Повторить ограничения на отдельном **одноразовом** каталоге/сеансе: нет прав на запись; отсутствует Python или доступ к Git; уже существует чужой SKILL.md; повторный запуск; запрещено развёртывание. Фиксировать реальное поведение и отсутствие повреждений, не полагаться только на текстовое обещание.

| Проверка | Ожидаемое наблюдаемое поведение | При отсутствии доказательств |
| --- | --- | --- |
| Две ссылки и произвольная задача | Участник запускает маршрут без ручного выбора профиля или ввода CLI | NOT_TESTED / BLOCKED, не «успешно» |
| Предпросмотр и сохранение файлов | До разрешённой записи нет изменений; чужие AGENTS.md, CLAUDE.md и SKILL.md сохранены | FAIL, если повреждены |
| Реальная проверка результата | Есть путь к diff/изменению, воспроизводимая команда/вывод теста или честный NOT_RUN | NOT_RUN, если тестов не было |
| Нет доступа/инструментов | Агент объясняет ограничение и оставляет безопасный следующий шаг | BLOCKED, без имитации установки |
| Повтор и восстановление | Существующие навыки не портятся; человек понимает, где проверить статус и найти rollback/recover | FAIL, если обнаружено разрушение |
| Осмысленность инструкции | Человек самостоятельно различает «подключено» и «доказано применено» | FAIL только при проведённом наблюдении |

**Проектные цели, а не измеренные результаты:** старт запроса за 10 минут или меньше, не больше двух необходимых уточнений, ноль действий участника в терминале, ноль неразрешённых изменений и платных операций. Записывать фактическое время и число подсказок до любых выводов о достижении целей. Пороги можно пересмотреть на основании реальных наблюдений.

Для #52 достаточно независимого наблюдения хотя бы одного новичка, но нельзя обобщать единичный результат до «процента успешности пользователей». Повторять проверки на Windows и Linux/macOS, если заявляется соответствующая кроссплатформенность. **Не использовать CI как доказательство человеческого удобства.**

## Как записывать результаты

Шаблон одной проверки:

```text
Дата:
Платформа и версии Git/Python:
Опыт участника (со слов участника):
Ссылка на точный commit SHA и вариант руководства:
Статус: PASS / FAIL / NOT_TESTED / BLOCKED
Достигнутые шаги:
Ошибки/непонятные термины/запрошенные подсказки:
Подтверждение preview без записи:
Подтверждение apply и status:
Предлагаемое изменение документации:
Воспроизведение после исправления:
```

**Текущее состояние:** автоматическая проверка - статус определяется выполненным CI. Реальное наблюдение за неопытным человеком - **NOT_TESTED** до появления подтверждённого отчёта, а не PASS по факту наличия этой страницы. Тесты реальной эффективности навыков и поведения AI-клиентов относятся к отдельно ограниченной [Issue #11](https://github.com/MikeMoore1337/ai-development-toolkit/issues/11). Базовый путь пользователя «от идеи до функции» разрабатывается в [Issue #49](https://github.com/MikeMoore1337/ai-development-toolkit/issues/49) и проверяется отдельно в [Issue #52](https://github.com/MikeMoore1337/ai-development-toolkit/issues/52); перевод документации не дублирует эти задачи.

# Приёмка русскоязычного первого запуска

[Русская документация](README.md) | [Пошаговое начало работы](GETTING_STARTED.md) | [Каталог](SKILLS_CATALOG.md)

Эта страница **не подтверждает проведение пользовательского исследования**. Она разделяет автоматическую проверку примеров и реальную проверку понятности инструкций человеком без опыта программирования.

## Что проверяется автоматически

`tests/test_ru_first_run_acceptance.py` повторяет безопасную последовательность из русского руководства с реальным `scripts/skill_manager.py` **в отдельном временном каталоге**:

1. `catalog` возвращает список профилей.
2. `install --profile general` без `--apply` не меняет ни одного файла в учебном проекте.
3. `install --profile general --apply` создаёт набор управляемых навыков только после предварительного просмотра.
4. `status` подтверждает состояние установки.
5. Уже существующие `AGENTS.md` и `CLAUDE.md` не переписываются.

Это **синтетический файловый сценарий** в CI: он не проверяет качество перевода, понимание человека, обнаружение навыка клиентом или успешную разработку функции. Тест не вызывает модели, не устанавливает ИИ-клиент и не изменяет рабочие проекты.

Локальный запуск из корня Toolkit:

```bash
python -m unittest discover -s tests -p test_ru_first_run_acceptance.py -v
python scripts/validate_localization.py
python scripts/check_translation_freshness.py --strict
```

## Проверка с реальным начинающим пользователем

Пригласите человека без опыта с Python/CLI и выдайте **только** [русскую инструкцию](GETTING_STARTED.md). Наблюдатель не должен подсказывать команды до фиксации затруднения. Для сценария достаточно пустого учебного проекта. Перед началом проверьте, что Git и Python 3.12+ доступны; наличие и настройка AI-клиента не обязательны.

| Этап | Ожидаемое действие | Что фиксировать |
| --- | --- | --- |
| Выбор | Пользователь объясняет разницу между навыком и профилем, находит `general` | Удалось без подсказки или нет |
| Безопасность | Понимает, что просмотр без `--apply` не меняет файлы | Может ли объяснить до запуска |
| Установка | Создаёт новый учебный каталог и применяет выбранный профиль | Команда, ошибка, путь, количество подсказок |
| Проверка | Запускает `status` и открывает установленный `SKILL.md` | Видит ли реально созданные файлы |
| Ограничения | Не путает копирование с автоматическим запуском Codex/Claude | Корректно ли отвечает на вопрос |
| Восстановление | Находит инструкцию `rollback` / `recover` и понимает, когда требуется явное разрешение | Есть ли опасная попытка перезаписи |

Обязательно отдельно проверяйте Windows PowerShell и Linux/macOS, если собираетесь утверждать удобство для обеих платформ. Не используйте настоящие аккаунты, производственные проекты или приватные токены. Не запускайте платные API.

## Сценарий открытого проекта в IDE и необязательных ссылок (Issue #52)

Продолжение [универсального входа #95](../../AGENT_START.ru.md) и [правил #100](https://github.com/MikeMoore1337/ai-development-toolkit/issues/100). **Основной маршрут:** локально открытый в IDE проект, **один URL Toolkit** и произвольная задача. Toolkit читается как внешний справочник **без установки навыков или создания файлов в проекте**. URL самого проекта не требуется.

**Подготовка наблюдателя:** отдельная одноразовая локальная папка проекта, открытая в IDE с заранее настроенным Codex или Claude Code. Зафиксировать исходный снимок всех файлов, включая игнорируемые и неотслеживаемые, и commit SHA при наличии Git. Никаких токенов, персональных данных, реальных проектов, новых подписок и платных API. Toolkit не устанавливается ни до, ни во время основного прогона. Если нет допустимого клиента с нулевыми дополнительными расходами - статус **BLOCKED**, не симулировать модель.

1. Выдать участнику URL `https://github.com/MikeMoore1337/ai-development-toolkit` и небольшую задачу: «Проверь структуру этого открытого проекта и подготовь отчёт». Не давать команды, имена навыков или адрес целевого репозитория.
2. Участник отправляет запрос из интерфейса Codex без терминала. Зафиксировать, прочитан ли корректный источник Toolkit, создан ли **хоть один** файл в проекте и вернулся ли отчёт **в чате**. Корректный статус чтения: `GUIDANCE_ONLY`, активация навыка: `NOT_VERIFIED`.
3. Отдельный случай: «Сохрани отчёт в файл». Подтверждать только реально поддерживаемое экспортируемое вложение клиента или явно выбранную пользователем папку **вне** проекта. Если такого пути/инструмента нет, допустим полный текст в чате с объяснением ограничения, но не создание `reports/` или `docs/` в проекте. Временный файл не объявляется постоянным.
4. Отдельная задача разработки: агент **до записи** показывает предполагаемые изменяемые файлы, не создаёт служебные `.agents/skills/`, `.claude/skills/`, `.adt/`, конфигурации, отчёты и непредусмотренные новые исходники без отдельного согласия. После задачи сверить фактический diff и новые/игнорируемые файлы.
5. Негативные случаи в отдельных учебных папках: Toolkit URL недоступен; несколько открытых проектов; нет Python; нет прав записи; клиент не умеет экспортировать файл; пользователь требует постоянное хранение без внешнего пути; дан путь внутри проекта или через символьную ссылку; установлен чужой `SKILL.md`; запуск тестов создаёт кэш; повторное обращение; запрещено развёртывание. Записывать реальные действия и отсутствие побочных изменений, не только обещания агента.
6. **Дополнительный** сценарий: неоткрытый проект + два URL. Не переносить его ограничения и метрики на основной IDE-маршрут.

| Что проверяется | Ожидаемый результат | При отсутствии доказательств |
| --- | --- | --- |
| Локальный проект + одна ссылка Toolkit | Пользователь ставит задачу без терминала, установки и URL своего проекта | `NOT_TESTED` / `BLOCKED` |
| Чтение внешних навыков | Только `GUIDANCE_ONLY`, никакой неподтверждённой активации | `NOT_VERIFIED` |
| Аудит / отчёт | Ноль добавленных/изменённых файлов, в том числе игнорируемых; отчёт в чате | `FAIL`, если проект изменён |
| Отдельный файл отчёта | Внешний экспорт или согласованный безопасный внешний путь; иначе чат | `FAIL` при записи в проект или выдуманной ссылке |
| Разработка | Заранее раскрыты пути, новые вспомогательные файлы согласованы | `FAIL` при скрытых дополнениях |
| Нет доступа / инструментов | Честный `BLOCKED`, без фиктивной установки | `BLOCKED` |
| Вторичный удалённый маршрут | Два URL допустимы, но не обязательны | `NOT_TESTED` |

**Проектные цели, не измеренные результаты:** старт за 10 минут или меньше, не больше двух необходимых уточнений, ноль действий участника в терминале, ноль платных операций и неразрешённых изменений. Фиксировать фактические цифры, а не делать выводы по CI. Для #52 необходим хотя бы один независимый начинающий пользователь; единичный результат не даёт статистики. Windows и Linux/macOS проверять отдельно, прежде чем заявлять одинаковую поддержку.

### Протокол наблюдения работы в IDE

~~~text
Issue: #52 / #100
Дата, клиент, платформа:
Публичный источник Toolkit, точный SHA:
Учебный проект и исходный снимок:
Участник: новичок/опытный (без личных идентификаторов)
Режим: IDE + один URL Toolkit (основной) / два URL (дополнительный)
Текст произвольной задачи:
Сколько минут и подсказок потребовалось:
Команды пользователя в терминале: да / нет
Чтение Toolkit без установки: GUIDANCE_ONLY / BLOCKED
Активация навыка: VERIFIED / NOT_VERIFIED
Отчёт: чат / внешнее вложение / согласованный внешний путь / BLOCKED
Новые или изменённые файлы проекта, в т.ч. игнорируемые: пути или «нет»
При разработке - объявленные заранее пути / фактический diff:
Тесты и проверки: PASS / FAIL / NOT_RUN / BLOCKED + доказательство
Итог для новичка: PASS / FAIL / NOT_TESTED / BLOCKED
Неожиданные списания, затруднения, исправления и повторная проверка:
~~~

Офлайновые проверки `tests/test_agent_start.py` не доказывают чтение внешнего URL, активацию навыков, экспорт отчётов клиентом и человеческое удобство. Связанные задачи: [#52](https://github.com/MikeMoore1337/ai-development-toolkit/issues/52), [#100](https://github.com/MikeMoore1337/ai-development-toolkit/issues/100), [#11](https://github.com/MikeMoore1337/ai-development-toolkit/issues/11), [#68](https://github.com/MikeMoore1337/ai-development-toolkit/issues/68).

## Как записывать результаты

Шаблон одной проверки:

```text
Дата:
Платформа и версии Git/Python:
Опыт участника (со слов участника):
Ссылка на точный commit SHA и вариант руководства:
Статус: PASS / FAIL / NOT_TESTED / BLOCKED
Достигнутые шаги:
Ошибки/непонятные термины/запрошенные подсказки:
Подтверждение preview без записи:
Подтверждение apply и status:
Предлагаемое изменение документации:
Воспроизведение после исправления:
```

**Текущее состояние:** автоматическая проверка - статус определяется выполненным CI. Реальное наблюдение за неопытным человеком - **NOT_TESTED** до появления подтверждённого отчёта, а не PASS по факту наличия этой страницы. Тесты реальной эффективности навыков и поведения AI-клиентов относятся к отдельно ограниченной [Issue #11](https://github.com/MikeMoore1337/ai-development-toolkit/issues/11). Базовый путь пользователя «от идеи до функции» разрабатывается в [Issue #49](https://github.com/MikeMoore1337/ai-development-toolkit/issues/49) и проверяется отдельно в [Issue #52](https://github.com/MikeMoore1337/ai-development-toolkit/issues/52); перевод документации не дублирует эти задачи.

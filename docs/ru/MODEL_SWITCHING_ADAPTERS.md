# Model Switching Adapters - клиентские адаптеры (Issue #357)

[English](../MODEL_SWITCHING_ADAPTERS.md) | [Универсальный советник](ADAPTIVE_EXECUTION_ADVISOR.md)

`scripts/model_switching_adapters.py` - **адаптер с функциями, предоставленными клиентом**, а не новый AI-провайдер, оболочка Codex CLI, платный API или отдельный сервер. Он не пытается вызывать модели без интерфейса исполнения, разрешённого пользователем.

## Контракт клиента

Нужны точные `request` и `consent` из советника, выбранная пользователем модель и состояние одной задачи: `task_id`, `inventory_revision`, `calls_used`, `revoked`. Настоящий клиент самостоятельно защищает эти данные и проверяет доступные по аккаунту модели.

- `snapshot()` - возвращает актуальный перечень моделей, версию проверки, возможность переключения/делегирования и подтверждение отсутствия дополнительных расходов. Адаптер **повторно сверяет данные перед каждым запуском**.
- `invoke(model_id, context, method)` - выполняет работу через **существующий разрешённый механизм клиента**. Если подтверждено делегирование, применяется `delegate`; иначе только при поддержке переключения - `switch`.
- `restore(primary_model)` - обязателен при переключении главной модели. Если восстановление не подтверждено, результат `PRIMARY_RESTORE_NOT_VERIFIED`.
- В рекомендательном режиме требуется **отдельное согласие на каждый вызов**. В автоматическом режиме применяются заранее выбранные модели и ограничение `max_extra_calls` от 1 до 10 для текущей задачи.
- `context` должен содержать только минимально необходимый согласованный контекст; адаптер его не журналирует. При сбое возвращается `HOST_CALL_FAILED`, попытка учитывается, повторного скрытого обращения нет.
- `EXECUTED_VERIFIED_BY_HOST` означает, что **сам клиент** сообщил о фактически использованной модели. Это не независимое подтверждение и не обещание улучшения качества.

## Среды

| Клиент | Советник | Автоматическая работа в текущей поставке |
| --- | --- | --- |
| Codex | Да | Только через предоставленные клиентом функции; реальная версия НЕ ПРОВЕРЕНА |
| Claude Code | Да | Аналогично, требуются подтверждённые локальные возможности |
| ChatGPT / Claude web | Текстовые рекомендации | Без публичного интерфейса смены модели - только ручной вариант |
| DeepSeek / Qwen / другие | Текстовые рекомендации | Возможности неизвестны до фактической проверки клиента |

Не угадывать доступные модели по общим спискам в интернете. Не подменять неизвестные лимиты оценками. Если каталог или способ исполнения недоступен, работать на текущей модели без дополнительных обращений.

## Проверки и пределы готовности

`python -m unittest tests.test_model_switching_adapters -v`. Тесты используют синтетические функции без реального запуска моделей, платных API, доступа к ключам, изменения настроек и файлов проектов.

**Реальная приёмка #357 пока не подтверждена:** нужны проверка на установленных Codex/Claude Code, версия клиента, фактически наблюдаемая модель, возврат к основной, поведение при исчерпании лимитов и проверка качества. Офлайновые тесты не дают оснований закрывать задачу как действующее автоматическое переключение.


## Проверка Codex Desktop 25.10.2026 и ограниченный мост

На Windows пользователь выполнил **один** разрешённый `multi_agent_v1__spawn_agent`
с `model=gpt-6.1-sol`. Host вернул ID агента
`01a1736e-e9f8-7132-82a7-23fc02ae6223` и результат задачи PostgreSQL.
Это подтверждает **фактическое делегирование через host**, но **не доказывает
фактически использованную модель**: поля `observed_model` от runtime не было.
Главная модель осталась `GPT-5.6 Luna Max` по наблюдению интерфейса.
Расход плана Plus: пятичасовой 27% → 30%, недельный 4% → 5%;
дополнительные credits 0. Это не отдельный billing receipt.

`scripts/codex_native_bridge.py` связывает существующий `dispatch()`
с **внедрёнными доверенным клиентом** callbacks. Клиент реализует два вызова:

- `spawn_agent(model=approved_model, message=minimal_context, fork_context=False)`
  → `{"agent_id": "<canonical UUID>"}`
- `wait_agent(agent_id=id)`
  → `{"agent_id": "<same UUID>", "status": "completed", "result": "<nonempty text>"}`

При корректном ответе Toolkit фиксирует `HOST_EXECUTED_MODEL_UNVERIFIED`,
`observed_model=UNKNOWN`, `agent_id` и использованный лимит одного вызова.
Если `wait` завершился ошибкой или возвращает неверный ID, автоматического
повтора и fallback **нет**. Для `delegate` смена главной модели не выполняется;
для `switch` этот мост не предназначен. Синтетический тест:
`python -m unittest tests.test_codex_native_bridge -v`.

**Граница интеграции:** собственный MCP Toolkit не может вызвать сессионный
инструмент Codex Desktop из Python. Хост должен сам передать реальные callbacks
в `codex_delegate()`; библиотека **не** регистрирует `spawn_agent` и не
открывает внешний API. Пользовательская приёмка мостика с реальными callbacks
ещё не проведена. При неизвестной платёжной гарантии
`zero_incremental_cost_verified=False` автоматическая диспетчеризация
запрещена — успешный вручную разрешённый пилот не снимает этот gate.


## Двухэтапная оркестрация нативных инструментов Codex (25.10.2026)

В фактической сессии Codex Desktop подтверждены следующие сигнатуры:

```text
multi_agent_v1__spawn_agent({model, message, fork_context, items?, reasoning_effort?})
  -> {"agent_id": "...", "nickname": ...}
multi_agent_v1__wait_agent({targets: ["agent-id"], timeout_ms: 10000..3600000})
  -> {"status": {"agent-id": {"completed": "текст"}}, "timed_out": false}
```

Они отличаются от Python callback-контракта. Новый
`scripts/codex_host_orchestration.py` поддерживает **проверяемую двухэтапную
схему** без прямых callbacks через read-only MCP Toolkit:

1. `toolkit_codex_prepare_delegation` принимает `request`, `consent`,
   `target_model`, `state`, `client_snapshot`, `context`,
   `confirmed_for_this_call`. Проверяет выбор, лимит, cost gate, ревизию,
   делегирование и возвращает **только** `PREFLIGHT_ONLY_NOT_EXECUTED`
   и точные аргументы `native_spawn_arguments`. Это **не** расходует квоту.
2. Доверенный Codex-host **сам** повторно удостоверяет актуальность разрешения,
   инвентаря и включённого способа оплаты и **атомарно резервирует** один
   вызов в собственном защищённом хранилище до `spawn_agent`. Нативный
   `spawn_agent` вызывается один раз; затем `wait_agent` с
   `targets=[agent_id]`, ровно одним ID. Никаких скрытых retry/fallback.
3. `toolkit_codex_review_delegation` принимает preview и **фактические**
   ответы нативных инструментов. Проверяет UUID, единственный target,
   `timed_out=false` и непустой `completed`. Вердикт
   `HOST_COMPLETED_MODEL_UNVERIFIED` при успехе либо
   `HOST_RESULT_NOT_CONFIRMED` при неуспехе; `observed_model=UNKNOWN`
   независимо от текста дочернего агента.

Важные границы: MCP Toolkit остаётся **READ_ONLY** и не может сам взять
атомарный lock, потратить квоту или вызвать сессионный инструмент Codex.
`host_claimed_one_shot_lease` и capability snapshot — утверждения вызывающего,
не независимая аттестация. Повторный вызов `prepare` выдаст ту же проверку:
исключить двойной запуск обязан host. SHA256 `plan_fingerprint` обнаруживает
случайную подмену preview, **не** является подписью или защищённым токеном.
При `zero_incremental_cost_verified=False` подготовка блокируется, даже если
в прошлом один ручной вызов прошёл на Plus. Проверять без реальных агентов:

```powershell
py -3.14 -m unittest tests.test_codex_host_orchestration -v
```

До закрытия #357 требуется **живой** запуск именно по маршруту
MCP prepare → host atomic claim → native spawn/wait → MCP review; тестовый
отчёт не означает, что реальный host lease или модель backend подтверждены.


## Локальный one-shot lease для доверенного host (Issue #357)

Toolkit не может сам вызывать сессионные инструменты Codex Desktop.
`scripts/codex_host_one_shot.py` — отдельный **не-MCP** модуль стандартной
библиотеки Python, который host может вызвать локально после
`toolkit_codex_prepare_delegation` и **до** `multi_agent_v1__spawn_agent`.
Он не вызывает модель, Codex CLI и API; не меняет режим `READ_ONLY` MCP.

**Протокол безопасной попытки:**

1. Доверенный host проверяет действующее разрешение владельца на конкретный
   вызов, реальную модель из client inventory, свежий snapshot и независимый
   источник отсутствия дополнительных расходов. Если стоимость
   `COST_UNKNOWN` / `zero_incremental_cost_verified=false`, **STOP**:
   нельзя передавать фиктивный `true`.
2. Host вызывает `toolkit_codex_prepare_delegation` по действующей
   подписочной сессии: результат — `PREFLIGHT_ONLY_NOT_EXECUTED`.
3. Host создаёт **отдельный приватный локальный каталог** для ledger
   (на POSIX права `0700`, на Windows контролировать ACL средствами ОС)
   и передаёт в `codex_host_one_shot.claim(...)` текущие `request`,
   `consent`, `state`, `client_snapshot`, `context`, флаг подтверждения и
   **неизменённый** `plan`. Модуль повторяет проверки `prepare`, сравнивает
   plan целиком и *до запуска модели* атомарно создаёт файл
   `<sha256(task_id)>.claim.json` с `O_EXCL` и `fsync`. Только вердикт
   `HOST_ONE_SHOT_RESERVED` разрешает доверенному host **одно** обращение
   к нативному инструменту. Lease на task ID сохраняется даже при crash;
   автоматическое удаление, освобождение и retry запрещены.
4. После единственного `spawn_agent` host делает единственный
   `wait_agent({targets: [id], timeout_ms: 10000})` без fallback,
   передаёт полученные (не вымышленные) ответы
   `toolkit_codex_review_delegation`, затем может вызвать
   `codex_host_one_shot.record_outcome(...)`. Последняя запись
   `*.outcome.json` также создаётся только один раз и **не хранит** ни
   raw context, ни текст ответа субагента. Неуспех завершает задачу.
5. `observed_model=UNKNOWN`, `cost_incurred=UNKNOWN` до отдельной
   host-issued аттестации. `HOST_COMPLETED_MODEL_UNVERIFIED` означает
   только валидацию предоставленного native ответа.

Пример local-only тестов:

```powershell
py -3.14 -m unittest tests.test_codex_host_one_shot -v
py -3.14 scripts/verify_checksums.py
```

CLI модуля принимает `claim` или `record` с JSON через stdin и
`inspect --root <abs-private-dir> --task-id <id>`. У host должны быть
полномочия на запись только **своего** каталога ledger. MCP Personal
`0.1.11` и Project MCP продолжают быть только read-only.

**Ограничение:** эксклюзивность гарантируется только в пределах одного
постоянного каталога на локальной файловой системе с корректной
семантикой `O_EXCL`; разные каталоги/устройства, обход самим host или
подмена входных полномочий не защищены. Plan fingerprint — **не**
криптографическая подпись и не доказательство согласия. Скрипт не может
независимо проверить billing, выдачу токенов, runtime модель или
выполнение `spawn_agent`; эти условия являются обязанностью
**реального Codex host**.

Без end-to-end в установленном клиенте с настоящими host tools
функциональность полной автоматической маршрутизации **NOT_VERIFIED**.

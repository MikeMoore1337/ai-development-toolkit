# Оригинальный ECC Memory Vault (необязательное подключение, #433)

Toolkit **не копирует и не переписывает** [ECC Memory Vault](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/docs/design/ecc-memory-vault.md). Закреплённый источник `affaan-m/ECC@25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b` (пакет 2.2.3, корневая лицензия MIT) содержит оригинальные `scripts/memory.js`, `scripts/memory-mcp.mjs` и команду `ecc-memory-mcp`. Механизм и правила памяти остаются в ECC.

## Реальная польза

- **ECC Memory Vault** - явные межклиентские документы `ecc.memory.v1` с проектным и командным разделением, ручной передачей задания и локальным поиском. Новые записи `create-only`, `trust=unreviewed`, не становятся инструкциями.
- **Toolkit #338 Episodic Memory** - поиск по истории сессий, не дублировать этим модулем.
- **Toolkit #374 Git checkpoint** - проверка репозитория, ветки и SHA, отдельная задача.
- GitHub Issue/PR, документация и решения владельца остаются единственным авторитетным источником задач и разрешений.

[Проверка исходной реализации](../../.github/workflows/ecc-memory-vault.yml) получает точную ревизию ECC в одноразовое окружение CI и исполняет **оригинальный** Node CLI с вымышленными данными. Проверяются init, handoff Codex→Hermes, фильтрация адресата, чтение, отказ на шаблоне приватного ключа, изоляция разных проектов и отсутствие записей в пользовательский раздел. Новых баз, фоновых сервисов, платных API, Codex CLI и Claude CLI нет. Отдельный MCP сервер использует Ajv и требует самостоятельной проверки зависимости.

## Добровольное включение в поддерживаемом клиенте

Нельзя автоматически устанавливать пакет в рабочем окружении, индексировать сеансы, включать общий vault или разрешать запись между проектами. После проверки оригинального пакета и зависимостей пользователь может воспользоваться штатным ECC CLI либо зарегистрировать **оригинальный** локальный MCP. Пример из upstream `mcp-configs/mcp-servers.json`:

```json
{
  "ecc-memory-vault": {
    "command": "ecc-memory-mcp",
    "env": {"ECC_MEMORY_HARNESS": "codex"}
  }
}
```

Для каждого клиента используется собственная строчная `ECC_MEMORY_HARNESS`. При необходимости задать отдельные `ECC_MEMORY_PROJECT_ROOT` и `ECC_MEMORY_USER_ROOT`; **не включать** `ECC_MEMORY_ALLOW_USER_SCOPE=1` по умолчанию. MCP позволяет запись, поэтому требует отдельного разрешения на запись и видимость данных. Не подключать приватный Second Brain vault, настоящие переписки и рабочие секреты.

В upstream указаны дефекты нативной Windows-записи памяти; успешный синтетический CI не доказывает, что пользовательский Codex Desktop и Hermes Agent уже подключены. Откат - отключить только запись MCP в разрешённом интерфейсе и при необходимости удалить именно установленный ECC, не затрагивая чужие настройки или память.

**Статус:** чтение исходников, GitHub CI и реальный клиентский запуск оцениваются раздельно. Issue #433 остаётся OPEN до доказанной локальной приёмки.

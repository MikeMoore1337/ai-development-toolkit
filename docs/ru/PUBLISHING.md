# Публикация AI Development Toolkit

[English source](../PUBLISHING.md) | [Процесс релиза](RELEASE_PROCESS.md) | [Правила публикации](PUBLICATION_POLICY.md)

Официальный репозиторий [MikeMoore1337/ai-development-toolkit](https://github.com/MikeMoore1337/ai-development-toolkit) **уже существует** и имеет [выпуски GitHub Releases](https://github.com/MikeMoore1337/ai-development-toolkit/releases). Актуальную опубликованную версию проверяйте по списку релизов: изменения README или нетегированной `main` сами по себе не являются выпуском. **Не создавайте повторно** официальный репозиторий и не используйте скрипт первоначальной публикации для обычного сопровождения.

## Сопровождение существующего репозитория

1. Создайте ветку от актуальной `main` и Pull Request с проверкой изменений. Не переписывайте существующие теги и историю релизов.
2. Выполните проверки структуры, качества, происхождения, тестов и SHA256. Обновляйте реестр `SHA256SUMS.txt` командой `python scripts/verify_checksums.py --write` **только после просмотра точного diff**.
3. Перед разрешением на слияние необходим успешный GitHub Actions CI на **точном HEAD PR** для Linux и Windows. При изменении `main` перепроверьте актуальность ветки.
4. Изменения в `main` без тега остаются **Unreleased**. `MANIFEST.json.version` фиксирует базовую опубликованную версию до отдельно согласованного нового выпуска.

## Выпуск новой версии

Соблюдайте полный [порядок выпуска](RELEASE_PROCESS.md): release-mode проверка происхождения и прав, **явное согласование владельца для точного исходного дерева**, контрольные суммы, проверка архива и SHA тега. Зелёный CI **не даёт** разрешения на публикацию. Нельзя автоматически выбирать следующий номер, создавать тег или выпускать GitHub Release.

После публикации проверьте фактически скачанный ZIP, [workflow проверки архива](../RELEASE_PROCESS.md#independent-verification-of-a-github-source-archive) и сохраните результаты.

## Только для первого выпуска отдельного форка или нового репозитория

Устаревший для официального репозитория скрипт `scripts/publish_github.ps1` предназначен для первичной публикации: он проверяет файлы, запрашивает явное подтверждение `PUBLISH`, создаёт **публичный** GitHub-репозиторий и отправляет `main`. **Не применяйте его к уже опубликованному официальному Toolkit.** Для другого проекта отдельно изучите поведение скрипта и условия лицензирования. Не публикуйте личные лицензии, учётные данные или архивы прежних выпусков.

Настройки внешнего вида репозитория описаны в [руководстве GitHub](../GITHUB_SETUP.md).

**Границы доказательств:** публикация исходников и прохождение CI не доказывают работу независимых ИИ-агентов, совместимость реальных клиентов либо право на распространение сторонних материалов без надлежащих разрешений.

# План оценки практической полезности

[English source](../EVALUATION_PLAN_V4.md)

Нельзя утверждать, что система улучшилась, лишь потому что в ней стало больше навыков или тестов.

## Парные испытания

На одном и том же закреплённом SHA репозитория выполните репрезентативные задачи с одинаковой моделью, текстом задания, разрешениями, инструментами и бюджетом: сначала с v3, затем с v4. По возможности меняйте порядок запусков. Включите простое исправление UI, ошибку API, сложную функцию, восстановление контекста, импорт навыка и изменение с ограничениями на развёртывание.

Зафиксируйте:

- Достигнутые критерии приёмки с независимыми подтверждениями.
- Значимые регрессии и внесённые дефекты.
- Фактические согласования пользователя или препятствия.
- Общее использование модели и прошедшее время по телеметрии агента, если доступно; иначе - `unknown`.
- Лишние изменения файлов и дублирование документов.
- Доказательства активации навыка, а не только его наличия на диске.
- Корректное различение локального тестирования, CI и production.

Без повторных сопоставимых запусков выводы предварительны. Корректный пакет навыков сам по себе не гарантирует лучшую работу агента.

## Быстрые проверки по продуктам

- Codex: реальное обнаружение папки навыков проекта; один запуск по условию `feature-delivery` и один случай, когда навык **не** должен запускаться.
- Hermes: правильный профиль и домашний каталог навыков; независимое подтверждение фактической загрузки. Make Feature - только с учётом персональной лицензии.
- Claude Code: проверить поддерживаемый клиентом корень навыков и совместимость метаданных.
- GitHub: проверить, что `AGENTS.md` и CI продолжают обеспечивать ограничения выпуска, установленные конкретным проектом.

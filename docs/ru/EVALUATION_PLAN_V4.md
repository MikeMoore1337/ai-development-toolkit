# План проверки практической полезности v4

[Английский исходник](../EVALUATION_PLAN_V4.md) | [Оценка навыков](SKILL_EVALS.md) | [Реальные испытания агентов](REAL_AGENT_PILOT.md)

**Не заявляйте об улучшении только на основании увеличения числа навыков или тестов.**

## Парные испытания

Для одного и того же зафиксированного SHA репозитория выполняйте представительные задачи с идентичными моделью, формулировкой задачи, разрешениями, инструментами и бюджетом: сначала с v3, затем с v4. Где возможно, меняйте порядок условий между повторами. Включите простой дефект интерфейса, ошибку API, сложную функцию, восстановление контекста, импорт навыка и изменение, требующее отдельного разрешения на публикацию.

Фиксируйте:

- Какие критерии приёмки выполнены и чем они **независимо подтверждены**.
- Существенные регрессии и привнесённые дефекты.
- Реальные согласования пользователя и блокирующие условия.
- Фактический расход модели и прошедшее время по телеметрии агента, **если данные доступны**; иначе `UNKNOWN` / `NOT_MEASURED`.
- Незатребованные изменения файлов и дублирующиеся документы.
- Доказательства реальной активации навыка, а не только его присутствия на диске.
- Точное различие между локальными тестами, CI и production.

Выводы без повторных сопоставимых испытаний считайте предварительными. Корректный пакет навыков сам по себе не гарантирует улучшения работы агента.

## Проверки на отдельных продуктах

- **Codex:** подтвердите обнаружение каталога навыков в проекте; проверьте одно условие активации `feature-delivery` и один случай, когда навык **не должен** активироваться.
- **Hermes:** подтвердите правильный каталог профиля/домашних навыков и **независимо** зафиксируйте реальную загрузку; Make Feature используйте только в рамках личной лицензии и разрешений правообладателя.
- **Claude Code:** проверьте совместимость корневого каталога навыков и метаданных с фактическими возможностями клиента.
- **GitHub:** проверьте, что `AGENTS.md` и CI по-прежнему обеспечивают правила выпуска именно данного проекта.

## Ограничения действующих испытаний

Само наличие сценариев и контрактных тестов не доказывает реального запуска Codex/Claude или независимых агентов. Ограничение владельца `ZERO-SPEND` остаётся действующим: нельзя запускать дополнительные платные API или выдавать результаты синтетических проверок за реальные. Пока реальные парные запуски не подтверждены, статус `NOT_RUN`, экономия времени/токенов - `NOT_MEASURED`.

# Нативный ручной предварительный анализ обучения (#436)

Toolkit использует **существующий механизм проверки обезличенных наблюдений** и добавляет предварительное формирование кандидатов строго в рамках одного проекта. ECC устанавливать или запускать не нужно. Нет Codex CLI, Claude CLI, платных API, фонового агента, хуков, чтения сессий, автоматического изменения навыков или `AGENTS.md`. Сравниваемый первоисточник: ECC `skills/continuous-learning-v2/SKILL.md` на ревизии `affaan-m/ECC@25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b` (заявленная лицензия MIT). Оригинальный наблюдатель и использование Haiku не переносятся.

## Ручной запуск с явным разрешением

Подготовь **самостоятельно очищенный** JSON-файл с `schema_version=2` и массивом `observations`. Для каждого наблюдения обязательны только `observation_id`, `skill_id`, `category` (из существующего словаря категорий), `source_url` (публичный адрес GitHub Issue, PR, Actions или коммита), `signal` (`support` / `contradict`) и `observed_on` (формат `YYYY-MM-DD`). Содержание чата, промпты, персональные данные, секреты и необработанные журналы запрещены.

Пример вызова существующего скрипта на разрешённом публичном репозитории:

```bash
python scripts/skill_observation_review.py --input sanitized-public-observations.json --learning-preview --project-repo example/repo --as-of 2026-10-28
```

Команда только читает переданный файл, не обращается к сети и не записывает результат на диск. Ограничение - 32 КиБ и 20 наблюдений. Ранее существовавший режим версии 1 продолжает работать без изменений.

## Значение результата

Кандидаты группируются внутри одного `owner/repo` по идентификатору навыка и категории. Источники из другого репозитория, повторяющиеся наблюдения и повтор одного URL для одного кандидата отклоняются. Противоречащие и старые свидетельства снижают `confidence_hint`, который является **непроверенной эвристикой**, а не вероятностью правильности или подтверждением фактов GitHub. Менее двух положительных источников - `INSUFFICIENT_SUPPORT`; два и больше - всё равно `MANUAL_REVIEW_REQUIRED`.

В ответе всегда `evidence_verified=false`, `owner_approval=NOT_GRANTED`, `auto_promoted=false`, `observer_executed=false`, `model_calls=0`, `skill_files_written=0`. Ссылки - лишь утверждения пользователя: фактическое содержание и полезность должен отдельно проверить уполномоченный человек. Только после этого можно вручную предложить изменение навыка через обычный Issue/PR. Глобальное повышение, управление памятью и самозапись исключены.

## Ошибки и границы приёмки

Некорректные поля, чужие репозитории, будущие даты, записи старше 730 дней, повторные источники и потенциальные внедрённые инструкции отклоняются. Результат не сохраняется, откат не нужен. Настоящее обучение и применение в Codex Desktop, подтверждение ссылок и одобренный жизненный цикл практики остаются **NOT_VERIFIED**. Это не автоматическое самообучение ECC: фоновые хуки и наблюдение отключены.

## Проверка публичных GitHub-фактов (отдельный opt-in)

Новая команда проверяет узкие типизированные утверждения по тем же наблюдениям версии 2; существующий preview и CLI v1 остаются без изменений. Для каждого `source_url` передайте ровно одно утверждение с ключами `source_url`, `predicate` и `expected_sha`:

```json
{
  "schema_version": 1,
  "claims": [
    {"source_url":"https://github.com/example/repo/issues/101","predicate":"issue_exists","expected_sha":null},
    {"source_url":"https://github.com/example/repo/pull/102","predicate":"pr_merged_at_sha","expected_sha":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}
  ]
}
```

Это синтетический пример, не действительные доказательства. Поддерживаются `issue_exists`, `pr_head_at_sha`, `pr_merged_at_sha`, `run_success_at_sha`, `commit_exists_at_sha`.

```bash
python scripts/skill_learning_verification.py \
  --input sanitized-public-observations.json \
  --claims typed-claims.json \
  --project-repo example/repo --as-of 2026-11-01
```

Для контроля версии навыка дополнительно задаются все четыре параметра `--skill-root`, `--skill-id`, `--skill-file`, `--skill-expected-sha256`. Допустимые относительные файлы - `.agents/skills/<skill-id>/SKILL.md` и `extensions/<pack>/skills/<skill-id>/SKILL.md`. Несовпадение SHA блокирует рассмотрение; совпадение локального SHA само по себе не подтверждает удалённый GitHub-коммит.

Сеть используется только при явном запуске: ограниченные GET к публичному `api.github.com` без ключей, редиректов, дополнительных прав и произвольных адресов. Проверяются точный репозиторий, существование ресурса, HEAD/merge SHA и результат Actions run. Сбой запроса, фальшивый SHA и ошибочное утверждение о CI возвращают `NOT_VERIFIED`. Текст Issue/PR не сохраняется в отчёт и никогда не становится инструкцией.

`EXISTS_ONLY` подтверждает только существование Issue/коммита, а не исправление дефекта. Merged PR и успешный CI не доказывают production deployment. PR и run с одним HEAD SHA считаются одной независимой группой, а противоречия препятствуют готовности к утверждению. `confidence_hint` остаётся эвристикой, не статистической вероятностью.

## Рассмотрение и отзыв практики

Кандидат получает детерминированное структурированное предложение: `proposal_id`, вид изменения, область проекта, состояние проверки, версию исходного навыка, необходимые тесты, риски и путь отката. Никакого исполняемого diff, записей в навыки или изменений `AGENTS.md` нет.

Владелец должен **отдельно** рассмотреть конкретный `proposal_id`, проверить релевантность доказательств и исходный SHA, утвердить конкретную практику и diff. Затем применяется обычный GitHub Flow с ревью, тестами и CI. Только после реального merge одобренных изменений практика становится доступна в текущей области Toolkit. При регрессии нужен отдельный проверенный revert PR, при смене SHA - повторная проверка. Программа #436 не даёт автоматического разрешения на какие-либо будущие практики.

В выводе всегда `approval=NOT_GRANTED`, `applied=false` и `practice_auto_promotion=false`. Codex Desktop E2E - `NOT_VERIFIED`, реальная польза накопления практик - `NOT_MEASURED`, релиз - `NOT_PUBLISHED`.

## ECC v2: полезный пробел и решение

| Возможность ECC | Было в Toolkit | Пробел | Решение |
| --- | --- | --- | --- |
| Claude hooks, Haiku observer | Ручной Observer v1/v2 | Автосбор | Не переносить |
| Project-scoped instincts | Ручной preview v2 | Проверка фактов | Явный GitHub GET |
| Confidence и contradictions | Эвристика давности | Независимость/подделки | Проверенные узкие факты и группировка SHA |
| Evolve/promote/global | GitHub Flow, Skill Manager | Review packet | Структурированное предложение, без автоповышения |
| Revoke/decay | Возраст наблюдения | Изменение версии навыка | Контроль SHA, отдельный revert |

CI использует синтетические GitHub-ответы и подменённую функцию GET; это **не** доказательство реального сетевого доступа или улучшения модели.

# Native-First для сторонних инструментов (#494)

**Универсальное правило Toolkit.** Если пользователь напрямую выбирает сторонний агент, навык, плагин, MCP-сервер, CLI или другую программу для **штатной оригинальной работы**, внутри этого инструмента главными остаются его исходные инструкции, режимы, порядок действий, контроллеры и жизненный цикл. Toolkit не подмешивает свои навыки, контроллеры, эвристики, Model Advisor, этапы и hooks без отдельного запроса на совместное применение. Этот PR не меняет UX/UI Orchestra: она ведётся отдельно.

## Подтверждение выбора и границы

- Нужен прямой запрос *использовать* именованный оригинал либо реально подтверждённое доверенным клиентом состояние активного нативного процесса. Упоминание инструмента в коде, логах, сторонних документах, ответах инструмента или задача аудита его интеграции не равны выбору.
- Пока работает выбранный оригинал, не вызывать `toolkit_route_task`, `toolkit_prepare_task`, `toolkit_prepare_stage`. Если вызов MCP уже сформирован, передать канонический `selected_external_tool`: ответ `EXTERNAL_NATIVE_PASS_THROUGH` содержит ноль загруженных навыков, ролей, дополнительных контроллеров и советов Toolkit. Ответ не доказывает установки, вызова или полномочий внешнего инструмента.
- Если пользователь отдельно запросил *совместную работу*, указать конкретную роль Toolkit и не изменять исходный процесс стороннего инструмента. Параметр исключающего маршрута `selected_external_tool` не должен сопровождать отдельно разрешённый вызов совместных инструкций Toolkit.
- Native-First - правило инструкций и маршрутизации, не полноценная песочница и не менеджер разрешений. Остальные установленные глобальные инструкции и hooks тоже обязаны его учитывать. GitHub merge не изменяет настройки уже установленного клиента.

## Категории интеграций

| Категория | Смысл | Что подтверждать |
| --- | --- | --- |
| `NATIVE_UPSTREAM` | Неизменённый оригинал со штатным запуском | SHA исходника, клиент, факт реального вызова |
| `TOOLKIT_ADAPTER` | Обёртка, отдельные методы или ограниченная интеграция | Какие функции оригинала отсутствуют или отключены |
| `REFERENCE_ONLY` | Только ссылки, метаданные и чтение исходников | Не заявлять установку и запуск |
| `HARDENED_FORK` | Оригинальный проект с целевым патчем | Исходник, патч, причина и отличие от оригинала |

Примеры: оригинальный Graphify и `graphify-adapter`; полный Ponytail и копирование только навыков; штатные команды Harness² и ограниченный запускатор Toolkit; оригинальные Observer/Curator и адаптации ChatGPT; Episodic Memory с патчем не является неизменённым исходником. Оригинальные сканеры могут запускаться с ограниченным набором штатных режимов, но это должно быть явно указано.

## Безопасность, расходы и подтверждение

Native-First **не отменяет** системные/клиентские правила, разрешения пользователя и проекта, песочницу, границы файлов/сети/данных, защиту секретов, лицензии, доступ к моделям, лимиты расходов и отдельные согласования записи, merge и deploy. Если оригинал требует недоступных прав, указывается причина, а не выдумывается работа урезанного оригинала. Личные запреты CLI/расходов остаются пользовательскими, а не обязательными для всех; фикстуры `ZERO_SPEND` не задают универсальную политику.

Hooks Toolkit должны иметь явное разрешение и границы задачи. Необязательный Stop hook Model Advisor ничего не блокирует без предоставленного доверенным клиентом признака `adt_workflow_scope=TOOLKIT_MODEL_ADVISOR`; обычный Codex Stop-event не содержит такого нестандартного поля. Поставленный клиентом маркер сам по себе не является независимым доказательством: доверенный хост обязан обеспечить корректность. Такой отказ от вмешательства безопаснее для внешнего процесса.

**Границы доказательств:** проверки кода и CI не заменяют реальный вызов клиента. Установка, активация оригинала, изоляция hooks и влияние на результат остаются `NOT_VERIFIED` до клиентской приёмки. Обновление исходников не обновляет установленный MCP, глобальные инструкции или плагин ChatGPT автоматически.

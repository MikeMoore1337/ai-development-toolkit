# Начните без терминала

[English](../BEGINNER_START.md) | [Главная](../../README.ru.md) | [Техническая установка](INSTALLATION.md) | [Словарь](GLOSSARY.md)

**Чтобы обсудить идею или проверить предоставленные материалы, не нужно знать Python, Git, Agent Skills или пользоваться терминалом.** Изменение настоящего проекта, запуск тестов и публикация приложения - отдельные действия. Они возможны только с подходящими инструментами, доступом и разрешениями.

AI Development Toolkit - библиотека полезных инструкций и готовых наборов навыков. Это **не отдельный ИИ-клиент, не конструктор приложений одной кнопкой и не хостинг**. Прочитать эту страницу - не значит установить или активировать навыки. [Основной маршрут работы от идеи до результата](BEGINNER_WORKFLOW.md) остаётся единым; здесь объяснено, **куда перейти в первую очередь**. Незнакомые слова объяснены в [словаре](GLOSSARY.md).

**Уже есть проект?** Откройте краткую человеческую инструкцию [«Мой проект уже есть»](EXISTING_PROJECT.md): она объясняет, какие файлы прикрепить и как не раскрыть секреты. В ChatGPT и Claude кнопка загрузки может называться «+», «скрепка» или «Добавить файлы» и может отсутствовать в некоторых режимах. **Обычный чат** обсуждает доступные материалы; **Work** (если доступен) — отдельный режим для более длинных задач с доступными инструментами. Ни один из них не читает папки компьютера автоматически.

## Первый результат за три шага

1. **Скажите, какого результата хотите.** Выберите один из [шести примеров задач](#сначала-выберите-задачу) или опишите проблему своими словами. Не требуется знать язык программирования, название навыка или профиля.
2. **Предоставьте только необходимый доступ.** Для новой идеи достаточно описания. Для существующего проекта выберите [доступный способ работы](#выберите-способ-подключения) и передайте разрешённые файлы, ссылку на репозиторий или шаги воспроизведения. Не отправляйте пароли и токены.
3. **Проверьте реальный итог, а не обещание.** Спросите: *Что действительно прочитано или изменено? Какие проверки реально дали PASS/FAIL? Что осталось NOT_RUN?* Если нет доступа к проекту или инструментов исполнения, примите честный план либо подготовленные файлы, а не утверждение об исправленном и протестированном приложении.

**Один готовый пример:** «Перестала работать кнопка сохранения. Используй доступные тебе файлы проекта, найди причину, меняй только то, на что есть разрешение, и перечисли реальные проверки и всё со статусом NOT_RUN». Результатом может быть и диагноз или конкретный безопасный следующий шаг. Полные правила приёмки изложены в [существующем маршруте новичка](BEGINNER_WORKFLOW.md), отдельный процесс не нужен.

Если нужная функция недоступна, используйте [описанную альтернативу](#если-нужная-возможность-недоступна). Чтение инструкции само по себе не даёт доступ к файлам и не активирует навыки клиента.

**Статусы простыми словами:** `PASS` — проверка реально прошла; `FAIL` — реально выявлена ошибка; `NOT_RUN` — её не запускали; `NOT_VERIFIED` — нет подтверждения; `BLOCKED` — недоступна из-за условий; `GUIDANCE_ONLY` — прочитана инструкция, но навык не обязательно применён. `MCP` — способ предоставить ИИ инструменты, `профиль` — набор инструкций. `--apply` означает согласованную запись после просмотра изменений; для чата он не нужен. [Пример с готовым проектом](EXISTING_PROJECT.md).

## Сначала выберите задачу

Скопируйте один запрос в ИИ-клиент, которому доступны необходимые материалы. **Не требуется знать названия навыков, выбирать профиль или пользоваться терминалом.** Эти примеры не открывают доступ к файлам, не запускают установку и не означают, что тесты уже выполнены.

| Что нужно | Готовый запрос | Подробности |
| --- | --- | --- |
| **Код** | «Добавь одну небольшую функцию в мой проект. Сначала изучи его, затем покажи изменения и результаты только действительно выполненных тестов». | [Пошаговый процесс](BEGINNER_WORKFLOW.md) |
| **QA** | «Проверь самые рискованные изменения проекта, включая негативные сценарии. Укажи доказательства и тесты, которые не запускались». | [Проверка изменений](QA_CHANGE_IMPACT.md) |
| **Дизайн** | «Покажи разные визуальные композиции сайта для компьютера и телефона. До изменения интерфейса покажи настоящий макет на согласование». | [UX/UI-дизайн](UX_UI_DESIGN.md) |
| **SEO** | «Проверь SEO доступных страниц моего сайта. Отдели обнаруженные проблемы от предположений и расставь исправления по важности». | [SEO-проверка](PROMPT_AND_SEO_SKILLS.md) |
| **Исследование** | «Изучи мой вопрос по доступным надёжным источникам. Отдели подтверждённые факты от неопределённости и рекомендаций». | [Проверка источников](../../.agents/skills/research-verification/SKILL.md) |
| **Сопровождение** | «Проверь известные проблемы и риски моего проекта. Предложи безопасные дальнейшие действия, не включая автоматические обновления и наблюдение». | [Процесс для новичка](BEGINNER_WORKFLOW.md) |

Шесть строк выше - это **шесть категорий задач** для быстрого выбора. [Пять готовых запросов](#пять-готовых-запросов) - **пять подробных сценариев**, а не дополнительные обязательные шаги или отдельная установка. Для начала достаточно одного подходящего запроса. [Полный каталог навыков](SKILLS_CATALOG.md) нужен только для справки, **а не для старта**.

## Выберите способ подключения

Выберите **один** вариант по реально доступным инструментам и разрешениям. Ни один из вариантов не считается более важным. Toolkit предоставляет инструкции, но не выдаёт дополнительных прав и не запускает отдельную модель.

| Вариант | С чего начать | Что действительно подтверждается |
| --- | --- | --- |
| **Чат без установки** | Опишите задачу в ChatGPT или Claude, приложите доступные материалы; см. [работу в чате](BEGINNER_WORKFLOW.md). | Можно получить рекомендации по прочитанным источникам. Доступ к ссылке или файлам надо проверить; вставка ссылки не устанавливает навыки. |
| **Установленный плагин ChatGPT** | Откройте *отдельно подключённый* плагин Toolkit и сформулируйте задачу; см. [правила источников плагина](../../AGENT_START.ru.md). | Путь работает только при фактическом подключении плагина. Обновление инструкций с GitHub не является обновлением самого плагина и не доказывает использование навыка. |
| **Toolkit MCP для Codex или Claude Code** | Откройте [инструкцию MCP](MCP_INSTALL.md), проверьте план конфигурации проекта и отдельно разрешите `--apply` при необходимости. | MCP даёт доступ к инструкциям и рекомендациям без записи; наличие конфигурации не доказывает, что клиент обнаружил и вызвал инструменты. |
| **Локальные навыки Codex или Claude Code** | Пройдите [проверку проекта](PROJECT_ADOPTION_PREFLIGHT.md) и изучите [план установки](INSTALLATION.md) до отдельного `--apply`. | Копирование файлов не подтверждает обнаружение и применение навыков. Правила проекта и пользовательские файлы важнее предлагаемых профилей. |

**Быстрый выбор:** нужно только обсудить задачу - начните с чата. Плагин Toolkit уже подключён - используйте его. Нужны инструкции в IDE без копирования файлов - выберите MCP. Нужны установленные файлы навыков внутри проекта - используйте Skill Manager после предпросмотра и разрешения. Это альтернативы, **а не четыре последовательных шага установки**.

**Граница доказательств:** чтение инструкции, настройка подключения, обнаружение навыка клиентом, его реальное применение и проверка приложения - **разные факты**. Пока реальных испытаний нет, обнаружение, использование и польза навыка - **NOT_TESTED**. Ни один маршрут не разрешает автоматически публикацию, платные сервисы или внешние действия.

## Хотите новый дизайн, но не умеете писать промпты?

Можно просто написать: **«Хочу красивый сайт для фитнес-клуба».** Если Codex получил доступ к инструкциям Toolkit, он должен распознать дизайн-задачу, проверить открытый проект (если он доступен) и самостоятельно выбрать режим `create-design` в UX/UI Design Orchestra. Не нужно знать названия навыков, устройство сайта или термины UX. Допустимы максимум два важных вопроса. Затем агент явно обозначает предположения и создаёт три разных черновых макета для сравнения. После просмотра эскизов он готовит подробные версии выбранного направления для компьютера и телефона. Эскизы и макеты считаются созданными только при реальном использовании инструментов визуализации; без них агент сообщает, что визуальное сравнение не выполнено, и предлагает текстовый план. Код существующего сайта не меняется до согласования визуальной версии. [Руководство по дизайну](UX_UI_DESIGN.md).

## Уже открыли локальный проект в IDE с Codex?

Самый короткий маршрут: откройте свой проект в IDE и напишите «Используй https://github.com/MikeMoore1337/ai-development-toolkit, чтобы добавить тесты в текущем проекте». Специальный шаблон, установка или URL своего проекта не нужны. [Инструкция агента](../../AGENT_START.ru.md) разделяет роли: Toolkit используется **только для чтения**, код, тесты и отчёты относятся к пользовательскому проекту, если этого требует задача, либо возвращаются в чат или выбранное место. **Чужие материалы никогда не записываются в Toolkit.**

## Выберите ИИ-клиент

**Для первого знакомства достаточно одного варианта.** Чат анализирует предоставленные материалы; Codex и Claude Code могут менять код только при наличии доступа к проекту и разрешений. Подробные инструкции, сравнительную таблицу, ссылки на официальные источники и ограничения перенесли в [справочник по клиентам](BEGINNER_CLIENT_DETAILS.md).

| Где хотите работать | Самый короткий старт |
| --- | --- |
| **ChatGPT или Claude, обычный чат** | Приложите разрешённые файлы через «+» / скрепку, если функция доступна; иначе вставьте относящиеся к задаче фрагменты |
| **ChatGPT Work** | **Work** — отдельный режим выполнения более сложных задач с доступными инструментами и подключениями, а не название обычного чата; доступность проверяйте в аккаунте |
| **Codex или Claude Code** | Откройте нужный проект и дайте инструкцию Toolkit; убедитесь, что клиент действительно видит файлы проекта и имеет необходимые разрешения |

Отправленная ссылка на Toolkit не даёт доступ к файлам вашего проекта и не устанавливает навыки. Если функция клиента недоступна, используйте разрешённые вложения, фрагменты или [простой маршрут существующего проекта](EXISTING_PROJECT.md). **Синхронизация инструкций, установка, обнаружение навыка и проверка исправления — разные действия.**

## Пять готовых запросов

Скопируйте **один** текст в выбранный ИИ-клиент. Не нужно разбираться в именах навыков. Подробный [единый семиэтапный маршрут](BEGINNER_WORKFLOW.md) остаётся технической основой.

### A. Хочу приложение

```text
Хочу сделать небольшое приложение, но не умею программировать. Помоги выбрать минимальную полезную версию, объясни её простыми словами и выполни только действия, на которые у тебя есть инструменты и мои разрешения. Не подключай платные сервисы и не публикуй ничего без согласования. Расскажи, как открыть результат и что действительно удалось проверить.
```

**Цель:** идея -> MVP -> простая реализация -> проверка. **Входные данные:** идея и её будущий пользователь. **Результат:** небольшой проверенный проект только при наличии coding-среды, иначе спецификация или подготовленные файлы. **Ограничения:** никакой автоматической публикации и оплаты. **Проверка:** одно основное действие, некорректный ввод и реальные шаги запуска; без исполнения - `NOT_RUN`. **При блокировке:** сначала подготовьте одностраничное MVP с критериями приёмки.

### B. Проверь проект

```text
Проверь мой проект и объясни простыми словами, что уже готово и что нужно исправить. Найди только проблемы с реальными доказательствами, раздели критичные и незначительные, предложи порядок работы. Не меняй файлы без моего разрешения. Если доступа к проекту нет, скажи, какие материалы нужны.
```

**Цель:** доступ -> диагностика -> доказательства -> приоритеты. **Входные данные:** разрешённый репозиторий, файлы или небольшой архив. **Результат:** проверенный по доступным материалам аудит. **Ограничения:** без изменений файлов по умолчанию. **Проверка:** у каждого важного вывода есть файл, путь, лог или тест; неизвестное явно указано. **При блокировке:** запросите минимальный артефакт, например README и лог ошибки.

### C. Исправь ошибку

```text
В моём приложении перестала работать функция. Сначала выясни ожидаемое и фактическое поведение, изучи доступный проект и попробуй воспроизвести проблему, если есть инструменты. Исправь только подтверждённую причину с минимальными изменениями, выполни доступные регрессионные проверки. Объясни, что проверить не удалось.
```

**Цель:** ожидаемое/фактическое -> воспроизведение -> причина -> исправление -> регрессия. **Входные данные:** шаги, ошибка/лог, доступ к нужным файлам. **Результат:** проверенное исправление, только если действительно выполнены правки и тесты, иначе диагностика или предложение патча. **Ограничения:** нельзя объявлять ошибку исправленной по одному обсуждению. **Проверка:** до/после и смежный сценарий со статусами. **При блокировке:** запросите шаги воспроизведения или лог.

### D. Добавь функцию

```text
Хочу добавить одну функцию в существующее приложение. Сначала изучи текущую реализацию, опиши небольшое проверяемое поведение и объясни минимальные изменения. Только затем внеси разрешённые правки и выполни тесты. Укажи затронутые файлы и фактические результаты. Не запускай несколько контроллеров реализации функции одновременно.
```

**Цель:** текущий проект -> требования -> критерии -> код -> тесты. **Входные данные:** доступный проект и описание поведения. **Результат:** проверенная разница файлов либо план. **Ограничения:** не запускать вместе feature-delivery и Make Feature. **Проверка:** критерий новой функции и сохранение соседнего поведения. **При блокировке:** сначала запишите два примера ожидаемого поведения.

### E. Сопровождай приложение

```text
Помоги поддерживать моё приложение: изучи доступные материалы, найди подтверждённые проблемы, расставь риски по приоритету и предложи безопасный план сопровождения. Не запускай наблюдение, автоматические изменения, обновления и платные сервисы без моего явного согласия. Укажи, чего ты не можешь проверить.
```

**Цель:** инвентаризация -> состояние -> риски -> план. **Входные данные:** разрешённые документы, код, известные ошибки, зависимости. **Результат:** приоритизированный план и возможные проверки. **Ограничения:** никаких обещаний постоянного мониторинга без реально настроенного механизма. **Проверка:** у каждого риска есть доказательство, ответственный и следующий проверяемый шаг. **При блокировке:** запросите актуальный снимок проекта или список задач.

## Если нужная возможность недоступна

| Ситуация | Безопасный результат и один следующий шаг |
| --- | --- |
| Клиент не запускает команды | Не объявлять тесты успешными; подготовить команды для разрешённой среды |
| Не предоставлен проект или файлы | Не выдумывать аудит; запросить необходимый README, код или лог |
| Ожидание, что ChatGPT сам обнаружит локальные навыки Codex | Объяснить разные механизмы Skills; не заявлять активацию |
| Публикация без согласия владельца | Остановиться; запросить явное разрешение и проверить среду |
| Платная функция недоступна | Продолжить текстовый план, не оформлять платные услуги |
| Нет терминала | Использовать чат или интерфейс, не выдавать это за установку менеджером |
| Код получен, но тесты не запущены | Указать `NOT_RUN` и предложить проверяемые шаги запуска |
| Нет прав доступа к репозиторию | Запросить конкретное разрешение или небольшой архив |
| Клиент не поддерживает каталог навыков | Применить документированный способ или использовать инструкции как текст |
| Существующие чужие навыки конфликтуют | Остановиться; сохранить файлы и проверить владельца, не перезаписывать |
| Нет механизма постоянного сопровождения | Подготовить чеклист; не обещать фоновое наблюдение |

## Разрешения и безопасная остановка

| Уровень | Примеры | Правило |
| --- | --- | --- |
| Безопасное изучение | Читать инструкции, выбирать задачу, обсуждать план, проверять доступные сведения | Можно начинать без установки; не раскрывайте секреты |
| Изменение с разрешением | Создать или изменить файлы, установить профиль/зависимости, выполнить команду, затрагивающую проект | Сначала проверьте папку, план изменений и права; затем подтвердите конкретное действие |
| Повышенный риск | Удалить данные, необратимо мигрировать базу, опубликовать код, развернуть production, потратить деньги, передать приватные материалы | **Остановиться и запросить явное разрешение** согласно правилам владельца проекта |

**Четыре разных подтверждения:** (1) *файлы Toolkit подготовлены* - проверена установка или копирование; (2) *клиент обнаружил навык* - наблюдение внутри конкретного клиента; (3) *навык использован* - наблюдение активации в задаче; (4) *приложение работает* - проверено соответствующее поведение. Ни один уровень сам по себе не доказывает следующий. В данной Issue возможен PASS для офлайновых проверок документации, но обнаружение навыков - **NOT_TESTED**, использование - **NOT_TESTED**, эффективность - **NOT_MEASURED**, независимая проверка новичками - **NOT_TESTED**.

Если вы используете только телефон/браузер, не можете устанавливать программы, передавать проект, запускать команды или не имеете разрешения изменять файлы - **остановитесь на честном плане, подготовленном коде или отчёте**. Не просите ИИ придумывать результаты тестов либо обходить ограничения владельца. При ошибке сохраните файлы и сообщения, проверьте изменения и выберите минимальный обратимый шаг.

## Необязательная локальная установка

**Только при наличии** Python 3.12+, копии Toolkit, существующей доверенной папки проекта и возможности выполнять команды. Из корня Toolkit:

```bash
python scripts/adt.py profile list
python scripts/adt.py doctor --target /path/to/project
python scripts/adt.py profile plan --target /path/to/project --task qa
python scripts/adt.py init --target /path/to/project --profile general
# Только после проверки плана и разрешения:
python scripts/adt.py init --target /path/to/project --profile general --apply
python scripts/adt.py status --target /path/to/project
```

Для Claude Code добавьте `--layout claude` к соответствующим командам с `--target`. В Windows можно использовать `py -3` и путь Windows. Менеджер не перезаписывает чужие навыки; успешный `status` **не подтверждает активацию**. Подробнее: [установка](INSTALLATION.md), [перенос и восстановление](CLIENT_MIGRATION.md), [офлайновая совместимость](CLIENT_COMPATIBILITY.md). Материалами Toolkit можно пользоваться без установки, но это **использование инструкций как текста**, а не управляемое подключение навыков.

Два предоставленных владельцем отчёта о прохождении трёх заданий новичками выявили затруднения навигации; изменения задокументированы в [Issue #333](https://github.com/MikeMoore1337/ai-development-toolkit/issues/333). Отчёты и результаты проверки в клиенте — **разные типы свидетельств**. Офлайновые тесты не измеряют скорость или самостоятельность человека и не заменяют дальнейшую пользовательскую проверку.

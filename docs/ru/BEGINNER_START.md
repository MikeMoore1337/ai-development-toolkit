# Начните без терминала

[English](../BEGINNER_START.md) | [Главная](../../README.ru.md) | [Техническая установка](INSTALLATION.md) | [Словарь](GLOSSARY.md)

**Чтобы обсудить идею или проверить предоставленные материалы, не нужно знать Python, Git, Agent Skills или пользоваться терминалом.** Изменение настоящего проекта, запуск тестов и публикация приложения - отдельные действия. Они возможны только с подходящими инструментами, доступом и разрешениями.

AI Development Toolkit - библиотека полезных инструкций и готовых наборов навыков. Это **не отдельный ИИ-клиент, не конструктор приложений одной кнопкой и не хостинг**. Прочитать эту страницу - не значит установить или активировать навыки. [Основной маршрут работы от идеи до результата](BEGINNER_WORKFLOW.md) остаётся единым; здесь объяснено, **куда перейти в первую очередь**. Незнакомые слова объяснены в [словаре](GLOSSARY.md).

## Уже открыли локальный проект в IDE с Codex?

Это самый короткий маршрут для **существующего проекта**: откройте папку в IDE и напишите «Используй AI Development Toolkit в этом проекте, чтобы выполнить мою задачу». Не нужно искать GitHub URL проекта, публиковать его или вручную устанавливать набор навыков. [Инструкция для агента](../../AGENT_START.ru.md) описывает разрешённое подключение Toolkit: сам агент должен иметь доступ к рабочей папке и проверенному источнику; наличие ссылки или копирование файлов ещё не подтверждает реального применения навыка. Две ссылки остаются дополнительным вариантом для удалённого проекта.

## Четыре первых действия

1. **Выберите ИИ-клиент** в [таблице](#выберите-ии-клиент). Для первого обсуждения идеи проще начать с ChatGPT или Claude в браузере.
2. **Выберите одну задачу** среди [пяти готовых запросов](#пять-готовых-запросов). Не нужно предварительно выбирать язык программирования, профиль или навык.
3. **Предоставьте только необходимое**: для идеи достаточно описания; для существующего приложения нужны доступные файлы, репозиторий или точные сведения об ошибке. Не отправляйте пароли и токены.
4. **Проверьте, что произошло в действительности**. Спросите, какие файлы прочитаны и изменены, какие тесты запущены. План или код в сообщении ещё не означает работающего приложения.

Если нужной функции нет в вашем аккаунте, **ограничьтесь планом и безопасной альтернативой**. Интерфейсы и поддержка Agent Skills у разных клиентов не одинаковы.

## Выберите ИИ-клиент

| Клиент и режим | Самый простой путь | Может изменить приложение? | Может запустить тесты? | Навыки Toolkit | Терминал |
| --- | --- | --- | --- | --- | --- |
| [OpenAI Codex](#openai-codex), облачная среда | Выбрать подготовленный GitHub-проект в Codex Cloud | Да, в доступной облачной копии; локальный режим Desktop может работать с выбранной папкой | Да, при наличии инструментов, зависимостей и разрешений | Для Codex документирован каталог `.agents/skills`, но его нужно реально добавить в нужный проект | **Не нужен** для работы через настроенный облачный интерфейс; локальная установка через менеджер Toolkit требует CLI |
| [ChatGPT](#chatgpt), Chat / Work | Открыть чат или доступный Work, приложить материалы | Chat готовит тексты и файлы; Work может изменять доступные ему источники при наличии подключений и разрешений | Только в режиме с реальными инструментами исполнения, не гарантируется в обычном чате | Skills рабочего пространства и плагины **не равны** локальным `SKILL.md` Toolkit; автоматическое подключение не подтверждено | **Не нужен** для обсуждения и загрузки файлов |
| [Claude Code](#claude-code), Desktop Code / облако | Открыть вкладку Code и выбрать существующий проект или доступную облачную среду | Да, внутри разрешённого проекта/сеанса | Да, если доступны инструменты исполнения и зависимости | Поддерживается `.claude/skills`; установка менеджером Toolkit - отдельная операция CLI | **Не нужен** для уже настроенной Desktop-сессии, но установка и зависимости могут требовать команд |
| [Claude](#claude), чат / Projects | Начать диалог или Project и загрузить нужные материалы | Готовит текст и артефакты; не получает автоматически доступ к локальному проекту | В доступном режиме с включённым исполнением кода, не тесты локального репозитория по умолчанию | Пользовательские навыки можно загрузить **ZIP-архивом через Customize > Skills** при наличии функции | **Не нужен** для чата или поддерживаемой загрузки ZIP; подготовка ZIP может потребовать отдельного шага |

Это **проверенные по документации возможности на 20.10.2026**, а не результат запуска четырёх клиентов. Доступность зависит от тарифа, региона, платформы, настроек организации и разрешений. Если кнопка отсутствует, не считайте это ошибкой пользователя. Для чтения этого руководства платные API не нужны; доступ к отдельным возможностям клиента нужно уточнять по своему аккаунту.

### OpenAI Codex

**Подходит:** если нужно действительно менять код в GitHub-репозитории или локальном проекте.

1. Откройте [Codex Cloud](https://learn.chatgpt.com/docs/cloud) в браузере или Desktop. При необходимости подключите разрешённый GitHub-репозиторий. Новую облачную среду можно подготовить и опубликовать **после проверки её настроек и полномочий**. Если среда уже готова, используйте её. На телефоне можно выбрать существующую среду; первоначальная настройка описана для браузера и Desktop.
2. Выберите среду и вставьте один [готовый запрос](#пять-готовых-запросов). Сразу запретите публикацию, платные действия и развёртывание без согласования. Перед коммитом или PR изучите изменения и результаты тестов.
3. **Чтобы применить навыки Toolkit**, соответствующие каталоги должны действительно находиться в нужном репозитории по пути `.agents/skills/<имя-навыка>/SKILL.md`. Чтение README Toolkit не подключает навыки к чужому проекту. Используйте [существующий CLI](#необязательная-локальная-установка) в подходящей среде или попросите уполномоченного coding-агента подготовить изменения для проверки.
4. Нет доступа к репозиторию или подготовленной среде? Получите описание минимальной версии приложения и список файлов, а не фиктивный отчёт об изменениях.

**Терминал:** необязателен для подготовленного облачного интерфейса; для самостоятельного запуска локального менеджера `adt.py` он нужен. Codex Desktop может работать с выбранными локальными папками, но требует установленного приложения и доступа к файловой системе. Доступность и лимиты уточняются в аккаунте OpenAI; бесплатность выполнения не гарантируется.

**Официальные источники (проверено 20.10.2026):** [Codex Cloud](https://learn.chatgpt.com/docs/cloud), [каталоги навыков Codex](https://learn.chatgpt.com/docs/build-skills), [различия ChatGPT и Codex](https://help.openai.com/en/articles/20001275). **Не проверено:** обнаружение, фактическое применение и полезность навыков в работающей сессии.

### ChatGPT

**Подходит:** для обсуждения идеи, анализа доступных документов, планирования приложения и проверки кода теми средствами, которые реально включены в выбранном режиме.

1. Откройте [ChatGPT](https://chatgpt.com/). Используйте обычный Chat или доступный вам Work. При необходимости создайте Project для связанных бесед и файлов; загружайте только разрешённые материалы.
2. Вставьте [готовый запрос](#пять-готовых-запросов). Попросите перечислить **фактически доступные инструменты**. Обычный чат может подготовить код или файл, но это не означает изменение либо тестирование вашего репозитория.
3. Если доступен Work и вы предоставили ему доступ к репозиторию, подключённому приложению или локальной папке через Desktop, можно отдельно разрешить конкретные изменения. Work в браузере и на телефоне **не получает автоматически доступ к файлам на компьютере**. Проверяйте подтверждение записи и результаты тестов.
4. **Навыки Toolkit:** переданные в чат инструкции могут служить контекстом, но наличие локального навыка для Codex или загруженного README не доказывает его обнаружение ChatGPT. Skills рабочего пространства и плагины имеют **свои механизмы установки и разрешений**.

**Альтернатива:** если Work, запись файлов или доступ к репозиторию недоступны, получите спецификацию или готовые файлы для последующего применения, а тесты отметьте `NOT_RUN`. Для этого терминал не нужен.

**Официальные источники (проверено 20.10.2026):** [работа с ChatGPT](https://learn.chatgpt.com/docs/use-chatgpt), [ChatGPT Work и Codex](https://help.openai.com/en/articles/20001275), [раздельные механизмы Skills](https://learn.chatgpt.com/docs/enterprise/skills), [доступ ChatGPT к GitHub](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt-drease). **Не подтверждено:** автоматическое подключение локальных Toolkit skills в обычном чате.

### Claude Code

**Подходит:** для работы с существующим кодом через ИИ-агента, которому разрешён доступ к проекту.

1. Откройте [Claude Desktop Code](https://code.claude.com/docs/en/desktop), выберите вкладку Code и локальную папку/сеанс либо доступную облачную среду. Проверьте запросы доверия к проекту и разрешения. Для локального интерфейса нужно установленное Desktop-приложение, но запуск из терминала - не единственный способ.
2. Опишите одну задачу, запросите изучение проекта и небольшой план до изменений, затем проверьте разницу файлов и фактический вывод тестов. Локальная настройка проекта и зависимости могут требовать выполнения команд, даже если человек пользуется только интерфейсом.
3. Текущий менеджер Toolkit с `--layout claude` устанавливает навыки в `.claude/skills/<имя-навыка>/SKILL.md`. Клиент документирует такой каталог, но копирование подтверждает только состояние файлов, а не реальное использование. Синхронизируемые навыки аккаунта claude.ai - другой механизм; облачная сессия не наследует произвольные локальные каталоги.
4. Нет Desktop, прав на установку, проекта или средств исполнения? Подготовьте предложение изменений или перейдите в доступную разрешённую среду разработки.

**Официальные источники (проверено 20.10.2026):** [Desktop для Claude Code](https://code.claude.com/docs/en/desktop), [навыки и область видимости](https://code.claude.com/docs/en/skills). **Не проверено:** обнаружение и использование навыков Toolkit в живом Claude Code.

### Claude

**Подходит:** для идей, анализа загруженных файлов, описаний функций и подготовки артефактов.

1. Откройте [Claude](https://claude.ai/), начните диалог или Project и добавьте краткое описание либо разрешённые файлы. Projects помогают хранить контекст, но не дают автоматически доступ к локальному репозиторию.
2. Вставьте [готовый запрос](#пять-готовых-запросов). Попросите указать, что **не менялось** и **не выполнялось**.
3. **Дополнительный путь Skills через интерфейс:** если доступно `Customize > Skills` и включены исполнение кода/создание файлов, Anthropic документирует загрузку **ZIP с каталогом навыка и SKILL.md**. Сначала проверьте исходники и содержимое архива. Это **не установка менеджером Toolkit** и не гарантия поддержки для любого аккаунта. Загружайте только минимальный разрешённый навык, не весь Toolkit, не защищённые или личные файлы; учитывайте ограничения организации.
4. Если загрузка навыков недоступна, вставьте небольшой несекретный фрагмент руководства в чат. Для реальных изменений в репозитории при отсутствии инструмента записи понадобится другая разрешённая среда разработки.

**Официальные источники (проверено 20.10.2026):** [Claude Projects](https://support.claude.com/en/articles/9517075-what-are-projects), [пользовательские навыки Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude), [структура ZIP навыка](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills). **Не проверено:** успешная загрузка, обнаружение или использование конкретного архива навыка Toolkit.

## Пять готовых запросов

Скопируйте **один** текст в выбранный ИИ-клиент. Не нужно разбираться в именах навыков. Подробный [единый семиэтапный маршрут](BEGINNER_WORKFLOW.md) остаётся технической основой.

### A. Хочу приложение

```text
Хочу сделать небольшое приложение, но не умею программировать. Помоги выбрать минимальную полезную версию, объясни её простыми словами и выполни только действия, на которые у тебя есть инструменты и мои разрешения. Не подключай платные сервисы и не публикуй ничего без согласования. Расскажи, как открыть результат и что действительно удалось проверить.
```

**Цель:** идея -> MVP -> простая реализация -> проверка. **Входные данные:** идея и её будущий пользователь. **Результат:** небольшой проверенный проект только при наличии coding-среды, иначе спецификация или подготовленные файлы. **Ограничения:** никакой автоматической публикации и оплаты. **Проверка:** одно основное действие, некорректный ввод и реальные шаги запуска; без исполнения - `NOT_RUN`. **При блокировке:** сначала подготовьте одностраничное MVP с критериями приёмки.

### B. Проверь проект

```text
Проверь мой проект и объясни простыми словами, что уже готово и что нужно исправить. Найди только проблемы с реальными доказательствами, раздели критичные и незначительные, предложи порядок работы. Не меняй файлы без моего разрешения. Если доступа к проекту нет, скажи, какие материалы нужны.
```

**Цель:** доступ -> диагностика -> доказательства -> приоритеты. **Входные данные:** разрешённый репозиторий, файлы или небольшой архив. **Результат:** проверенный по доступным материалам аудит. **Ограничения:** без изменений файлов по умолчанию. **Проверка:** у каждого важного вывода есть файл, путь, лог или тест; неизвестное явно указано. **При блокировке:** запросите минимальный артефакт, например README и лог ошибки.

### C. Исправь ошибку

```text
В моём приложении перестала работать функция. Сначала выясни ожидаемое и фактическое поведение, изучи доступный проект и попробуй воспроизвести проблему, если есть инструменты. Исправь только подтверждённую причину с минимальными изменениями, выполни доступные регрессионные проверки. Объясни, что проверить не удалось.
```

**Цель:** ожидаемое/фактическое -> воспроизведение -> причина -> исправление -> регрессия. **Входные данные:** шаги, ошибка/лог, доступ к нужным файлам. **Результат:** проверенное исправление, только если действительно выполнены правки и тесты, иначе диагностика или предложение патча. **Ограничения:** нельзя объявлять ошибку исправленной по одному обсуждению. **Проверка:** до/после и смежный сценарий со статусами. **При блокировке:** запросите шаги воспроизведения или лог.

### D. Добавь функцию

```text
Хочу добавить одну функцию в существующее приложение. Сначала изучи текущую реализацию, опиши небольшое проверяемое поведение и объясни минимальные изменения. Только затем внеси разрешённые правки и выполни тесты. Укажи затронутые файлы и фактические результаты. Не запускай несколько контроллеров реализации функции одновременно.
```

**Цель:** текущий проект -> требования -> критерии -> код -> тесты. **Входные данные:** доступный проект и описание поведения. **Результат:** проверенная разница файлов либо план. **Ограничения:** не запускать вместе feature-delivery и Make Feature. **Проверка:** критерий новой функции и сохранение соседнего поведения. **При блокировке:** сначала запишите два примера ожидаемого поведения.

### E. Сопровождай приложение

```text
Помоги поддерживать моё приложение: изучи доступные материалы, найди подтверждённые проблемы, расставь риски по приоритету и предложи безопасный план сопровождения. Не запускай наблюдение, автоматические изменения, обновления и платные сервисы без моего явного согласия. Укажи, чего ты не можешь проверить.
```

**Цель:** инвентаризация -> состояние -> риски -> план. **Входные данные:** разрешённые документы, код, известные ошибки, зависимости. **Результат:** приоритизированный план и возможные проверки. **Ограничения:** никаких обещаний постоянного мониторинга без реально настроенного механизма. **Проверка:** у каждого риска есть доказательство, ответственный и следующий проверяемый шаг. **При блокировке:** запросите актуальный снимок проекта или список задач.

## Если нужная возможность недоступна

| Ситуация | Безопасный результат и один следующий шаг |
| --- | --- |
| Клиент не запускает команды | Не объявлять тесты успешными; подготовить команды для разрешённой среды |
| Не предоставлен проект или файлы | Не выдумывать аудит; запросить необходимый README, код или лог |
| Ожидание, что ChatGPT сам обнаружит локальные навыки Codex | Объяснить разные механизмы Skills; не заявлять активацию |
| Публикация без согласия владельца | Остановиться; запросить явное разрешение и проверить среду |
| Платная функция недоступна | Продолжить текстовый план, не оформлять платные услуги |
| Нет терминала | Использовать чат или интерфейс, не выдавать это за установку менеджером |
| Код получен, но тесты не запущены | Указать `NOT_RUN` и предложить проверяемые шаги запуска |
| Нет прав доступа к репозиторию | Запросить конкретное разрешение или небольшой архив |
| Клиент не поддерживает каталог навыков | Применить документированный способ или использовать инструкции как текст |
| Существующие чужие навыки конфликтуют | Остановиться; сохранить файлы и проверить владельца, не перезаписывать |
| Нет механизма постоянного сопровождения | Подготовить чеклист; не обещать фоновое наблюдение |

## Разрешения и безопасная остановка

| Уровень | Примеры | Правило |
| --- | --- | --- |
| Безопасное изучение | Читать инструкции, выбирать задачу, обсуждать план, проверять доступные сведения | Можно начинать без установки; не раскрывайте секреты |
| Изменение с разрешением | Создать или изменить файлы, установить профиль/зависимости, выполнить команду, затрагивающую проект | Сначала проверьте папку, план изменений и права; затем подтвердите конкретное действие |
| Повышенный риск | Удалить данные, необратимо мигрировать базу, опубликовать код, развернуть production, потратить деньги, передать приватные материалы | **Остановиться и запросить явное разрешение** согласно правилам владельца проекта |

**Четыре разных подтверждения:** (1) *файлы Toolkit подготовлены* - проверена установка или копирование; (2) *клиент обнаружил навык* - наблюдение внутри конкретного клиента; (3) *навык использован* - наблюдение активации в задаче; (4) *приложение работает* - проверено соответствующее поведение. Ни один уровень сам по себе не доказывает следующий. В данной Issue возможен PASS для офлайновых проверок документации, но обнаружение навыков - **NOT_TESTED**, использование - **NOT_TESTED**, эффективность - **NOT_MEASURED**, независимая проверка новичками - **NOT_TESTED**.

Если вы используете только телефон/браузер, не можете устанавливать программы, передавать проект, запускать команды или не имеете разрешения изменять файлы - **остановитесь на честном плане, подготовленном коде или отчёте**. Не просите ИИ придумывать результаты тестов либо обходить ограничения владельца. При ошибке сохраните файлы и сообщения, проверьте изменения и выберите минимальный обратимый шаг.

## Необязательная локальная установка

**Только при наличии** Python 3.12+, копии Toolkit, существующей доверенной папки проекта и возможности выполнять команды. Из корня Toolkit:

```bash
python scripts/adt.py profile list
python scripts/adt.py doctor --target /path/to/project
python scripts/adt.py profile plan --target /path/to/project --task qa
python scripts/adt.py init --target /path/to/project --profile general
# Только после проверки плана и разрешения:
python scripts/adt.py init --target /path/to/project --profile general --apply
python scripts/adt.py status --target /path/to/project
```

Для Claude Code добавьте `--layout claude` к соответствующим командам с `--target`. В Windows можно использовать `py -3` и путь Windows. Менеджер не перезаписывает чужие навыки; успешный `status` **не подтверждает активацию**. Подробнее: [установка](INSTALLATION.md), [перенос и восстановление](CLIENT_MIGRATION.md), [офлайновая совместимость](CLIENT_COMPATIBILITY.md). Материалами Toolkit можно пользоваться без установки, но это **использование инструкций как текста**, а не управляемое подключение навыков.

В [Issue #52](https://github.com/MikeMoore1337/ai-development-toolkit/issues/52) предстоит **независимая проверка реальными новичками**: поиск начала, выбор клиента, копирование запроса, решение при отсутствии функции и понимание разницы между текстовым результатом и выполненными действиями. Офлайновые тесты не измеряют понятность или скорость работы человека.

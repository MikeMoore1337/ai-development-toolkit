# Независимая сквозная приёмка безопасности - Issue #360

[English](../SECURITY_FINAL_ACCEPTANCE_360.md) | [Точные SHA и ID проверок](../../fixtures/security_360_evidence.json)

Это **документальная проверка исходников и процессов**, а не новая система
сканирования, установка навыков, запуск агента, разрешение на выполнение или
сертификат безопасности. На **25.10.2026** сверены PR, commit SHA и
выполненные CI до и после объединения.

Состояния `PASS`, `REVIEW_REQUIRED`, `BLOCKED`, `NOT_RUN` и
`NOT_APPLICABLE` **не взаимозаменяемы**: пропущенная проверка
не является пройденной. Успешное закрытие Issue без CI не принимается
за подтверждение релиза. Ссылки на exact-head и post-merge CI находятся
в машиночитаемом JSON, где разрешены полные адреса источников.

## Независимые повторяемые тесты

```bash
python -m unittest tests.test_security_360_acceptance -v
python -m unittest tests.test_skillspector_adapter tests.test_cisco_mcp_gate -v
```

Новые тесты не вызывают модель и не требуют сети: сверяют pin и факты
релизов, живой локальный экспорт объявлений собственных MCP-инструментов,
отсутствие запуска сканера без согласия, защиту при ошибках и неполном
отчёте, запрет LLM и обработку синтетических RU/EN атак.

**Важно:** сигнал `HIGH` для вредоносных RU/EN примеров подставляется
в тестовый отчёт. Это доказывает корректное решение `BLOCKED`, но не
доказывает, что сторонний анализатор распознает произвольную атаку.
Реальный Cisco CLI отдельно проверен на первых MCP-контрактах;
реальный SkillSpector запускался на чистых синтетических RU/EN навыках
на Linux/Windows. Полноту семантического обнаружения эти опыты не доказывают.

## Почему не создаём ещё один слой

Локальная проверка файлов, контрольных сумм и provenance остаётся
первой ступенью. Второй независимый SkillSpector запускается **только
явно**, до ручного решения об импорте. Skill Manager сохраняет предварительный
просмотр и разрешение на `apply`. Cisco исследует *описания*
инструментов, не их полномочия или runtime. Существующая Docker-изоляция
не заменяется SRT, который не дал проверенного дополнительного преимущества.
Дублирующих агентов, обязательных API и новых менеджеров нет.

## Почему Snyk - NO_ADOPT

В официальных
[README](https://github.com/snyk/agent-scan/blob/main/README.md) и
[CLI reference](https://github.com/snyk/agent-scan/blob/main/docs/cli-reference.md)
документирован `scan`: сведения о компонентах, конфигурациях MCP,
названиях и описаниях инструментов, содержимом навыков после редактирования
секретов отправляются для анализа через API Snyk.
Режим `inspect` не анализирует уязвимости и при чтении MCP-конфигурации
может запускать stdio-серверы или обращаться к удалённым адресам.
Формат CLI-результата экспериментальный. Для наших строгих требований
отсутствия передачи данных без разрешения Snyk **не добавляется**.
Это не утверждение об отсутствии у Snyk бесплатного тарифа. CLI не
запускался, токены/секреты не использовались и данные не загружались.

## Условия релиза #360

Документация, JSON-доказательства и unit-тесты - только исходники.
Необходимо подтвердить required CI для точного head PR, объединение
в `main` и CI нового commit. После фиксации этих доказательств Issue
можно закрыть. Production и настройки клиентов не изменяются.

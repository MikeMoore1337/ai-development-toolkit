**Make Feature** - необязательный процесс разработки функции: короткий запрос → выбор решения → контракт и план → реализация → проверка результата и передача. На английском доступно [руководство для пользователя](../MAKE_FEATURE_INTEGRATION.md); оно не является вторым устанавливаемым навыком и не подтверждает англоязычную активацию.

## Когда использовать

Используйте Make Feature для реализации новой функции, когда необходимо связать требования, выбор архитектуры, изменения кода и доказательства приёмки. Для небольшой правки в понятном плане предпочтительна прямая работа. **Нельзя одновременно запускать `make-feature` и `feature-delivery` как управляющие процессы одной задачи.**

| Режим | Когда подходит | Верхние пределы одного запуска по умолчанию |
| --- | --- | --- |
| `quick` | Понятное обратимое изменение в одной существующей области, без критической неизвестности прав, денег и данных | 2 делегации, 1 исправление после проверки, 10 минут |
| `normal` | Новая функция или несколько связанных частей, контракты известны | 6 делегаций, 1 исправление, 25 минут |
| `deep` | Деньги, права, необратимые миграции или потеря данных, ключевая неизвестная интеграция либо спорное продуктовое решение | 12 делегаций, 2 исправления, 45 минут |

Это максимумы, а не обязательные объёмы работ. Меньший предел пользователя имеет приоритет. Возобновление и смена режима не обнуляют расход и не дают новых полномочий.

## Безопасная установка в проект

Запускайте команды из каталога Toolkit, с Python 3.12+ и **уже существующей доверенной папкой** учебного или рабочего проекта:

~~~bash
python scripts/skill_manager.py catalog --profile make-feature
python scripts/skill_manager.py install --target /path/to/project --profile make-feature
python scripts/skill_manager.py install --target /path/to/project --profile make-feature --apply
python scripts/skill_manager.py status --target /path/to/project
~~~

Первая команда `install` выполняет **просмотр без записи**. Проверьте каталог назначения, список изменений и конфликты, затем применяйте `--apply`. Для Claude Code последовательно добавляйте `--layout claude` к установке и проверке состояния. Менеджер не перезаписывает чужие навыки, `AGENTS.md` и `CLAUDE.md`. Подробности - в [руководстве по установке](INSTALLATION.md).

[Оригинальная инструкция (RU)](../../extensions/make-feature/skills/make-feature/INSTALL.md) описывает также ручную установку выданного архива, в том числе для Hermes. Это **не означает**, что у Toolkit есть отдельный проверенный адаптер Hermes. Фактический клиент, расположение навыков, разрешения и точную версию пакета нужно проверить отдельно.

Пример обращения к уже обнаруженному клиентом навыку:

> Используй установленный навык make-feature: «Добавь предварительный просмотр импорта CSV с понятными ошибками валидации». Покажи выбранный вариант, соблюдай правила проекта и приложи результаты реально запущенных тестов.

Исходный триггер сформулирован по-русски: «Сделай мне функцию». Нельзя считать, что только английский запрос автоматически включил этот навык: его необходимо выбрать реальным механизмом клиента и подтвердить обнаружение.

## Этапы и доказательства

1. **Понять:** исходный запрос, текущее поведение, проверяемые критерии `C*`, ограничения и риски.
2. **Выбрать:** переиспользование или минимальное решение, выбор `D*`, источники и компромиссы.
3. **Спроектировать:** данные, контракты, ошибки, повторы, права, задачи `T*` и проверки.
4. **Реализовать:** изменения только в разрешённых файлах и в пределах доступных инструментов, затем фактические регрессионные тесты.
5. **Принять:** независимый агент только при реально существующем отдельном контексте. Иначе честно сообщить о самопроверке и тестах без фиктивной независимой приёмки.

Чаще всего достаточно четырёх актуальных Markdown в `.make-feature/<slug>/`: исходный запрос, индекс, решение/план и доказательства. Первоисточники: [documents](../../extensions/make-feature/skills/make-feature/references/documents.md), [workflow](../../extensions/make-feature/skills/make-feature/references/workflow.md), [runtime](../../extensions/make-feature/skills/make-feature/references/runtime.md), [agents](../../extensions/make-feature/skills/make-feature/references/agents.md), [verification](../../extensions/make-feature/skills/make-feature/references/verification.md).

Скрипты бюджета и состояния ведут учёт записанных попыток и локального состояния, но **не перехватывают** вызовы моделей, не измеряют реальные токены/стоимость и не ограничивают исполнение клиента извне.

| Статус | Значение |
| --- | --- |
| `SELF_CHECK` | Самопроверка автора, не независимая приёмка |
| `TESTED` | Действительно выполненные тесты с командами, результатами и покрытыми критериями |
| `INDEPENDENT_REVIEW` | Проверка отдельным контекстом, который не реализовывал проверяемую версию |
| `DONE_WITHOUT_INDEPENDENT_REVIEW` | Только обратимый quick/normal, все обязательные критерии подтверждены, независимая приёмка не обязательна |
| `INDEPENDENT_REVIEW_PENDING` / `INCOMPLETE` | Обязательная проверка или критерии ещё не выполнены |
| `BLOCKED_REVIEW` | Рискованный deep-этап запрещён без нужной независимой приёмки/разрешения владельца |

В конце сообщите о реальных изменениях, проверках, оставшихся критериях, доступности независимой приёмки и следующих шагах. Копирование навыка **не доказывает** его обнаружение, применение моделью, готовность production или эффективность. [Оригинальный отчёт](../../extensions/make-feature/skills/make-feature/TEST-REPORT.md) описывает ограниченные проверки исходного пакета, не полноценные эксперименты Toolkit.

**Граница локализации:** английская страница - пояснение для человека, не побайтовый перевод и не ещё один работающий навык. Для исполнения и разрешений действуют один исходный русскоязычный `SKILL.md` и инструкции проекта. Активация по одному английскому запросу **NOT_TESTED**.

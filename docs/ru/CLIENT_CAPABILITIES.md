## Типы и уровни

Исходный [реестр файловых клиентов](../../compatibility/clients.json) остаётся на **схеме v1**: `codex`, `claude-code`, `hermes`. [Дополнительный разговорный контракт](../../compatibility/conversational_clients.json) (схема v1) содержит только `chatgpt` и `claude-ai`. Оба набора проверяются одним существующим `scripts/verify_client_compatibility.py`; пересекающихся записей нет.

- `FILESYSTEM_SKILL_CLIENT`: Codex с `.agents/skills`, Claude Code с `.claude/skills`, документированные пути Hermes. Безопасное копирование не означает обнаружение.
- `CONVERSATIONAL_REFERENCE_CLIENT`: использование ссылки и доступных файлов как инструкций. Нельзя подставлять файловый layout Codex/Claude Code. У ChatGPT и Claude.ai существуют **собственные** механизмы размещения Skills при доступности функции, которые не управляются Toolkit Skill Manager.
- Возможности текущей сессии: `toolkit_access, file_read, file_write, terminal, browser, github_access, attachments, zip_handling, skill_installation, skill_discovery, tool_invocation, separate_agents, external_actions`. Значения: `AVAILABLE, UNAVAILABLE, NOT_TESTED, UNKNOWN, REQUIRES_PERMISSION, NOT_APPLICABLE`. Документация продукта сама по себе не делает возможность `AVAILABLE` в конкретном чате.
- Статусы: `VERIFIED, PARTIAL, NOT_TESTED, UNSUPPORTED, UNKNOWN, BLOCKED, OWNER_REPORTED_PASS, EVIDENCE_NOT_ATTACHED`. Для уровня L6 используется также `NOT_MEASURED`, для неприменимых уровней - `NOT_APPLICABLE`.

## Диагностика источников и фактического чтения (Issue #274)

Существующие read-only команды `toolkit_info`, `toolkit_prepare_task` и `adt.py doctor --json` возвращают `diagnostics` (схема v1): `adapter`, `adapter_version`, `toolkit_version`, `source_sha`, `source_worktree`, `loaded_skills`, `loaded_skill_evidence`, `fallback`, `l4_client_discovery`, `l5_client_invocation`, `l6_client_benefit`, `client_activation`, `target_execution`, `project_files_changed`.

`loaded_skills` содержит только те инструкции, которые команда **действительно прочитала и вернула** в своём ответе. `toolkit_info` и `doctor` не возвращают тексты навыков и поэтому показывают `[]`. У `toolkit_prepare_task` значение `RETURNED_LOCAL_GUIDANCE` подтверждает только чтение исходников, **не** автоматическую активацию навыка в клиенте и не эффективность. Отсутствующий SHA остаётся `UNAVAILABLE` (MCP) или `NOT_VERIFIED` (CLI). У CLI нет отдельной версии пакета, поэтому его `adapter_version = UNVERSIONED_SCRIPT`.

ChatGPT-плагин использует те же названия признаков в инструкциях, но не исполняет код Python, не получает доступ к ПК сам по себе и не выдаёт неизвестную версию за проверенную. Бандл-фолбэк можно указать, только когда он наблюдался; в остальных случаях — `NOT_VERIFIED`. Новый контракт не повышает уровень L4-L6 ни у одного клиента.

## Официальная документация (перепроверена 21.10.2026)

- [Agent Skills](https://agentskills.io/specification): единый переносимый `SKILL.md`, обязательные метаданные, необязательные ресурсы.
- [Codex](https://learn.chatgpt.com/docs/build-skills): пути `.agents/skills`, домашние/административные навыки, отдельные ограничения среды.
- [Claude Code](https://code.claude.com/docs/en/skills): `.claude/skills`, пользовательские/организационные навыки, специфичные метаданные и разрешения. Отдельные версии Claude Code синхронизируют навыки аккаунта Claude.ai; это **не** означает, что Toolkit контролирует такую синхронизацию.
- [ChatGPT Skills](https://help.openai.com/en/articles/20001066-skills-in-chatgpt) и [загрузка файлов](https://help.openai.com/en/articles/8555545-uploading-files-and-audio-to-chatgpt): встроенные Skills при соответствующей доступности и ограничения вложений. Ссылка на Toolkit не устанавливает навык.
- [Claude.ai Skills](https://support.claude.com/en/articles/12512180-use-skills-in-claude), [создание навыков](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills), [проекты](https://support.claude.com/en/articles/9517075-what-are-projects): загрузка пользовательских Skills через интерфейс; документация включает Free при включённом выполнении кода. Никаких автоматических предположений о возможностях текущего чата.

Версии реальных клиентов неизвестны. Чтение документации не подтверждает доступ к терминалу, браузеру, GitHub или файловой системе конкретной сессии.

## Выбор маршрута по фактическим возможностям

1. `NATIVE_FILESYSTEM_SKILL` - файловый клиент; навык установлен, действительно обнаружен и доступен для чтения. Копирования недостаточно.
2. `TOOLKIT_REFERENCE` - инструкции по URL **действительно прочитаны**. Статус `GUIDANCE_ONLY`, а не вызов Skill.
3. `ATTACHMENT_GUIDANCE` - материал Toolkit доступен как вложение; ZIP пользовательского проекта существует **отдельно**.
4. `MANUAL_FALLBACK` - чтение файлов недоступно, но можно подготовить ответ, пример кода или план. Это допустимый режим.

Офлайновые функции `client_capabilities.select_route` и `validate_execution_claim` не выполняют ни установку, ни вызов моделей. Они блокируют ложные заявления о запуске тестов, чтении ZIP, записи файлов, обнаружении/активации, независимых агентах и платных вызовах.

## Практические сценарии

- **Локальная IDE**: «Используй https://github.com/MikeMoore1337/ai-development-toolkit, чтобы исправить сохранение в моём открытом проекте». URL или публикация **самого пользовательского проекта не нужны**. Сначала проверить рабочую область и права, затем прочитать нужные инструкции и изменять только разрешённый проект.
- **Две ссылки**: первая - Toolkit как источник только для чтения; вторая - проект пользователя. Публичность проекта не разрешает коммиты.
- **ZIP + ссылка на Toolkit**: определить архив проекта, проверить доступность, безопасно прочитать доступное содержимое, выбрать применимый процесс, выполнить разрешённое действие. Не распаковывать в Toolkit и не устанавливать навыки автоматически. Недоступный ZIP обозначать `ATTACHMENT_UNAVAILABLE`; отсутствие права на запись - не выполненная реализация, отсутствие исполнения - `TESTS_NOT_RUN`.
- **Обычный чат без файлов**: `GUIDANCE_PREPARED`, `IMPLEMENTATION_NOT_PERFORMED`, `FILES_NOT_ACCESSIBLE`, `TESTS_NOT_RUN`. Запрашивать минимальные блокирующие материалы по необходимости.
- **Опциональная установка**: существующий Skill Manager, последовательность Discover -> Preview -> Consent -> Apply -> Status. Обязательны защита чужих навыков, `AGENTS.md`, `CLAUDE.md`, контроль drift, возврат и права владельца. Реальная активация отдельно не доказана.

`client_capabilities.inspect_zip` проверяет метаданные ZIP **без распаковки и исполнения**. Запрещены абсолютные пути и выход за каталог, символьные ссылки, дубликаты с разным регистром, секретные файлы, вложенные архивы, шифрование и чрезмерное расширение. Пределы: 1000 файлов, 64 МиБ распакованного объёма, коэффициент сжатия одного файла не больше 80. Это только предварительная проверка, не антивирус. При безопасном встроенном чтении вложений клиента дополнительная распаковка не обязательна.

## Единственный источник и будущая упаковка

**Экспортёр не создавался:** обычный URL, доступные файлы и существующие архивы покрывают подтверждённые случаи; не доказана потребность в отдельном пакете. При появлении обоснованного пробела будущий read-only пакет обязан фиксировать: идентификатор, точную ревизию Toolkit, выбранные Skills, канонические пути, SHA256 каждого файла, references/scripts, лицензии и происхождение, получателя, способ упаковки, результат валидации и ограничения. Недостающие ссылки, файлы, лицензии, подмена SHA и расходящиеся копии - отказ. SHA256 не подтверждает авторство или безопасность.

Отдельный протокол будущих **реальных**, только явно разрешённых испытаний: версия клиента, настройки, layout, SHA Skill, наблюдаемое обнаружение, доказательство фактического вызова, задача и критерии приёмки, baseline и candidate, цена, ограничения, разрешения. Обнаружение, вызов, завершение задачи и измеримая польза учитываются независимо. В #68 такие испытания, платные API, самостоятельные агенты и deployment не запускались.

Issue #69 получает только словарь возможностей для будущих интеграций, не разрешения или готовые подключения.

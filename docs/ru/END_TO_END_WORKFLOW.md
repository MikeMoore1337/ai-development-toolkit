# Сквозной процесс: от идеи до поддержки (Issue #67)

[English](../END_TO_END_WORKFLOW.md) | [Новичку](BEGINNER_WORKFLOW.md) | [Планирование](PROJECT_DELIVERY_MANAGEMENT.md) | [Релиз](RELEASE_PROCESS.md)

Это переносимый **контракт**, а не третий оркестратор, новая база задач, установка навыков или доказательство работы ИИ-клиента. Для реализации выбирается **один** управляющий навык: по умолчанию feature-delivery (quick/normal/deep по риску), а make-feature - только при сознательном выборе его правил делегации и состояния. Специалисты решают ограниченные подзадачи и возвращают результат контроллеру. Описание роли не равно независимому агенту; без отдельного контекста указывай INDEPENDENT_REVIEW=NOT_AVAILABLE.

## Контракты

**Workflow:** идентификатор, исходный запрос, проект, ревизия, один контроллер, режим, этапы и обоснованные пропуски, оригинальные R/AC, решения, зависимости, артефакты, доказательства, права, блокеры, оставшийся объём, следующее действие. Для маленькой задачи хватит сообщения в чате. Файл сохраняется только с разрешения.

**Handoff:** ID, отправитель/получатель, задача, неизменные R/AC, исходный артефакт и ревизия, результат, решения, ограничения, вопросы, доказательства, уровень проверки, требуемое разрешение, реальное подтверждение получателя. HANDOFF_PREPARED не означает HANDOFF_ACCEPTED; DESIGN_APPROVED не означает UI_IMPLEMENTED; IMPLEMENTATION_COMPLETE не означает QA_PASS; QA_PASS не означает RELEASED.

**Evidence:** этап, вход, выход, ревизия, требования, решения, тест, фактическое наблюдение, недостающие сведения, разрешение и следующий этап. Уровни: PROPOSED, SOURCE_BACKED, CONTRACT_VALIDATED, SYNTHETIC_TESTED, IMPLEMENTED, TESTED, INDEPENDENT_REVIEWED, MERGED, RELEASED, DEPLOYED, USER_VERIFIED, NOT_TESTED, BLOCKED. Синтетическая проверка доказывает только SYNTHETIC_TESTED.

Трассировка: цель -> исходный R-ID -> AC-ID -> решение -> код -> запущенный тест -> наблюдение -> точная версия/релиз -> поддержка. Потерянный критерий, невыполненный тест, расширение scope и блокер должны быть обнаружимы.

Зависимости: BLOCKS, RELATED, REQUIRES_DECISION, REQUIRES_APPROVAL, OPTIONAL. Проверяй отсутствующие этапы, циклы и обязательных предшественников. Блокер публикации не должен запрещать независимую разработку. Quick - понятная обратимая правка; normal - связанная новая функция; deep - деньги, доступ, необратимые данные или ключевые неизвестные. Режим определяется риском, не размером diff.

## Остановка, возобновление и полномочия

Проверяй отдельно доступность инструментов и полномочия READ, CHANGE, EXECUTE, EXTERNAL; EXPLAIN и PREPARE не изменяют проект. Не устанавливай скрытно навыки, не подключай платные API, не записывай отчёты в Toolkit, не пропускай визуальное согласование. Публикация, слияние, deployment, удаление и необратимая миграция используют отдельные необходимые разрешения.

При возобновлении храни небольшой индекс: workflow, предыдущая ревизия состояния, текущий SHA/источник, завершённый и следующий этапы, принятые решения, evidence, блокеры, ожидающие разрешения, изменения после паузы, необходимые перепроверки, использованные лимиты делегаций. Изменение HEAD/требований делает старый PASS недостаточным. Не повторяй необратимые действия, не создавай дубли, не сбрасывай счётчики. Остановка локальна для зависимого действия.

    python -m unittest tests.test_end_to_end_workflow -v

Стандартный Python без внешних API проверяет [42 неисправных варианта](../../fixtures/end-to-end-workflow/broken_cases.json): два контроллера, потерю R/AC, циклы, фиктивную независимость, QA PASS без исполнения, ложный релиз, scope creep, изменение SHA и права на запись. Проверяется связность структурных утверждений, а не работа реального приложения.

## Новичку, специалисту и при отсутствии терминала

**Новичок:** «Хочу простой локальный список домашних дел. Используй AI Development Toolkit, самостоятельно выбери нужные методы, не требуй GitHub и терминал, ясно покажи, что выполнено, а что нет». ИИ сокращает scope, уточняет только блокирующее, действует лишь при доступе и разрешениях, сообщает одно следующее действие.

**Специалист:** «Сохраняй исходные R/AC через применимые требования, анализ, UX, архитектуру, код, QA/security, разрешения на выпуск и поддержку. Представь доказательства и индекс для возобновления».

Локальный проект в IDE не требует URL. Архив проекта и ссылка на Toolkit достаточны для анализа доступных файлов, но это не доказывает установки навыков. В чате без файлов/терминала честно покажи подготовленный результат и пометь исполнение и тесты NOT_TESTED / CAPABILITY_UNAVAILABLE. Наличие SKILL.md не доказывает активацию. Реальные клиентские испытания - Issue #68; необязательные полномочия и интеграции - #69. Платные сервисы не обязательны.

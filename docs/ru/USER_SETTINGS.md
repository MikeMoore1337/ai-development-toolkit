# Индивидуальные настройки пользователя и проекта

[English](../USER_SETTINGS.md) | [Задача #394](https://github.com/MikeMoore1337/ai-development-toolkit/issues/394)

В публичном Toolkit **нет персональных настроек владельца**. Каталог навыков и список потенциальных клиентов не являются разрешением на запуск. Каждый пользователь может задать предпочтения отдельно, не меняя общие исходники Toolkit и правила других проектов.

## Четыре уровня

1. **Универсальные значения**: по умолчанию запрещены реальные агентные эксперименты, вызовы платных API, CLI-агенты, сеть и дополнительные расходы.
2. **Пользователь**: необязательный локальный файл `preferences.json` вне репозитория Toolkit. На Linux/macOS: `${XDG_CONFIG_HOME:-~/.config}/ai-development-toolkit/preferences.json`; на Windows: `%APPDATA%\AI Development Toolkit\preferences.json`. Пример: `profiles/user-preferences.example.json`.
3. **Проект**: необязательный `.adt/config.json` в целевом проекте. В Git допускается хранить только несекретные проектные правила. `AGENTS.md` и реальные правила релиза остаются основными. Проект может лишь ужесточить права и ограничить доступные маршруты.
4. **Задача**: необязательный JSON для одной проверки, который также может только ужесточить ограничения.

Для языка, выбора клиента и навыков действует порядок: значения по умолчанию < пользователь < проект < задача. Проект и задача не могут включить запрещённые пользователем расходы, сеть или CLI. Значения `approvals`: `deny` или `ask`, без бесконтрольного `allow`. Неизвестные поля, секреты и некорректные настройки отклоняются. Исключения навыков объединяются.

## Предпросмотр без установки

```sh
python scripts/toolkit_preferences.py --target /path/to/project
python scripts/toolkit_preferences.py --target /path/to/project --user-config /private/preferences.json
python scripts/toolkit_preferences.py --task-config /private/task.json
```

Файл `.adt/config.json` создаётся пользователем отдельно при необходимости. Команда лишь читает настройки, показывает итоговые ограничения и источник каждого значения. Она не записывает файлы, не запускает модель, не устанавливает пакет и не обращается к API. В отчёте `execution_authorized=false`; никакого постоянного разрешения на выполнение нет. Штатный Skill Manager с предварительным просмотром и `--apply` сохраняется.

Выбор пользователем платного API или CLI означает только **готовность рассмотреть этот маршрут**. Это не запуск и не право на оплату: реальную стоимость, предел расходов, доступность клиента, разрешения и согласие на каждую задачу должен независимо проверить соответствующий адаптер.

Нельзя включать ключи, пароли, личные сведения или закрытый код в публикуемую конфигурацию. Плагин ChatGPT без доступа к локальному компьютеру не может самостоятельно прочитать этот JSON - настройки нужно явно передавать поддерживаемым клиентским способом. Шаблон `profiles/project-profile.example.json` остаётся описанием фактических свойств проекта. Применение политик в клиентских маршрутах относится к [#395](https://github.com/MikeMoore1337/ai-development-toolkit/issues/395).

## Оригинальные дизайн-навыки (добровольный режим)

По умолчанию `skills.design_originals` имеет значение `STANDARD`. После отдельного разрешения на установку и проверки неизменённых Impeccable, Taste Skill и UI UX Pro Max пользователь может записать `"skills": {"design_originals": "ALL_THREE"}` в **локальный файл** своих настроек или выбрать это значение в разрешённой настройке проекта/задачи. Существующая Design Orchestra будет считать все три оригинала обязательными для дизайна. Эта настройка не разрешает скачивать исполняемые файлы, включать hooks, запускать Codex CLI или тратить деньги. Исключение любого обязательного оригинала приводит к ошибке настроек. Наличие каталогов проверяется через `python scripts/validate_ux_ui_orchestra.py --inspect-originals TARGET`; фактическое подключение к клиенту остаётся `NOT_VERIFIED` до наблюдаемого запуска. Личные настройки не сохранять в Git.

Toolkit подготавливает **содержимое репозитория**, но не изменяет настройки вашей учётной записи GitHub. Официальный репозиторий [MikeMoore1337/ai-development-toolkit](https://github.com/MikeMoore1337/ai-development-toolkit) **уже существует**. Инструкция ниже служит справочником его настроек или настройкой отдельного разрешённого форка. **Не создавайте официальный репозиторий повторно и не используйте скрипт первой публикации для обновления существующего проекта.**

## Оформление и настройки

1. **README:** `README.md` автоматически отображается на главной странице репозитория.
2. **Изображение предпросмотра:** откройте `Settings → General → Social preview → Edit` и загрузите `assets/branding/social-preview.png` (1280 × 640).
3. **Закрепление в профиле:** при необходимости добавьте репозиторий через `Customize your pins` в своём профиле GitHub.
4. **Релизы:** публикуйте GitHub Release только для точного проверенного Git-тега, после обязательного CI и **отдельного согласования прав на конкретное дерево исходников**. Имя ZIP, слияние PR и номер в README не подтверждают факт публикации. См. [процедуру выпуска](RELEASE_PROCESS.md).
5. **Сообщество:** включите Issues и Discussions, если планируете взаимодействовать с участниками; шаблоны и руководство по вкладу находятся в `.github`.
6. **Защита ветки:** используйте ruleset для проверки PR и обязательного CI, если это поддерживается настройками тарифа и репозитория. Уже настроенные правила не обходите.

## Первая публикация **другого, нового** репозитория

**Следующие команды нужны только при намеренном создании нового публичного репозитория, который ещё не существует. Не запускайте их для обновления официального AI Development Toolkit.** На своём авторизованном компьютере предварительно изучите полный состав исходников и права на распространение.

```powershell
python scripts/check_public_package.py
python scripts/validate_pack.py
python -m unittest discover -s tests -v
.\scripts\publish_github.ps1
```

Скрипт первой публикации требует явного подтверждения, через авторизованную сессию `gh` создаёт **публичный** репозиторий и отправляет `main`. Без подтверждения публикации нет. В **существующем официальном** Toolkit повседневные изменения поставляются через Pull Request, защищённую `main` и обязательные проверки. Новый выпуск дополнительно требует отдельного согласования владельца на точный артефакт. Не добавляйте архивы прежних выпусков, учётные данные, персональные лицензионные документы и посторонние рабочие каталоги.

**Важно:** настройки GitHub и изображение предпросмотра невозможно изменить только текстом Markdown. Готовые изображения уже включены в репозиторий, но загрузку в интерфейс GitHub нужно выполнять отдельно.

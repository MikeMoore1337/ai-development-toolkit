# Проверка внешнего кандидата: Toolkit #199 + #200

[English](../EXTERNAL_SKILL_CANDIDATE_REVIEW.md) | [Локальные навыки](SKILL_COVERAGE.md) | [Security Gate](EXTERNAL_SKILL_GATE.md)

Это **не** маркетплейс, загрузчик Skill Manager, сертификат безопасности или автоматическая установка. Описанный ниже локальный сценарий не использует сеть; отдельно в персональном MCP реализован разрешаемый владельцем поиск закреплённых метаданных (#199). `scripts/skill_candidate_review.py` связывает существующий механизм оценки локальных навыков с существующим Security Gate для внешнего `SKILL.md`. Кандидат заранее предоставлен оператором в отдельном каталоге. Нет сети, платных API, LLM, пакетного менеджера, запуска чужих скриптов или записи в проект.

Проверка задачи без доступа к внешнему кандидату:

```bash
python scripts/skill_candidate_review.py --query "qa-strategy"
```

Отдельное **ручное подтверждение** проверки конкретного источника:

```bash
python scripts/skill_candidate_review.py --query "отсутствующий навык" \
  --review-external \
  --candidate-dir /isolated/candidate \
  --manifest /isolated/review-manifest.json \
  --allow-source https://github.com/approved-owner/approved-repo
```

Манифест должен находиться вне каталога кандидата. Оператор независимо задаёт точный URL разрешённого GitHub-репозитория, а не принимает его на веру из стороннего SKILL.md. Манифест содержит pinned commit SHA (40 символов), заявленную лицензию и SHA-256 всех файлов. **Обязательна независимая проверка upstream-репозитория, лицензии, revision, хешей и фактического состава**, прежде чем рассматривать установку. Самоподписанный манифест - не подтверждение происхождения.

Локальный статус `FOUND_LOCAL` означает только читаемое точное имя навыка; `AMBIGUOUS` - лексическая похожесть; `MISSING` - отсутствие лексического совпадения, а не доказанный пробел в знаниях. При положительной проверке Gate выдаёт `ALLOW_FOR_REVIEW`, но обёртка всё равно возвращает **`MANUAL_REVIEW_REQUIRED` с кодом выхода 1**. При отказе - `REJECT` с кодом 2. Без кандидата - `LOCAL_ONLY` с кодом 0, не являющийся разрешением активации навыка в Codex.

## Границы доверия

Данный офлайн-скрипт **не выполняет сетевого поиска**. В personal MCP v0.1.10 поиск только метаданных доступен после явного разрешения и указания закреплённого GitHub SHA. Здесь реализован безопасный offline-переход от «какого навыка не хватает» к «можно ли передать вручную найденный, явно разрешённый пакет на экспертизу». Нельзя автоматически импортировать, обновлять или исполнять внешний навык. Static checks не гарантируют отсутствие prompt injection, вредоносного кода либо достоверность авторства и лицензии. Не передавать каталог с секретами. Для оценки изменений можно использовать режим Skill Manager `external-preview`, описанный ниже. Этот режим никогда не разрешает `apply` внешнего кандидата; штатная установка работает только с навыками собственного каталога Toolkit.

```bash
python -m unittest tests.test_skill_candidate_review -v
python scripts/validate_pack.py
python scripts/verify_checksums.py
```

Это тесты исходников, **не** доказательство работы установленного Codex MCP или ChatGPT-плагина. Отдельно не подтверждены фактическая работа нового MCP в установленном Codex и ручная экспертиза лицензии/источника (#190).


## Предварительный просмотр внешнего навыка в Skill Manager (#199)

После Security Gate можно оценить **заранее полученный** кандидат с
закреплённой ревизией и полным перечнем хешей. Цель должна быть существующей
изолированной папкой, а кандидат, его манифест и цель - разными каталогами.

```bash
python3.12 scripts/skill_manager.py external-preview \
  --target /isolated/existing-target \
  --candidate-dir /isolated/external-skill \
  --manifest /isolated/review-manifest.json
```

Переиспользуются Security Gate, контроль владения Skill Manager и сравнение
файлов. Вывод содержит только пути, типы изменений и SHA-256, без содержимого
файлов. Возможные результаты: `CANDIDATE_ONLY`, `NEEDS_MANUAL_REVIEW`
либо `REFUSED_*` при неверном пакете, занятой чужой папке или изменённом
управляемом навыке. Параметры `--apply`, `--skills`, `--profile` и
`--from-layout` запрещены; отказ возвращает код 2.

**Даже `CANDIDATE_ONLY` не разрешает установку.** Лицензия, GitHub URL,
commit SHA и хеши из предоставленного манифеста остаются заявлением
оператора, не независимым доказательством происхождения. Статический анализ
не гарантирует безопасность. Нет сетевых вызовов, запуска инструкций, Codex,
записей в проект и фоновых процессов. Для реального внешнего импорта
потребуются отдельная реализация и явное решение владельца; существующий
`install --apply` предназначен только для собственных навыков Toolkit.

```bash
python3.12 -m unittest tests.test_external_skill_preview -v
```

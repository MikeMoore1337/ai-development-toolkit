## Явная совместимость рабочих процессов

| Группа | Назначение и выбор |
| --- | --- |
| `feature-delivery`, `make-feature` | Для одной задачи выбирается **ровно один** контроллер верхнего уровня. У Make Feature могут быть дополнительные соглашения о состоянии и делегировании; ни один не переопределяет правила целевого проекта. |
| `adaptive-delivery` | Только устаревший справочный вариант; не сочетать ни с одним из двух контроллеров функций. Существующие файлы сохранены ради обратной совместимости. |
| `implementation`, `minimal-safe-change` | Совместимые **вспомогательные** навыки выбранного контроллера: первый ограниченно реализует изменение, второй минимизирует риск и объём. Не самостоятельные контроллеры. |
| `clear-voice`, `editorial-naturalness`, `qa-clear-voice` | Для широкой редакторской точности - `clear-voice`, для коротких универсальных правок - `editorial-naturalness`, для доказательной QA-редактуры - `qa-clear-voice`. Избегать избыточного наложения стилей; само по себе это не причина блокировки CI. |
| `qa-strategy`, `test-strategy` | Ядро предлагает проверки по рискам, QA-пакет - архитектуру и уровни тестирования. Совместимы, если нужны оба аспекта. |
| `test-analysis-design`, `test-review`, `qa-code-review`, `quality-gate-assessment` | Проектирование тестов, независимая проверка оракулов, сопровождаемость тестового кода и итоговая проверка доказательств релиза соответственно; могут сосуществовать. |
| `security-boundaries`, `security-review`, `security-testing`, `external-skill-review` | Границы доверия; анализ угроз CI/автоматизации; проектирование негативных проверок безопасности; происхождение и полномочия сторонних навыков. Выбирать по реальной задаче. |
| `agent-framework-fit`, `codebase-knowledge-map`, `skill-portability`, `provider-reality-check` | Решения по оркестрации, карта репозитория, перенос пакетов навыков и проверка сведений о провайдерах. Сочетать только при наличии действительно междисциплинарной задачи. |

В `QUALITY_RULES.json` попадают только задокументированные **жёсткие конфликты**. Пересечение тем или словаря не доказывает конфликт инструкций.

## Границы ролей и передача доказательств

`orchestrator` выбирает один контроллер и отвечает за границы задачи/передачу результатов, но не может предоставлять право на слияние или развёртывание. `implementer` меняет код. `reviewer` и `qa-verifier` проводят независимую проверку **только если она действительно проводилась раздельно**. `researcher` устраняет ограниченные неопределённости. Справочные роли QA специализируются на диагностике отказов, покрытии, анализе требований, проектировании и реализации тестов, проверке тестов, исследовании CI и релизных ограничениях.

Эти роли **не** являются автономными фоновыми процессами и не создают новую иерархию агентов. Передача результатов между ролями должна содержать пути, действительно выполненные проверки, доказательства и неизвестные факторы.

## Автономные проверки и ограничения

`python scripts/validate_quality.py` проверяет заявленный состав, профили, явные правила несовместимых процессов и **все Markdown-файлы репозитория**: справочники навыков, роли, шаблоны CI, рецепты QA, интеграции и корневые инструкции. Создаваемые каталоги (`.git`, `.venv`, `node_modules`, сборки и кеши) намеренно исключены. Прежние проверки охватывали 135 из 146 отслеживаемых Markdown-файлов; расширенное сканирование устраняет этот пробел.

Распознаются относительные и процентно-кодированные пути, якоря Markdown-заголовков (включая повторы), блоки кода с корректными закрывающими ограничителями, встроенный код с несколькими обратными кавычками, определения ссылок Markdown и внешние HTTP-ссылки. Это **не полный парсер CommonMark**: код с отступами, HTML `href` и сложные вложенные ссылки всё ещё требуют ручного просмотра.

Небезопасные пути и отсутствие локальных файлов - `BLOCKER`. JSON-отчёт содержит `rule_id`, `severity`, `file`, `line` и `explanation`; порядок результатов устойчив. Неверный или отсутствующий файл правил качества сам является `BLOCKER`.

Для воспроизведения: `python scripts/validate_quality.py` и `python -m unittest discover -s tests -p test_quality_gate.py -v`. Та же проверка входит в существующую CI-матрицу Windows и Linux. Проверка внешних URL остаётся **вне обязательного CI**: 404/410, 401/403, 429, тайм-ауты и сетевые ограничения нельзя считать эквивалентными ошибками.

## Внешние URL: выборочная проверка (2026-10-19)

Проверена [спецификация Agent Skills](https://agentskills.io/specification): содержимое было доступно. Проверено [руководство Hermes по делегированию](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation/): происходит перенаправление на работающий канонический URL без конечной косой черты. Доступность официального `skills-ref` дополнительно проверяет существующая установка с закреплённой версией и запуск CLI в GitHub Actions.

Это **выборка**, не сплошная проверка всех внешних адресов. Отказ доступа, ограничения частоты запросов и временные сетевые сбои не доказывают неисправности ссылки. Как такие следует отмечать только подтверждённые 404/410. Обязательный CI не обходит внешние ссылки.

Этот аудит **не доказывает** реальной активации навыков Codex/Claude/Hermes, независимого анализа агентом, улучшения генерируемого кода, полной смысловой согласованности произвольных текстов, текущей доступности внешних ссылок, прав на сторонние материалы или развёртывания в production. Испытания реальных агентов по-прежнему относятся к **Issue #11**.

Ручная последующая работа: повторно проверить описания навыков и правила их выбора после существенных изменений, а также выборочно проверить официальные внешние URL ограниченными средствами с защитой от SSRF **только при наличии разрешения**. Платные сервисы и VPS не требуются.

# Офлайновая проверка выбора навыков

[English](../SKILL_ROUTING_EVALS.md) | [Спецификация Agent Skills](AGENT_SKILLS_SPEC.md) | [Проверка качества](SKILL_QUALITY_V2.md)

Бесплатная **лексическая диагностика** сопоставляет запросы обычным языком с полями `name` и `description` **всех навыков, объявленных в `MANIFEST.json`**. Количество вычисляется динамически; наличие навыка в каталоге не означает, что его поведение уже проверено. За основу взят подход к многоуровневой оценке из [agent-skills Addy Osmani](https://github.com/addyosmani/agent-skills), но сторонний код не копируется.

```bash
python scripts/skill_routing_eval.py --strict
python -m unittest tests.test_skill_routing_eval -v
```

Сценарии в [fixtures/skill_routing_cases.json](../../fixtures/skill_routing_cases.json) содержат положительные запросы (целевой навык должен быть среди первых трёх) и отрицательные соседние запросы (целевой навык не должен занимать первое место). CI проверяет **только эти заранее определённые случаи**. Процент успешных лексических проверок не означает, что все навыки проверены или что AI-клиент правильно их активирует.

Алгоритм использует разбиение на слова, упрощённую нормализацию английских окончаний, веса названий и описаний и частотность слов. Ограничения из описаний, начинающиеся с `Not for`, не считаются признаками выбора. Для проверенных вручную подсказок допускаются английские фразы и сопоставление первых пяти кириллических символов русских словоформ; эти эвристики не заменяют понимание смысла. Он не понимает смысл так, как модель. Особенно важно: запросы на русском, переформулировки и реальные AI-клиенты могут давать другой результат. Обнаружение, фактическая активация и влияние на результат модели остаются `NOT_MEASURED` (см. [Issue #11](https://github.com/MikeMoore1337/ai-development-toolkit/issues/11)).

Для нового случая добавь объект вида `{ "id": "уникальный-id", "target": "имя-навыка", "positive": ["..."], "negative": ["..."] }`. Для каждого случая требуются оба типа запросов. Неизвестный навык, дубликат, некорректный запрос или отсутствующий исходный `SKILL.md` останавливают проверку. Код навыков не исполняется, внешние API не вызываются, пользовательские проекты не изменяются.

Не переписывай короткие либо защищённые навыки ради лексического рейтинга без подтверждённого дефекта. Реальные проверки агентов допустимы только при отдельно согласованном способе без дополнительных расходов.

## Ручные сценарии проверки поведения QA-агентов

Лексический подбор выше **не проверяет работу AI-клиента**. Следующие сценарии выполняются вручную в разрешённом изолированном проекте, только когда подходят задаче. Не требуются дополнительные зависимости или платный API. Это **план приёмки**, а не сведения о выполненных тестах. Английская версия содержит аналогичные сценарии.

Для каждого случая раздельно фиксируйте **выбор навыка** (прочитан ли нужный навык по доступной трассе) и **поведение** (подтверждён ли результат независимым oracle), а также версию клиента/модели, commit, разрешения, инструменты и обезличенные доказательства. Выбор: `PASS / FAIL / NOT_OBSERVED`; поведение: `PASS / FAIL / BLOCKED / NOT_RUN`. Без трассы выбор навыка остаётся `NOT_OBSERVED`, даже когда ответ правильный. Нельзя объявлять поведение успешным без необходимого evidence. Результаты храните в существующем issue/PR или выбранном пользователем внешнем месте, но не в Toolkit.

### Покрытие навыков и русский язык

Проверенные вручную русские словосочетания находятся в [реестре подсказок](../../fixtures/skill_routing_aliases.json). Это ограниченное лексическое сопоставление, а не семантический поиск.

В JSON-отчёте `coverage.catalog_total` обозначает весь каталог, `coverage.curated_targets` - проверенные целевые навыки, `coverage.uncovered_targets` - ещё не охваченные навыки, `coverage.languages` - число позитивных и негативных примеров на каждом языке. Язык по кириллице определяется эвристически.

Текущий корпус содержит **104 сценария для всех 82 заявленных навыков**: для каждого предусмотрены положительные и отрицательные запросы **на русском и английском**. Это *покрытие тестовыми примерами*, а не независимо подтверждённая семантическая точность: эталоны и лексические подсказки составлялись вместе. Другие переформулировки и запросы с несколькими намерениями требуют отдельной проверки.

`client_skill_selection = NOT_OBSERVED` и `client_effectiveness = NOT_TESTED` означают отсутствие реального прогона ChatGPT/Codex/Claude. Испытания клиентов, независимые контрольные задачи и влияние на результат остаются задачей [#141](https://github.com/MikeMoore1337/ai-development-toolkit/issues/141).

### Рекомендации для составных задач без установки

```bash
python scripts/skill_routing_eval.py --recommend "Проверь API контракты и проведи SEO аудит сайта"
```

Опция `--recommend` использует существующий лексический маршрутизатор и объясняет совпадение токенов из названия, описания и подсказок. Дополнительно показывает подходящие профили, доступные роли (без автоматического выбора) и не более трёх **лексически подтверждённых** альтернатив за пределами запрошенного top-k. Случайные алфавитные соседи без совпадений исключаются. Теперь `top_k` ограничивает число **подтверждённых лексических кандидатов**, а не первые непроверенные позиции рейтинга: навык с исходным рангом 4 может быть предложен, если три первых совпадения не прошли фильтр. Поле `rank` сохраняет исходную позицию, а альтернативы не дублируют основную выдачу. Это не доказательство семантической точности. Эти имена не означают активацию навыка или подтверждённую уверенность модели. Разделение по `and`, `и` и `;` эвристическое, максимум три части. Команда не устанавливает и не исполняет навыки.

`confidence = NOT_CALIBRATED` означает, что совпадения слов не являются вероятностью корректного выбора. Результаты реального клиента остаются `NOT_OBSERVED`/`NOT_TESTED`; неопределённый выбор требует проверки человеком.

### Контрольные запросы без подгонки под словарь

Для проверки запросов, не использованных при подготовке лексических подсказок:

```bash
python scripts/skill_routing_eval.py --holdout fixtures/skill_routing_holdout.json
```

**38 отдельно составленных запросов:** 24 с одним намерением, 8 составных, 6 с явным отрицанием. Сценарии относятся к дневнику тренировок, агентным сервисам, личным данным и общим задачам разработки. В рамках этого PR набор фиксируется и не применяется для настройки словаря подсказок.

JSON-отчёт показывает `hit_at_k`, соблюдение запрета нежелательного первого варианта, количество успешных и неуспешных запросов по категориям и фактические рекомендации. Это **диагностика**, а не публикационный барьер (`strict_gate = false`). Эталоны составлены вручную и пока не прошли независимую экспертизу. Ошибочные результаты нужно регистрировать, а не менять ожидаемые ответы ради 100%.

В CI измерение отдельно от строгих подготовленных фикстур. Реальные вызовы и полезность для конечных проектов остаются задачей #141.

### Безопасное поведение при отсутствии признаков выбора

Команда `--recommend` больше не предлагает первые навыки по алфавиту, если для них не нашлось подтверждающих совпадений в названии, описании или проверенных подсказках. В таком случае `candidates` пуст, а статус - `INSUFFICIENT_EVIDENCE`. Числовая уверенность не выдумывается.

Простые явные запреты (`Не нужен SEO-аудит: ...`, `Не хочу SEO-аудит: ...`, `We're not redesigning the UI; ...`, `No need to ...`, `Skip database migration planning; ...`) отделяются от положительного запроса и перечисляются в `excluded_negated_clauses`. При наличии только запрета выводится `NO_POSITIVE_INTENT`. Это ограниченное правило для явных запретов в начале фразы (включая некоторые русские формы и английское Present Continuous), не полноценный разбор отрицаний в естественном языке. Например, `We are not sure...` обозначает неопределённость, а не запрет. Ранее подготовленный контрольный набор не изменяется.

### Дополнительные независимые от прежних наборов диагностические запросы (#273)

Добавлен `fixtures/skill_routing_untuned_20261024.json`: 16 отдельно составленных RU/EN запросов (по 8 на язык; 8 одиночных, 4 составных, 4 с явными запретами). Их тексты не дублируют подготовленные случаи, исходный holdout и предыдущие наборы из 18 и 12 запросов. Эталонные навыки предложены AI-ассистентом, **не проверены независимым человеком** и не являются исчерпывающим перечнем правильных ответов. Алгоритм, псевдонимы и прежние контрольные наборы по новым примерам не настраивались.

Команда `python scripts/skill_routing_eval.py --holdout fixtures/skill_routing_untuned_20261024.json` формирует **неблокирующий** отчёт о первичных/вспомогательных совпадениях, отказах при нехватке признаков, запрещённых рекомендациях и различиях RU/EN. CI запускает эту диагностику без платных AI/API, а корректность структуры и непересечение запросов проверяет отдельный unit-тест. Числа не означают доказанную семантическую точность либо фактическое применение навыков клиентом.

### Общий формат решения маршрутизации (#272)

Офлайновый лексический подбор и отдельный Personal MCP формируют общий **рекомендательный** объект `routing_decision`: `schema_version`, `intent_mode`, `status`, `primary_profile`, `primary_skills`, `auxiliary_profiles`, `auxiliary_skills`, `excluded_clauses`, `evidence_basis`, `uncertainty`, `client_activation`, `execution`, `installation_performed`, `project_files_changed`. Значение `primary_profile = null` в лексическом отчёте означает, что по одному совпадению терминов профиль выбирать нельзя. Personal MCP сохраняет прежние поля `profile` и `skills` для совместимости с клиентами.

Статусы `NO_POSITIVE_INTENT` и `INSUFFICIENT_EVIDENCE` не разрешают установку или исполнение. MCP отделяет явно запрещённые начальные фразы перед подбором по ключевым словам. ChatGPT-плагин использует те же смысловые границы в инструкциях, но не запускает Python-маршрутизатор автоматически. Реальная активация и эффективность клиента остаются NOT_OBSERVED / NOT_TESTED.

### Подтверждённые признаки выбора и первоначальный top-k

Для тех же 38 неизменённых контрольных запросов отчёт теперь отдельно показывает **два показателя**. Поля `passed`/`failed` сохраняют прежнюю проверку попадания в top-k, где возможен алфавитный выбор при нулевом совпадении. Поля `supported_passed`/`supported_failed` учитывают только кандидатов, для которых режим `--recommend` нашёл признаки в названии, описании или словаре подсказок. `abstained` - количество запросов без подтверждённой рекомендации; `unverified_fallback` - случаи, ошибочно выглядевшие успешными по прежней метрике, но не подтверждённые признаками.

Разбивка `by_kind` и `by_language` содержит те же показатели, а для каждого запроса сохраняются первоначальные и подтверждённые варианты. Это **лексические признаки, не вероятность корректного ответа**. Для `supported_passed` используются первые `top_k` доказательно подтверждённых кандидатов; их исходный `rank` может быть ниже, чем `top_k`, в отличие от исторического raw top-k. Эти разные способы отбора нельзя смешивать. Более низкое попадание после фильтрации и большее число отказов могут отражать безопасное поведение без изменения первоначального алгоритма.

Контрольные запросы и словарь подсказок в этом этапе не изменяются. Метрика не блокирует CI, работает без платных API и не подтверждает реальные вызовы навыков AI-клиентом.

### Человеческая проверка эталонов без подсказки прежних ответов

Ожидаемые навыки в 38 контрольных запросах составлены разработчиками и пока **не прошли независимую приёмку**. Для проверки другим человеком можно создать пакет, в котором видны только запросы и типы задач, но **скрыты исходные эталонные навыки и рекомендации алгоритма**:

```bash
python scripts/holdout_adjudication.py prepare --output human-review.json
python scripts/holdout_adjudication.py catalog --output skill-choices.json
```

Передавайте рецензенту **только** `human-review.json` и `skill-choices.json` — без исходных эталонных меток, результатов маршрутизатора и предыдущих отчётов об ошибках. Каталог содержит все заявленные `name` и `description` навыков, отсортированные и без подсказок ожидаемых ответов. Проверяйте одинаковый `catalog_sha256` двух файлов. Даже совпадающие хеши не доказывают независимость рецензента; ранее прочитанные эталоны необходимо раскрыть. Исходную фикстуру holdout слепому рецензенту не передавать.

Для каждого запроса рецензент выбирает `ACCEPT`, `CHALLENGE` или оставляет `PENDING`. При `ACCEPT` заполняет `proposed_targets`, для отрицательного сценария также `proposed_avoid_top1`, свой идентификатор `reviewer_id` и объяснение `rationale`. При `CHALLENGE` указывает причину неоднозначности, не утверждая новые эталоны. Пакет содержит хеши контрольного файла и каталога. Уже существующий файл с доказательствами не перезаписывается.

```bash
python scripts/holdout_adjudication.py audit --packet human-review.json --output review-audit.json
```

Отчёт аудита содержит `pending_case_ids` и `challenged_case_ids`: это только идентификаторы незавершённых и оспоренных случаев для повторной человеческой проверки, без эталонных меток или рекомендаций алгоритма.

Аудит проверяет целостность, непроверенные запросы, конфликтные/неизвестные навыки и расхождения между эталонами и предложением рецензента. **Автоматического изменения эталонов нет.** Даже при заполнении всех строк независимость рецензента остаётся неподтверждённой: `reviewer_independence = NOT_VERIFIED`, `ready_for_independent_accuracy_claim = false`. Сам факт наличия инструмента не означает, что внешний эксперт уже выполнил проверку. Платные API и AI-клиенты не используются.


### Диагностика маршрутизации для релизного кандидата (Issue #189)

Для каждого сегмента первая лексически подтверждённая рекомендация помечается `selection_role = PRIMARY`, остальные — `AUXILIARY`. Это **позиции предложений**, а не активация, вероятность правильного выбора или доказательство единственного подходящего навыка. При ограничении в три сегмента явные запреты удаляются *до* объединения дополнительных задач. Если запрет явно называет навык точным именем из каталога, он не предлагается даже как вспомогательный.

Отчёт `--holdout` сохраняет старые поля и добавляет `label_diagnostics`, а также поля наблюдений `supported_auxiliary_choices`, `primary_gold_match`, `auxiliary_only_gold_match`, `non_gold_primary_choices`, `forbidden_supported_primary`. Те же числа доступны в разбивке `by_kind` и `by_language`. Они помогают разделить совпадения основной и вспомогательной рекомендаций с ручными эталонами, случаи без совпадений, необоснованные по имеющимся меткам основные предложения и нарушение `avoid_top1`. **Несовпадение с ручной меткой не равно доказанному ложному срабатыванию**: эталоны могут пропускать допустимые варианты и не проходили независимую проверку.

Для воспроизведения отдельных отчётов:

```bash
python scripts/skill_routing_eval.py --holdout fixtures/skill_routing_holdout.json
python scripts/skill_routing_eval.py --holdout fixtures/skill_routing_exploratory_20261023.json
python scripts/skill_routing_eval.py --holdout fixtures/skill_routing_release_probes_20261023.json
```

На момент подготовки релизного кандидата: подготовленные тесты 416/416; исходный замороженный набор 18/38 подтверждённых совпадений (12 отказов; 15 совпадений основных и 7 только вспомогательных рекомендаций); предыдущий исследовательский набор 6/18 (6 отказов); новый набор из 12 RU/EN запросов — 4/12 (5 отказов). Последний набор и метки составлены AI-ассистентом, **не являются независимыми, слепыми или проверенными человеком** и не используются для настройки словаря или ранжирования. Наборы нельзя складывать или выдавать за семантическую точность. Алгоритм остаётся ограниченным **лексическим** подбором; реальное подключение клиентов NOT_OBSERVED, результативность NOT_TESTED (отдельная #141).

### Roadmap IV/#296: новый замороженный стресс-набор RU/EN

В [fixtures/skill_routing_stress_20261024.json](../../fixtures/skill_routing_stress_20261024.json) записаны **48 новых запросов: 24 на русском и 24 на английском**. Они охватывают 12 обычных, 12 составных, 12 с явными запретами, 6 неоднозначных и 6 запросов без подходящего навыка. **Запросы и предполагаемые метки подготовил AI-ассистент, а не независимый рецензент.** Набор зафиксирован до прогона его диагностики и без изменения словаря маршрутизации или рейтинга. Это не слепая и не независимая человеческая оценка.

```bash
python scripts/skill_routing_stress.py --summary-only
python scripts/skill_routing_stress.py
python -m unittest tests.test_skill_routing_stress -v
python scripts/skill_routing_eval.py --strict
```

Новый отчёт показывает для **каждого** запроса `primary`, `auxiliary`, `forbidden_selected` и `abstained`, отдельно считает пересечения с предложенными метками, нарушения явных запретов, необоснованные рекомендации и отказы по языкам и категориям. Метки могут быть неполными: чужой вариант **не обязательно ошибка**. Новый набор - **диагностический, не обязательный барьер CI для совпадения всех меток**; подгонка под эталоны не доказывает улучшение маршрутизации. Нарушение запрета на точное имя навыка отдельно проверено синтетическим тестом. `calibrated_semantic_accuracy = NOT_MEASURED`, `client_discovery = NOT_OBSERVED`, `client_effectiveness = NOT_TESTED`.

**Не смешивайте разные результаты:** 416/416 подготовленных проверок; 18/38 совпадений исходного контрольного набора с лексическим подтверждением; 6/18 отдельного исследовательского набора; 4/12 релизных запросов. Ещё один набор из 16 новых запросов существует отдельно. У этих наборов разные источники меток и методики, они **не складываются в общую точность** и не подтверждают уровни L4-L6. Новый отчёт воспроизводится локально на фиксированном SHA, без платных API и вызовов моделей; авторство и отсутствие независимой проверки записаны явно.

**Исходное измерение (замороженный набор, первый прогон PR #307):** всего 48 запросов, из них 36 с действием и 12 неоднозначных/вне каталога. Пересечение основных рекомендаций с предложенными метками: **26/36** запросов с действием; все ожидаемые навыки среди подтверждённых предложений: **22/36**; полный отказ - 11/48; совпадение ожидаемого отказа - 8/12; неожиданный отказ - **3/36** запросов с действием; лишняя рекомендация там, где предлагался отказ, - **4/12**; нарушение прямого запрета на навык среди основных и вспомогательных рекомендаций - **0/12** отрицательных сценариев. Основной навык совпал с предложенной меткой в 13 русских и 13 английских запросах, но на русском было 9 отказов, на английском - 2. Метки не проходили независимую проверку и могут не учитывать допустимые альтернативы: числа **не являются семантической точностью, частотой ошибок реальных пользователей или доказательством L4-L6**. Ради этого измерения не менялись алгоритм, словарь и старые фикстуры; реальные ошибки следует подтверждать отдельно.

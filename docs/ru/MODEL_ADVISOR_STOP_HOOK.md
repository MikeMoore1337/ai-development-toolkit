# Режим Model Advisor Stop hook (отдельный opt-in, эксперимент)

## Для чего нужен

В Issue #401 подтверждено: Codex Desktop вызвал Personal MCP с
`proactive_model_advice=true`, получил `NO_REVIEW_SIGNAL`, после этого
обнаружил серьёзные риски отката и Unix-инсталлятора, но не вызвал
`toolkit_model_review_checkpoint`.

MCP не получает событий чтения файлов и не может принудить Codex сделать
последующий вызов инструмента. В качестве отдельного пути используется
**официальный Codex lifecycle Stop hook**: он проверяет только последний
текст ответа, не выполняет повторный анализ исходников и при явных
признаках подтверждённых серьёзных рисков один раз просит **основную**
модель дополнить ответ необязательным предложением независимой проверки.
Это не полноценная семантическая экспертиза и не гарантия, что клиент
выполнит указание. Источник контракта: https://developers.openai.com/de-DE/docs/hooks.

## Ограничения безопасности

- По умолчанию hook **отключён**. Файлы в репозитории сами не активируют
  hooks и не изменяют настройки Codex.
- Вход — только JSON событие `Stop` из stdin (максимум 64 КиБ).
  Скрипт не открывает rollout, репозиторий, .env или сторонние файлы.
- Нет сети, внешнего API, CLI Codex/Claude, новых агентов, самостоятельного
  вызова модели, постоянных журналов или отправки фрагментов ответа наружу.
- В выходе используется только заранее заданный текст без оригинального
  содержимого чата. При ошибках — `{}`, не блокируя завершение задачи.
- Codex может сделать **дополнительное продолжение на текущей модели**,
  тратя часть включённой квоты подписки; дополнительную модель hook
  не запускает.
- `stop_hook_active=true` предотвращает повторное продолжение той же
  остановки. Hook не гарантирует подавление повторов между разными чатами.
- Статическая классификация по словам может дать false positive/negative.
  Скрипт ничего не меняет в технических выводах и не одобряет делегирование.

## Опциональная ручная установка в Codex Desktop (Windows)

**Не устанавливай одновременно с испытанием без согласия владельца.**
Изучить скрипт и его тесты после выпуска в `main`, а затем явно
разрешить этот дополнительный исполняемый hook. В глобальном
`%USERPROFILE%\.codex\hooks.json` (или `%CODEX_HOME%\hooks.json`)
добавить элемент в **уже существующий** массив `hooks.Stop` — нельзя
заменять или удалять чужие hooks. Пример отдельного файла для просмотра:

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 /absolute/trusted/path/model_advisor_stop_hook.py",
            "commandWindows": "py -3 \"C:\\Users\\YOUR_USER\\AppData\\Local\\ADT-Personal\\toolkit-source\\integrations\\personal-mcp\\adt-personal\\hooks\\model_advisor_stop_hook.py\"",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

Путь `YOUR_USER` заменить на свой, учесть `CODEX_HOME` и наличие уже
установленных hooks. Любое изменение hook требует повторного доверия
со стороны Codex. Не обходить проверку доверия и не использовать Codex CLI.
Проверять и подтверждать hook только в доступном **нативном интерфейсе**;
если клиент не предоставляет нужный UI — оставить режим отключённым.
Никакие инструкции в этом README не являются разрешением установить hook
автоматически.

## Отключение

Удалить **только созданную запись** из глобального `hooks.Stop` и
перезапустить Codex Desktop; другие hooks и `AGENTS.md` оставить нетронутыми.
Отключение блока `ADT-MODEL-ADVISOR` в `AGENTS.md` само по себе
не удаляет hook — это отдельный opt-in.

## Доказательства для закрытия #401

1. Отдельный review/trust для hook в реальном Codex Desktop на Windows.
2. Положительный кейс: подтверждённые серьёзные дефекты → одна рекомендация
   в тексте чата, без делегирования и без бесконечных продолжений.
3. Отрицательный: обычная правка README → без лишних рекомендаций.
4. При этом обычный Personal MCP сохраняет read-only контракты.

Тесты этого пакета проверяют лишь классификацию и формат stdout на
синтетических событиях. Они не подтверждают нативное включение/поведение.

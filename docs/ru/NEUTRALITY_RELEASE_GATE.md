# Проверка универсальности и исходных архивов перед выпуском

[English](../NEUTRALITY_RELEASE_GATE.md) | [Задача #396](https://github.com/MikeMoore1337/ai-development-toolkit/issues/396)

Публичный Toolkit должен быть универсальным и не зависеть от названий личных проектов или их внутренних правил. Текстовые файлы из Git проверяет validate_public_docs_neutrality.py, а исходные ZIP-архивы и пакеты интеграций проверяет audit_source_archive.py. Содержимое архивов не распаковывается и не выполняется.

## Команды

    python scripts/validate_public_docs_neutrality.py --repository example-owner/toolkit
    python -m unittest tests.test_public_docs_neutrality tests.test_audit_source_archive -v
    git archive --format=zip --output=source.zip HEAD
    python scripts/audit_source_archive.py --zip source.zip --repository example-owner/toolkit

Замените example-owner/toolkit на свой репозиторий. При необходимости передайте --local-denylist /outside/repo/identifiers.txt - личный локальный список для поиска. Файл не должен храниться в репозитории, а совпавшие части названий файлов скрываются в отчёте.

Инструмент проверяет имена файлов, символьные ссылки, обход каталогов, дубли, вложенные архивы, шифрованные элементы, размер и аномальное сжатие. Содержимое читаемых файлов UTF-8 (Markdown, Python, JSON, YAML, CSV, SVG) проверяется без запуска. Бинарные данные учитываются отдельно и не считаются проверенными: PASS **не доказывает отсутствие личных сведений во всех изображениях и бинарных файлах**.

Контроль SHA256, происхождения исходников и прав на распространение остаётся обязательным. Успешный CI не означает установку навыка, запуск модели или проверенную эффективность L4/L5.

## Для каждого пользователя

[Индивидуальные настройки](USER_SETTINGS.md) хранятся отдельно от публичного Toolkit. [Политики клиентов](CLIENT_POLICY_ROUTES.md) предоставляют варианты для Codex Desktop, Codex CLI, Claude Code, ChatGPT, MCP и API без запуска. Другой пользователь может самостоятельно разрешить CLI или платный API, но реальный вызов требует отдельной проверки прав, стоимости, лимитов и разрешения для задачи. Стандартный сценарий не предполагает расходов.

Выпуск требует зелёного CI точного коммита PR, объединения в защищённый main и отдельного успешного CI после объединения. Исторические релизы и Git-история не переписываются. Установка из репозитория доступна без публикации в сторонних каталогах.

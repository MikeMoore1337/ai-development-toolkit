# Нативная оценка бюджета метаданных профилей (#439)

В Toolkit сохраняются собственные **49 профилей**, Skill Manager и существующий маршрутизатор навыков. Сравниваемый источник: `affaan-m/ECC@25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b`, `manifests/context-profiles/lean@1.json`, `full@1.json`, `scripts/profile.js`. ECC предлагает для `lean` три **специфических для ECC** навыка и ограничение 8000 токенов на метаданные, а `full` - все описания. Оригинал не подтверждает фактическую загрузку контекста в клиенте. Переносить профиль буквально означало бы добавить сторонний реестр и второй маршрутизатор.

Toolkit уже умеет подсчитывать размер файлов, число навыков и пересечения профилей через `scripts/profile_metrics.py`, а также давать рекомендации по запросу через `scripts/skill_routing_eval.py`. Полезный недостающий элемент - **явное сравнение размера YAML-метаданных выбранного штатного профиля с заданным бюджетом в байтах**, не меняя маршрутизацию.

Пример запуска в доверенном checkout:

```sh
python scripts/profile_metrics.py --profile general --metadata-budget-bytes 8000
```

В ответе появляется `metadata_budget_preview`: размер UTF-8 frontmatter каждого `SKILL.md`, общий размер, превышение лимита и `within_budget`. Ничего не устанавливается и **не исключается автоматически** из профиля. Сравнение ведётся **в байтах, не в токенах**: `tokens=NOT_MEASURED`, `host_context=NOT_OBSERVED`, `activation=NOT_VERIFIED`, `applied=false`. Число 8000 в примере означает **байты**, а не лимит 8000 токенов ECC. Это разные метрики.

Некорректный бюджет, отсутствующий навык, ссылка вместо директории и неверный YAML отклоняются. Нет второго маршрутизатора, платных API, Codex CLI, Claude CLI, подключения ECC, автоматической настройки клиента и новых постоянных файлов. Откат - удалить необязательную функцию, параметр и документацию/тесты обычным PR. Настоящая экономия токенов и активация в Codex Desktop остаются **NOT_VERIFIED**.

## Проверка входных данных и отказ при ошибках

Предварительный просмотр использует **существующий** валидатор навыков Toolkit (`scripts/validate_pack.py`, PyYAML из штатного `requirements-dev.txt`). Он отклоняет повреждённый YAML, повторяющиеся ключи, несоответствие `name` директории, неполные метаданные, не-UTF-8 источники, символические ссылки и Windows junction, выход за корень репозитория и некорректный список навыков. Отсутствие зависимости для валидации приводит к отказу, а не к неподтверждённому положительному результату. Для чистого окружения предусмотрена обычная установка зависимостей разработки: `python -m pip install -r requirements-dev.txt`; отдельная служба или провайдер моделей не требуется.

Размер включает строку открытия и строку закрытия YAML frontmatter (вместе с завершающим переводом строки, если он есть). Содержание `SKILL.md` после границы, `references/`, системные инструкции хоста и данные модели **не входят** в эту метрику. Результат не предполагает, что хост действительно загружает все указанные метаданные.

Проверка на изолированных синтетических данных:

```sh
python -m unittest discover -s tests -p test_profile_budget_preview.py -v
python scripts/profile_metrics.py --profile general --metadata-budget-bytes 8000
```

При превышении бюджета интерфейс только сообщает число превышенных байтов; обязательные навыки и порядок профиля не меняются. Для отключения достаточно **не указывать** `--metadata-budget-bytes`. Выбор навыков и конфликтующих контроллеров регулируется существующими механизмами; подтверждённая семантическая эквивалентность и живое потребление токенов здесь не измеряются. Применение более компактного профиля требует отдельного решения пользователя. Неизвестный клиент в этом автономном просмотре не активируется и не проверяется.

Дополнительный регрессионный тест запускает предварительный просмотр для **всех профилей из текущего MANIFEST.json**, проверяет сохранение полного состава и порядка навыков и отсутствие автоматического применения. Синтетические negative tests охватывают ссылку на директорию, Windows junction (если операция поддерживается тестовым окружением) и отказ от обращения к файлам вне корня Toolkit.

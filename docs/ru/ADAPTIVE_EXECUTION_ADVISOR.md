# Adaptive Execution Advisor - универсальный советник по моделям (Issue #356)

[English](../ADAPTIVE_EXECUTION_ADVISOR.md)

Это **необязательный офлайновый механизм рекомендаций и согласия**, а не готовое переключение моделей. Он дополняет существующие маршрутизаторы задач, навыков и оркестрации, не создавая ещё один исполнитель агентов.

## Сценарий пользователя

1. Клиент принимает задачу, а существующий Toolkit подбирает профиль и навыки. Можно передать сигналы: `routine`, `architecture`, `security`, `design`, `ambiguous`, `repeated_failure`.
2. Если клиент умеет, он сообщает **реально доступные модели** и поддержку делегирования. При отсутствии достоверных сведений указывается UNKNOWN; список нельзя угадывать по названию провайдера. Введённый вручную перечень не получает VERIFIED без проверки клиента.
3. Перед дополнительным обращением Toolkit **обязательно показывает три режима, их преимущества и риски, спрашивает выбор для текущей задачи**. Если ответа нет, дополнительных обращений нет.
4. `SINGLE_MODEL` - только текущая модель. `RECOMMEND_WITH_CONFIRMATION` - рекомендация с **отдельным подтверждением каждого запуска**. `AUTO_OPT_IN` - автоматические консультации только среди разрешённых моделей и не более `max_extra_calls` обращений на задачу.
5. Если пользователь отменил разрешение, изменились лимиты, набор моделей или версия обнаружения - остаёмся на текущей модели. Адаптер **обязан заново проверить согласие непосредственно перед запуском**.

## Польза и риски

| Режим | Польза | Риски |
| --- | --- | --- |
| Одна модель | Меньше передач контекста, предсказуемые лимиты | Сложная задача может занять больше итераций |
| С рекомендациями | Пользователь решает, какую из доступных моделей применять | Дополнительные обращения, время, расход лимитов; улучшение не гарантировано |
| Автоматика | Меньше ручных действий при разрешённых консультациях | Расход квот, задержка и передача части контекста; улучшение не гарантировано |

## Использование

`python scripts/adaptive_execution_advisor.py request.json [--consent consent.json]`

Формат `request.json`:

```json
{
  "task_id": "demo-001",
  "locale": "ru",
  "current_model": "client-model-A",
  "available_models": ["client-model-A", "client-model-B"],
  "inventory_status": "VERIFIED",
  "inventory_revision": "client-discovery-revision-1",
  "switching": "UNKNOWN",
  "delegation": "VERIFIED",
  "zero_incremental_cost_verified": true,
  "signals": ["architecture"]
}
```

Результат без согласия содержит `user_selection_required=true`, `selected_mode=null`, `execution=NOT_RUN`, объяснение режимов и ограничений. Это **не разрешение на запуск**.

Отдельное согласие пользователя (только пример):

```json
{
  "task_id": "demo-001",
  "inventory_revision": "client-discovery-revision-1",
  "mode": "AUTO_OPT_IN",
  "approved_models": ["client-model-B"],
  "max_extra_calls": 2
}
```

Функция `authorize` лишь проверяет поля и ограничения; она **не запускает модель и не сохраняет постоянное разрешение**. Клиент обязан проверять актуальность разрешения, факт бесплатного вызова и остатки лимитов. `zero_incremental_cost_verified` в этом модуле - заявление вызывающей стороны, а не независимый результат проверки.

## Проверки и ограничения

Тесты: `python -m unittest tests.test_adaptive_execution_advisor` (либо стандартное обнаружение тестов). Проверяются отсутствие согласия, один вариант модели, отрицательные сценарии, устаревший перечень, языки RU/EN и отсутствие изменений файлов.

Успешные офлайновые тесты **не доказывают** переключение в реальном Codex, Claude или DeepSeek, экономию лимитов или повышение качества. Реальные адаптеры и наблюдаемые испытания относятся к **Issue #357**.

### Интеграция MCP

Проектный MCP предоставляет инструменты `toolkit_advise_execution` (`request`) и `toolkit_check_execution_consent` (`request`, `consent`) только для чтения. Они возвращают рекомендации или проверку разрешения в JSON; не переключают модели и не запускают агентов. Существующая маршрутизация профилей и навыков остаётся без изменений.

# Оценка навыков: парные испытания (экспериментальный метод)

[English source](../SKILL_EVALS.md) | [Реальные испытания агентов](REAL_AGENT_PILOT.md) | [Офлайновые проверки маршрутизации](../SKILL_ROUTING_EVALS.md)

Это **инструмент подсчёта результатов, а не средство запуска агентов и не сертификация эталонных испытаний**. Он не обращается к удалённым учётным записям, не выполняет задачи в целевых проектах, не восстанавливает отсутствующую телеметрию и не решает самостоятельно, подтверждают ли файлы заявленный результат.

## Сбор данных

Для каждого задания зафиксируйте SHA исходного репозитория, формулировку задачи и критерии приёмки. На **одной и той же версии модели с одинаковыми разрешениями инструментов** проводите испытание без навыка (`baseline`) и с навыком (`candidate`). По возможности меняйте порядок этих условий между повторами для снижения систематической погрешности. Независимые проверяющие должны исследовать реальные результаты и внести только наблюдаемые показатели.

Формат данных: `schema_version=1`.

```json
{
  "schema_version": 1,
  "dataset": "pilot-2026-10",
  "model": "provider/model-version",
  "repository_sha": "full-pinned-commit",
  "runs": [
    {
      "task_id": "api-error-case",
      "trial": 1,
      "variant": "baseline",
      "accepted": false,
      "regressions": 0,
      "unsafe_actions": 0,
      "tokens": null,
      "duration_seconds": null,
      "evidence": ["evidence/api-error-case-baseline-1.txt"]
    },
    {
      "task_id": "api-error-case",
      "trial": 1,
      "variant": "candidate",
      "accepted": true,
      "regressions": 0,
      "unsafe_actions": 0,
      "tokens": null,
      "duration_seconds": null,
      "evidence": ["evidence/api-error-case-candidate-1.txt"]
    }
  ]
}
```

Пути из `evidence` должны быть относительными к JSON-файлу, существовать и указывать на непустые файлы. Каждая пара `task_id/trial` должна иметь ровно один `baseline` и один `candidate`. Значение `accepted` - логическое. Счётчики `regressions` и `unsafe_actions` - известные неотрицательные целые числа. Поля `tokens` и `duration_seconds` могут быть `null`, если не измерены; **придумывать значения запрещено**. Идентификаторы набора данных, модели и исходного SHA должны совпадать внутри пары.

Пример JSON выше показывает **формат**, а не результат реального эксперимента.

## Подсчёт результатов

```bash
python scripts/skill_eval.py /path/to/recorded-runs.json
python -m unittest tests.test_skill_eval -v
```

Программа выводит машиночитаемый JSON: доли принятых задач, разницу пар в процентных пунктах, число регрессий и небезопасных действий, а также средние показатели затрат и времени **при наличии измерений**. Классификация: `classification: exploratory`. Инструмент не рассчитывает статистическую уверенность и не проверяет содержимое приложенных доказательств. Даже большая разница остаётся предварительной гипотезой до серии сопоставимых независимых испытаний. Результаты синтетических модульных тестов не являются реальным эталонным сравнением.

## Испытания реальных Codex и Claude (Issue #11)

[Англоязычная процедура](../REAL_AGENT_PILOT.md) и [русское руководство оператора](REAL_AGENT_PILOT.md) описывают ограниченный механизм CLI-испытаний Codex/Claude, три синтетических примера Python/JavaScript/Go со скрытыми проверками и обязательный независимый просмотр журналов.

**Issue #11 закрыта как CLOSED / NOT_PLANNED по обязательному ограничению владельца ZERO-SPEND:** реальные вызовы агентов сейчас заблокированы непосредственно в `scripts/agent_eval_runner.py`. Параметр `--execute` запрещён; использование `--acknowledge-costs` и `--acknowledge-isolation` не снимает запрета. Ни аутентификация клиента, ни наличие `SKILL.md` не доказывают активацию навыка. До отдельно согласованного, проверяемо бесплатного и изолированного способа реального испытания статус `NOT_RUN`, результат `NOT_MEASURED`. Успешный CI не доказывает эффективность модели.

## Бесплатные проверки лексической маршрутизации

[Офлайновые проверки маршрутизации навыков](../SKILL_ROUTING_EVALS.md) сопоставляют положительные и отрицательные формулировки с описаниями **65 навыков исходного проверочного набора**. Это детерминированная аппроксимация по тексту источников, а **не фактическое обнаружение, вызов или эффективность навыков моделью**. Число 65 - историческая характеристика исходного набора, **а в текущем манифесте заявлены 82 навыка**. Автономные результаты не означают независимую семантическую точность. Испытания реальных Codex/Claude заблокированы по Issue #11. Бесплатный исследовательский пилот Issue #141 завершён в ограниченном объёме и не подтверждает эффективность всех навыков, реальную активацию L4-L6 или измеренную экономию времени.

**Границы подтверждений:** `classification: exploratory` не означает независимую приёмку; `NOT_MEASURED` означает отсутствие измерений, а не нулевой расход. Публичные заявления о пользе требуют действительных парных испытаний и независимой проверки.

## Практическая оценка полезности профилей (Issue #298)

[Пять сопоставимых обезличенных задач](PROFILE_BENEFIT_EVAL.md) для `general`, `backend`, `fullstack`, `qa-python` и `ui-orchestra`. Бесплатная команда `python scripts/profile_benefit_preflight.py` сверяет состав каталога, проверочные критерии и фактические **байты исходных файлов**; показатели качества и времени при выполнении моделями имеют статус `NOT_MEASURED`. Необязательный `--score` читает **ранее полученные** 20 парных записей и использует уже имеющийся счётчик. Он не запускает клиентов, не проверяет независимость рецензента по его собственному заявлению и не снимает ZERO-SPEND Issue #11. Синтетические результаты не являются доказательством L6.

## Дополнительная проверка нативных квитанций (#437)

Для ранее записанных парных прогонов с капсулами можно **явно включить** проверку целостности:

```bash
python scripts/skill_eval.py /path/to/recorded-runs.json --verify-native-receipts
```

У каждого прогона `baseline` и `candidate` должно быть ровно одно поле `native_receipt` с тремя относительными путями:

```json
"native_receipt": {
  "receipt": "receipts/api-baseline-1.json",
  "capsule_dir": "capsules/api-baseline-1",
  "artifact": "evidence/api-error-case-baseline-1.txt"
}
```

Пути отсчитываются от JSON с результатами, не выходят за пределы общего каталога и не должны проходить через символические ссылки. Поле `artifact` обязано совпадать с одним из файлов `evidence` данного прогона. Капсула уже должна содержать `capsule.json`, `journal.ndjson`, `projection.json`. Запрос добровольно вызывает **встроенный** автономный `scripts/native_eval_capsules.js receipt verify` (требуется Node.js), без shell, модели, агента, сети или записи файлов. Некорректные, повреждённые, устаревшие, отсутствующие и подменённые файлы отклоняются; до 64 квитанций на оценку.

Поля результата: `native_receipts_verified` и `native_evidence_integrity: OFFLINE_VERIFIED_NOT_OUTCOME`. **Проверяется лишь целостность предоставленных локальных материалов**, а не личность автора, корректность оценки, реальный успех агента, невозможность полной подмены истории или разрешение на публикацию. Если `native_receipt` указан без явного флага проверки, программа отказывает, а не игнорирует его. Старый режим оценки без квитанций сохраняется.

Источники и ограничения библиотеки: [Нативные капсулы](NATIVE_EVAL_CAPSULES.md).

## Необязательный анализ стабильности записанных испытаний (#435)

```bash
python scripts/skill_eval.py /path/to/recorded-runs.json --observed-repeatability
```

Без параметра прежний вывод не меняется. Раздел
`observed_repeatability` показывает `observed_pass_at_1`
(успех с первой попытки), `observed_pass_at_3` (хотя бы один успех
за первые три) и `observed_pass_all_3` (успех во всех трёх).
Успех считается чистым при `accepted=true`, `regressions=0` и
`unsafe_actions=0`. Если для **любой** задачи отсутствует требуемый
номер повтора, соответствующий показатель получает `null` и
`NOT_MEASURED_INCOMPLETE_TRIALS`, а не выдуманный ноль.
Повторы с четвёртого не участвуют.

Синтетический проверочный набор содержит три задачи по три прогона
для каждого варианта: общая успешность одинакова (`6/9=66,67%`),
а прохождение всех трёх повторов отличается (`2/3` и `0/3`).
Это доказательство **полезности офлайнового отчёта**, а не того,
что оригинальный навык улучшает AI-модель. Это наблюдаемые результаты
записей, не статистическая оценка pass@k и не верификация фактической
независимости испытаний. `classification: exploratory` и независимая
проверка остаются обязательными. Полный ECC `eval-harness`
продолжает иметь статус `HOLD_REVIEW` до испытаний реальных оценщиков.

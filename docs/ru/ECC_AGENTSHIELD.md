# Подключение оригинального ECC AgentShield (#432)

Необязательный GitHub workflow запускает **оригинальный** [AgentShield](https://github.com/affaan-m/agentshield) через его GitHub Action. Проверенный источник: `affaan-m/agentshield@b0891303bdcd6037376a94263d45cfd2ff3dfb98` (пакет `ecc-agentshield` 1.6.0, корневая лицензия MIT). Правила сканирования не копируются и не переписываются. Установка npm на рабочий компьютер, Codex CLI/Claude CLI, вызовы моделей, изменение Toolkit runtime не нужны.

## Как работает

- **Текущее поведение (05.11.2026): исключительно ручной запуск.** У workflow есть только `workflow_dispatch`; PR/push автоматически его не вызывают. Исторический PR #441 запускал оригинальный сканер, но для новых PR требуется отдельное решение. Режим `synthetic` проверяет подготовленную фикстуру; `repository` анализирует публичные исходники Toolkit. Для обоих режимов проверяется квитанция evidence-pack.
- **По явному запуску:** Actions → **ECC AgentShield (opt-in)** → Run workflow → выбрать `repository` или `synthetic`. При проверке репозитория находки информационные: `fail-on-findings=false`. Ошибка сканера, некорректный SARIF или отсутствие подтверждённого evidence-pack приводят к неуспеху workflow. Автоматический запуск при PR не предусмотрен.
- Только `contents: read`; GitHub credentials после checkout не сохраняются. SARIF и очищенный evidence-pack создаются во временной директории runner, выгружаются как GitHub Actions artifacts сроком на 7 дней. Нет автоматического Code Scanning upload, записи в репозиторий, резидентного процесса, добавления MCP/хуков или доступа к приватным клиентским данным.

## Безопасность и ограничения

Закрепление SHA исходников защищает от изменения Git-тега, но **не доказывает** безопасность всех зависимостей и отсутствие внешних сетевых обращений. Включена штатная офлайн-проверка supply-chain; выключены онлайн-запросы npm metadata, активные injection-тесты, исполнение хуков в sandbox, `--opus`, `--deep`, `--fix`, платные провайдеры и автонаблюдение.

Зелёная проверка синтетики означает только успешный запуск настоящего сканера и обнаружение преднамеренной ошибки. Это не подтверждает безопасность Toolkit, установку AgentShield в Windows Codex Desktop или отсутствие ложных результатов. Балл AgentShield **не равен** разрешению на релиз. Сопоставлять результаты с существующими SkillSpector и Cisco MCP Scanner и проверять обнаруженные проблемы вручную.

**Отключение:** удалить/отключить `.github/workflows/ecc-agentshield.yml` отдельным проверенным PR. Глобальные настройки не меняются, новую систему исполнения не создаём. За хранение артефактов и минуты GitHub Actions отвечает действующий тариф репозитория; платные API не подключаются.

## Проверяемые состояния

- `SOURCE_REVIEWED`: проверены исходный манифест action с `node24` и наличие `dist/action.js`, pin.
- `ORIGINAL_SCANNER_SMOKE`: требуется завершённый workflow с реальными находками, SARIF 2.1.0 и проверенным evidence-pack.
- `REAL_REPOSITORY_SCAN`: отдельно запущенный вручную анализ публичного репозитория с разбором находок. Прежние PR-проверки - исторические свидетельства.
- `WINDOWS_DESKTOP`: не входит в этот этап и не выводится из статуса GitHub Actions.

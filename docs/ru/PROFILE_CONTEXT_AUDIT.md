# Контекст профилей: проверка 3 и 5 инструкций без потери ограничений (#299)

[English](../PROFILE_CONTEXT_AUDIT.md) | [Метрики файлов](../../scripts/profile_metrics.py) | [Personal MCP](../../integrations/personal-mcp/README.ru.md)

## Что проверено и как повторить

Это **автономный аудит без записи в рабочие проекты** на исходной ревизии `main@f0903be39787df39584a22087329840cb4feaa4b`. Переиспользованы `scripts/profile_metrics.py`, поле `context_load_metrics` из #276 и существующий Personal MCP, без переписывания защищённых исходников навыков.

```bash
python scripts/profile_context_audit.py
python scripts/profile_context_audit.py --audit-duplicates --audit-directives
python -m unittest tests.test_profile_context_audit -v
```

На **одних и тех же запросах** сравниваются `general`, `backend`, `fullstack`, `qa-python`, `ui-orchestra`, при одинаковых списках известных навыков/ролей и лимитах `max_skills=3` и `max_skills=5`. Отчёт содержит порядок навыков, фактически **возвращённые байты UTF-8 инструкций и роли**, оставшиеся навыки и число предварительно загруженных references. Ни один режим не читает references заранее: дополнительные навыки доступны через `toolkit_get_skill`, ссылки - через `toolkit_get_reference`. **Байты инструкций не являются токенами модели, задержкой или доказательством пользы**; уровни L4-L6 остаются `NOT_MEASURED` / `NOT_RUN`.

## Факты и исправление

- Профили `general`, `backend`, `fullstack` закономерно используют общие `implementation` и `qa-strategy`. **Общее членство разных профилей не равно повторной загрузке** в рамках одного запроса: список уникализирован, известные клиенту навыки не перечитываются, оставшиеся инструкции отложены.
- Команда `--audit-duplicates` ищет побайтовые совпадения SHA256 и пересечения профилей; `--audit-directives` выявляет похожие текстовые директивы. Это **кандидаты на экспертную проверку**, не доказанная семантическая идентичность: отрицания, исключения и права могут отличаться. Безопасно удалять инструкции по одному совпадению слов нельзя.
- **Исправлен реальный дефект:** при явном `profile=ui-orchestra` и просьбе создать сайт или экран могла пропадать стадия `create-design`, хотя автоматический выбор её выставлял. Явный профиль **не означает согласование макета**. Новая защита и тесты восстанавливают обязательную стадию, ничего не реализуя и не публикуя вместо пользователя.
- **Защита от конфликтующих контроллеров:** одновременно нельзя активировать `feature-delivery`, `adaptive-delivery` и `make-feature`; при этом независимые QA-навыки доступны.
- **Отрицательные проверки:** отсутствие усечения инструкций, уникальность выбранных навыков, честное `NOT_PROVIDED` для неизвестного инвентаря, отсутствие незапрошенной загрузки references/записи проекта, сохранение требований `AGENTS.md`, согласования и запрета выдумывать успешные тесты.

## Решение

Сохраняем введённое в #276 значение **3 инструкции по умолчанию** с возможностью явно запросить **5** и отложить остальные. Оснований сокращать защищённые SKILL.md нет. Единственное изменение логики - восстановление обязательного визуального согласования при явном выборе UI-профиля. Размеры до/после публикуются в логах точного CI как **байты исходного текста**, без заявлений об экономии токенов. Платные API/CLI, модели и реальные проекты не запускались.

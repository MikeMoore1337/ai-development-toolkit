# Испытание оркестрации без дополнительных расходов

[English](../ORCHESTRATION_PILOT.md) | [Задача #141](https://github.com/MikeMoore1337/ai-development-toolkit/issues/141) | [Действующий механизм проверки агентов](../REAL_AGENT_PILOT.md)

## Цель и ограничения

Сравнить одного разработчика-агента с оркестрацией, вызывающей 2–3 **действительно независимых** эксперта на чтение. [Реестр](../../fixtures/orchestration_pilot_reference.json) является синтетической фикстурой со статусами `NOT_RUN`; результаты реальных испытаний, если они есть, отдельно зафиксированы в [Issue #141](https://github.com/MikeMoore1337/ai-development-toolkit/issues/141). Просмотр исходников, успешный CI и обычное переключение ролей не доказывают эффективности отдельных субагентов.

В `scripts/agent_eval_runner.py` действует запрет владельца на вызовы моделей с возможными дополнительными расходами. **Не снимать блокировку**, не передавать `--execute`, не арендовать виртуальную машину, не использовать production VPS, не подключать провайдера и не считать подписку подтверждением отсутствия перерасхода. Нужны отдельное подтверждение нулевой стоимости, изоляции, работающих клиентов и необходимых разрешений. Проверка контейнера H15 21.10.2026: `codex` и `claude` не обнаружены; модели не вызывались.

## Три переносимых сценария

| Тип системы | Пример проверки только на чтение | Граница безопасности |
| --- | --- | --- |
| Веб- или мобильное приложение | Сохранение изменения через интерфейс, API и хранилище; повтор запроса | Без данных пользователей и реальной записи |
| Агентный сервис | Синтетическое событие: проверка фактов, решение об оповещении | Без вымышленных действий, секретов и активации служб |
| Приложение с приватными данными | Явное подтверждение действия, идемпотентность и сверка неопределённого исхода | Без доступа к личным записям и внешних действий |

Для двух режимов фиксируется одна и та же неизменяемая ревизия; исторические SHA и трассы хранятся в связанном Issue. В варианте **A** один агент проверяет зафиксированные критерии в режиме чтения. В **B** тот же клиент и модель используют оркестратора и 2–3 реально вызванных независимых эксперта, без конкурентной записи. Порядок A/B меняется между сценариями. При отсутствии инструмента субагентов используется честная метка `SEQUENTIAL`, но такой прогон **не** считается экспериментом с многоагентной системой.

Записываются только наблюдаемые идентификаторы вызовов, версия клиента/модели, SHA, фактическое время, результаты тестов, найденные дефекты и лимиты, если клиент действительно их показывает. Не вычислять «экономию» из объёма текста или синтетических тестов. Любые изменения продукта выполняются отдельно через разрешённые Issue, PR и CI.

## Офлайн-проверка утверждений

    python scripts/validate_orchestration_pilot.py fixtures/orchestration_pilot_reference.json
    python -m unittest tests.test_orchestration_pilot -v

Валидатор выявляет вымышленные запуски, отсутствие следов отдельных исполнителей, неподтверждённые права, ошибочное сравнение разных моделей и преждевременные выводы. Он **не доказывает подлинность** журналов и разрешений. Максимальный статус - `PENDING_INDEPENDENT_REVIEW`, а не автоматический успех.

## Безопасный выбор режима оркестрации (Issue #279)

Существующий `scripts/validate_orchestration_pilot.py` предоставляет **чистую офлайновую функцию** `recommend_execution_mode(...)`. Это **рекомендация**, а не запуск агентов, планировщик, бенчмарк или разрешение на запись.

- **SINGLE_AGENT** — режим по умолчанию, если описана только задача или неизвестны возможности клиента. Дополнительные модели и API не вызываются.
- **SEQUENTIAL_REVIEW** — последовательное ревью, если оно нужно и проверенно доступен рецензент. Записи выполняются только последовательно, по правилам проекта.
- **OPTIONAL_PARALLEL_READ_ONLY** — лишь возможный сценарий при наличии 2–3 реально независимых задач **только для чтения**, подтверждённой независимости, проверенной поддержки параллельных исполнителей клиентом, явного разрешения владельца, доказанных нулевых дополнительных расходов и изоляции, **без каких-либо конкурентных записей**. Если хотя бы один пункт не подтверждён, остаётся последовательное ревью или одиночный агент. Рекомендация не запускает исполнителей.

Пример анализа без запуска моделей:

```python
from scripts.validate_orchestration_pilot import recommend_execution_mode

decision = recommend_execution_mode(
    needs_review=True, reviewer_available=True, writes_requested=True
)
assert decision["mode"] == "SEQUENTIAL_REVIEW"
assert decision["execution"] == "NOT_RUN"
```

Во всех ответах остаются `actual_worker_invocations=0`, `project_files_changed=false`, `model_tokens=NOT_MEASURED`, `expected_speedup=NOT_MEASURED`, `evidence_status=DECLARED_GATES_NOT_RUNTIME_PROOF`. Офлайновые тесты подтверждают лишь правило выбора. Небольшой неоднородный A/B-пилот #141 не доказывает универсальное ускорение; дополнительный платный AI и доступ к проектам этот маршрут не включает. Реальные вызовы и расходы требуют отдельной приёмки и разрешений.

**Наличие исходников не доказывает выполнение.** В реестре испытаний по-прежнему `NOT_RUN`, `owner_runtime_approved=false`, `verified_zero_incremental_cost=false` и `verified_isolation=false`; отдельные исполнители и сравнение A/B остаются `NOT_RUN` / `NOT_MEASURED`. Архив, успешный CI или установленный навык не снимают запрет на запуск модели без проверки стоимости и изоляции. Публикация и вызовы моделей требуют разных разрешений.

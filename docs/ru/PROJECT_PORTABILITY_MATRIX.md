# Переносимость QA и UX/UI: пять типов проектов (Issue #300)

[English](../PROJECT_PORTABILITY_MATRIX.md) · [Read-only preflight](PROJECT_ADOPTION_PREFLIGHT.md) · [QA change impact](QA_CHANGE_IMPACT.md) · [UX/UI ограничения](UX_UI_EVALS.md)

Это **синтетический автономный тест**, а не эксперимент с реальными агентами или опубликованными продуктами. Он не читает и не меняет проекты владельца или работодателя. Пять переиспользуемых структур зафиксированы в [фикстуре](../../fixtures/project_portability_20261024.json) относительно `main@3fb90c41162da1cb4f0fb58c15dc72729feb5703`. Сценарии и критерии составлены AI-ассистентом; независимая человеческая оценка отсутствует.

| Проект | Маркеры | Профиль QA | Контрольные риски | Визуальная приёмка |
| --- | --- | --- | --- | --- |
| Python backend | pyproject, pytest | `qa-python` | Контракты API, негативные запросы, миграция/откат БД | Не требуется |
| Frontend UI | package, конфиг Playwright | `qa-ui` | Состояния интерфейса, браузерные сценарии | Новый сайт: **три направления**, обязательное рассмотрение человеком |
| Fullstack | pyproject, package, Playwright | `qa-fullstack` | UI/API/DB, откат, сквозные проверки | Существенный редизайн: **три направления**, обязательное рассмотрение человеком |
| Agent service | pyproject | `qa-python` | Повторная доставка, идемпотентность и границы авторизации | Не требуется |
| Docs-heavy | README, политики, docs | `qa-core` | Редакторская проверка, **не предполагаются выполненные тесты** | Не требуется |

## Воспроизведение без токенов и секретов

```bash
python scripts/project_portability_matrix.py
python -m unittest tests.test_project_portability_matrix -v
```

Скрипт создаёт пять **временных каталогов только с фиктивными файлами-маркерами**, вызывает существующие `project_adoption_preflight.inspect` и `qa_change_impact.plan` **только на именах файлов и заранее заданных изменённых путях**, а затем сверяет побайтовые снимки каталогов. Для UI-сценариев он проверяет правила `ux_ui_evals.catalog`, **не создавая** изображений и не имитируя согласование. Пропавшая критичная QA-проверка или стадия визуального рассмотрения **ломает тест**.

Каждая проверка QA остаётся `NOT_RUN`; содержимое политик проектов не анализировалось (`PRESENT_UNREAD`). Применение клиентом `NOT_RUN`, эффективность L6 `NOT_MEASURED`, реально отображённые макеты `NOT_PRODUCED`, визуальное согласование `NOT_OBSERVED`. Нет установки, запуска моделей/API, изменения настоящих проектов или продакшен-деплоя. Результаты подтверждают только **маршрутизацию по структуре и защиту от некорректных состояний**.

Эти фикстуры **не заменяют** независимые испытания на разных архитектурах из [QA_PORTABILITY.md](QA_PORTABILITY.md). При отдельно разрешённой реальной проверке потребуются изолированные проекты, фактические оракулы тестов, визуальные снимки и независимая человеческая приёмка.

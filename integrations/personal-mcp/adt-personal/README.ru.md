# AI Development Toolkit - персональная интеграция

> **Linux и macOS:** универсальные инструкции находятся в [`integrations/personal-mcp/README.ru.md`](../README.ru.md). Этот внутренний документ сохраняет подробности первоначальной реализации для Windows.


Версия пакета `0.1.7`, 21 октября 2026. MCP-сервер: `0.1.7`, протокол: `2025-06-18` (8 доступных инструментов). **Распространяется как самостоятельная интеграция Toolkit.** Версия MCP независима от версии библиотеки навыков.

## Что готово

- `mcp/adt_mcp.py` - локальный MCP-сервер (stdio, JSON-RPC, Python 3.10+, без зависимостей). 7 доступных только для чтения инструментов: `toolkit_info`, `toolkit_catalog`, `toolkit_route_task`, `toolkit_get_guide`, `toolkit_get_skill`, `toolkit_get_reference`, `toolkit_get_role`.
- `Install-ADT-Personal.ps1` - однократная настройка на Windows: отдельно клонирует исходный Toolkit, проверяет локальный MCP, копирует сервер в постоянный каталог `%LOCALAPPDATA%\ADT-Personal\mcp`, добавляет сервер и короткую инструкцию в **глобальные** настройки Codex / Claude Code. Перед изменением существующих настроек создаёт резервные копии. Повторный запуск сохраняет существующее одноимённое подключение и обновляет бинарный файл сервера в постоянной папке с резервной копией, если содержимое изменилось. Пользователь уже переключил регистрацию на постоянный путь `%LOCALAPPDATA%\ADT-Personal\mcp\adt_mcp.py`. При обновлении не нужно удалять и повторно регистрировать сервер.
- `../../chatgpt-plugin/` - отдельный публичный пакет навыков ChatGPT (4 навыка). Инструкции работают в облачном чате без локального MCP. **Не** предоставляют доступ к локальному компьютеру и не являются полной копией 80 навыков.
- `tests/` - изолированные тесты на синтетическом Toolkit, включая Git SHA, грязное рабочее дерево, составные запросы и MCP JSON-RPC. Успешную регистрацию и вызов предыдущей версии на Windows/Codex подтвердил владелец для v0.1.6; версия v0.1.7 на его устройстве пока не проверялась.

## Установка на Windows

1. Распакуйте этот архив в отдельную папку, например в `Downloads\ADT-Personal`. Не распаковывайте его в свой проект и не в исходный Toolkit.
2. Откройте PowerShell в распакованной папке.
3. Просмотрите изменения без их выполнения (если нужно):

   ```powershell
   .\Install-ADT-Personal.ps1 -WhatIf
   ```

4. Подключите к Codex:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Install-ADT-Personal.ps1" -Codex
   ```

   Или сразу к Codex и Claude Code:

   ```powershell
   .\Install-ADT-Personal.ps1 -Codex -ClaudeCode
   ```

   Если Toolkit уже локально доступен и загружать его не нужно:

   ```powershell
   .\Install-ADT-Personal.ps1 -Codex -ToolkitPath 'D:\tools\ai-development-toolkit'
   ```

После установки перезапустите Codex/Claude Code. Для проверки выполните `codex mcp get ai-development-toolkit`, `codex mcp list --json` либо `claude mcp list`. Регистрация MCP сама по себе не доказывает, что работающий клиент вызвал инструменты: проверьте один вызов в новой сессии. В чате разработки достаточно запросить, например, «Покрой мой проект тестами» или «Проведи аудит интерфейса». Упоминать ссылку на Toolkit не требуется.

**Важно:** после ручного обновления Toolkit (`git pull` в отдельном каталоге источника) навыки MCP будут читаться из обновлённых файлов без повторной установки. Автообновление намеренно отключено; новое содержимое репозитория считается внешними инструкциями.

## Ручное подключение без скрипта

В Codex CLI:

```powershell
codex mcp add ai-development-toolkit -- python 'C:\full\path\mcp\adt_mcp.py' --source 'C:\full\path\ai-development-toolkit'
```

В Claude Code CLI:

```powershell
claude mcp add --transport stdio --scope user ai-development-toolkit -- python 'C:\full\path\mcp\adt_mcp.py' --source 'C:\full\path\ai-development-toolkit'
```

## Границы и гарантии

- MCP **не** исполняет произвольные команды, не пишет файлы, не редактирует проект и не запускает вложенных агентов. Он только читает объявленные источники Toolkit. Работу делает ИИ-клиент через собственные инструменты.
- Каталог навыков и профилей берётся из `MANIFEST.json`. Маршрутизация естественных фраз эвристическая и не заменяет анализа задачи моделью; это вспомогательный выбор, который ИИ должен уточнить по контексту проекта.
- Операции с проектом, тестами, отчётами, merge/deploy остаются ограничены правилами целевого проекта и полномочиями клиента. Выводы, тесты и временные файлы не сохраняются в Toolkit.
- ChatGPT-плагин не связан с локальным MCP: web-ChatGPT не может напрямую запускать локальный процесс. Для удалённого MCP потребовались бы отдельный защищённый сервер, аутентификация и подключение.
- Требуется Python 3.10+ и установленный Codex/Claude Code для соответствующей настройки. Архив не устанавливает AI-клиентов, не использует платный API и не публикует плагин.
- Для установки без доступа к GitHub используйте `-ToolkitPath`. Для проверки статуса версии после установки можно вызвать `toolkit_info`.

## Разработка и проверки

```powershell
python -m unittest discover -s tests -v
python mcp/adt_mcp.py --source 'C:\full\path\ai-development-toolkit' --check
```

Публикацию и выпуск на GitHub можно делать позднее, после проверки на реальных клиентах.

## Исправление установщика 0.1.1

Исправлена ошибка параметра `[switch]$Codex`, с которым по регистронезависимому сравнению совпадала переменная `$codex`. Теперь исполняемый скрипт Codex хранится в `$codexCommand`. Блок Markdown в глобальном `AGENTS.md` записывается дословно, не теряя обратные кавычки.

Если в предыдущем запуске уже появился каталог `%LOCALAPPDATA%\ADT-Personal\toolkit-source`, повторный запуск повторно ничего не клонирует. Первичный запуск завершился до регистрации в Codex, поэтому версия 0.1.1 продолжит установку с оставшегося этапа.

## Исправление PowerShell v0.1.2

Версия 0.1.1 останавливалась при ожидаемой ошибке `codex mcp get ai-development-toolkit`, пока MCP ещё не зарегистрирован: PowerShell 5.1 с `$ErrorActionPreference = 'Stop'` интерпретировал stderr как завершающую ошибку. Версия 0.1.2 проверяет наличие MCP через успешную команду `codex mcp list --json`; после `mcp add` проверка повторяется. Для Claude Code ожидаемый код ошибки из `mcp get` обрабатывается отдельно, не прерывая установку.

Сервер теперь копируется в `%LOCALAPPDATA%\ADT-Personal\mcp\adt_mcp.py` и Codex регистрируется на этот постоянный путь. Настройки существующих MCP не удаляются. Если ранее вы выполнили ручную команду `codex mcp add` с путём к Downloads, установщик сохранит эту запись и покажет, что сервер уже есть; при этом не удаляйте папку Downloads до ручного переподключения на постоянный путь.

## Обновление персонального MCP v0.1.3 (с версии 0.1.2)

Исправлена маршрутизация составных инженерных задач: основная разработка (`backend`, `frontend`, `fullstack`, `codex-feature`) может сочетаться с одним профильным QA-направлением (`qa-python`, `qa-ui` и т. п.). Возвращаются совместимые поля `profile`, `matched`, `skills`, `roles`, `unavailable`, а также `secondary_profiles`, `profiles`, `priority_skills`, `matches_by_profile`, `deferred_profiles`, `visual_phase`. Совпадения эвристические и не заменяют анализ задачи самой моделью.

Пример: `Создать REST API на FastAPI и покрыть его тестами pytest` => `backend` + `qa-python`; тесты к существующему FastAPI => только `qa-python`. Создание нового сайта или редизайн требуют `ui-orchestra` с визуальным согласованием, а разработка и QA откладываются до следующего этапа. Не запускаются конкурирующие управляющие навыки; `qa-all` по умолчанию не выбирается.

Теперь `toolkit_info` возвращает `source_revision` как фактический SHA коммита локального Git HEAD и `working_tree_status` (`CLEAN_TRACKED` / `MODIFIED_TRACKED` / `UNKNOWN`). Для не-Git источников либо при недоступном Git будет `UNAVAILABLE`, без выдуманного SHA. Проверка Git работает с `GIT_OPTIONAL_LOCKS=0` и не обновляет индекс Git намеренно.

Для обновления установленной персональной копии:

1. Распакуйте **новый** архив в отдельную папку, откройте PowerShell внутри `adt-personal`.
2. Выполните:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Install-ADT-Personal.ps1" -Codex
   ```

3. Убедитесь, что в выводе есть `Installed MCP launcher:`. Установщик сохранит существующую регистрацию и глобальные инструкции. Полностью перезапустите Codex.
4. Проверьте `codex mcp get ai-development-toolkit` и вызовы `toolkit_info`, `toolkit_route_task` в новой сессии.

**Не нужно** запускать `codex mcp remove` или менять `AGENTS.md` вручную. Источник Toolkit останется той же локальной ревизии до отдельного осознанного `git pull`. Обновление MCP не обновляет открытый в ChatGPT приватный плагин: это разные среды исполнения.

## Обновление персонального MCP v0.1.4 - версия сервера и пилот применения

После подтверждённого владельцем сквозного вызова MCP v0.1.3 добавлены:

- Поле `mcp_server_version` (теперь `0.1.4`) и `mcp_protocol_version` в `toolkit_info`. `toolkit_version` по-прежнему обозначает **версию библиотеки Toolkit**, а `source_revision` - SHA его локального Git HEAD. Это три разных сведения.
- Уточнение составной маршрутизации для исправления ошибки в React и добавления Playwright E2E: `frontend` + `qa-ui`. Отдельное исправление тестов pytest не должно превращаться в разработку backend.
- Встроенный воспроизводимый **пилот на временном проекте**, не затрагивающий пользовательские репозитории: `pilot/run_pilot.py`. Он создаёт маленький Python API-контракт с преднамеренно неисправной реализацией и уже заданными тестами. Зависимостей, кроме стандартного Python 3.10+, нет.

### Как провести пилот в Codex (без изменений существующих проектов)

После обновления установленного MCP и перезапуска Codex:

1. В папке `adt-personal` с новым архивом выполните:

   ```powershell
   py -3 .\pilot\run_pilot.py prepare
   ```

2. Команда выведет `workspace` внутри временного каталога Windows (`adt-pilot-*`), статус `baseline: EXPECTED_FAIL` и `prompt_file`. Откройте **только эту временную папку** в Codex Desktop как отдельный проект. В ней есть `service.py`, `test_service.py` и `PILOT_PROMPT.ru.md`.
3. Отправьте в новую сессию Codex содержимое `PILOT_PROMPT.ru.md`. Codex должен показать реальные вызовы MCP, прочитать как минимум один API-навык и один QA-навык, исправить только `service.py` и выполнить тесты. Скрипт сам по себе **не** вызывает Codex и не расходует его лимиты.
4. После выполнения проверьте результат:

   ```powershell
   py -3 .\pilot\run_pilot.py verify --workspace 'C:\Users\<user>\AppData\Local\Temp\adt-pilot-XXXX'
   ```

   **Замените пример пути** на реальное значение `workspace`, полученное на шаге 1. Результат `PASS` проверяет исправленный код, неизменность тестового контракта и прохождение десяти тестов.

**Ограничение доказательств:** `PASS` от `verify` доказывает только работоспособность результата в изолированной папке. Скрипт честно сообщает `mcp_usage_evidence: NOT_VERIFIED_FROM_FILES`; факт вызовов навыков и связь требований с кодом оцениваются отдельно по реальной истории инструментов в Codex. Успешный вызов/чтение навыка сам по себе не доказывает полезность навыка относительно разработки без Toolkit. Для измерения эффекта нужен сопоставимый контрольный эксперимент.

Для обычного обновления достаточно распаковать v0.1.4 в отдельную папку и запустить `Install-ADT-Personal.ps1 -Codex`, как для v0.1.3; сервер будет заменён с резервной копией, настройки существующих MCP и `AGENTS.md` сохранятся. Не удаляйте и не переименовывайте текущий MCP в Codex. **ChatGPT-плагин не обновлялся** в этом выпуске.

## Версия 0.1.5 - устойчивость маршрутизатора и проверка задержек

Исправлено определение задач «исправь дефект/ошибку REST API и проверь тестами». Для этого текста возвращаются основной профиль `backend` и дополнительный `qa-core`. Исправлены ответы на неожиданные внутренние исключения: JSON-RPC-ошибка возвращает исходный `id` запроса, чтобы клиент не ожидал ответа с потерянным идентификатором. Причина ранее наблюдавшегося 20-секундного ожидания в Codex пока не установлена.

Обновите установленный MCP штатным `Install-ADT-Personal.ps1 -Codex`, как при предыдущих обновлениях. Затем проведите **автономную диагностику без Codex** из распакованной папки:

```powershell
py -3 .\diagnose_mcp.py
```

Скрипт использует `%LOCALAPPDATA%\ADT-Personal`, вызывает установленный MCP напрямую по stdio (45 запросов) и выводит JSON со статусом, числом ответов и задержкой. Он не меняет проекты, не запускает Codex и не использует сеть. `PASS` означает работоспособность локального транспорта; он **не** доказывает, что хост Codex всегда будет отвечать вовремя. В случае `FAIL` пришлите JSON целиком (без секретов и токенов). Для повторной проверки в Codex после перезапуска запустите отдельный `toolkit_route_task` с запросом из пилота и сохраните фактический результат.

Проверки пакета v0.1.5 на синтетическом Toolkit: 16/16 PASS. Проверка на пользовательском Windows в этом выпуске ещё не выполнена.


## Версия 0.1.6 - Windows UTF-8 и корректная проверка старого пилота

Версия 0.1.5 обнаружила на Windows две проблемы, не связанные с автоматическим подбором профилей:

1. При выводе stdio JSON-RPC на Windows Python мог использовать системную ANSI-кодировку вместо UTF-8. Это нарушало транспортный контракт для русскоязычных значений. Сервер теперь записывает байты `utf-8` непосредственно в `sys.stdout.buffer`. Диагностический скрипт использует бинарные потоки и выдаёт точный код `MCP_STDOUT_NOT_UTF8`, если получает неверную кодировку; ошибки ответов JSON-RPC различаются отдельно.
2. Пилот `prepare` на Windows записывал исходные тесты через `Path.write_text()` в формате CRLF, но в маркере сохранял SHA-256 от строки LF. Из-за этого `verify` мог ошибочно возвращать `test_contract_unchanged: false` даже при неизменённых тестах. Новый `prepare` пишет байты с фиксированными переводами строк. `verify` поддерживает старые фикстуры версии 1, требуя точного совпадения с одним из **двух** канонических вариантов (LF или CRLF); любые другие изменения исходных тестов по-прежнему отклоняются. Изменение только переводов строк в `service.py` больше не считается исправлением реализации.

**Установка v0.1.6**: распакуйте архив в `Downloads/ADT-Personal-0.1.6` и запустите `Install-ADT-Personal.ps1 -Codex` привычной командой с `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`. Повторная регистрация MCP не требуется. Затем:

```powershell
py -3 "$HOME\Downloads\ADT-Personal-0.1.6\adt-personal\diagnose_mcp.py"
py -3 "$HOME\Downloads\ADT-Personal-0.1.6\adt-personal\pilot\run_pilot.py" verify --workspace "C:\Users\<user>\AppData\Local\Temp\adt-pilot-bcxf9vh_"
```

**Важно:** `verify` из нового пакета ничего не изменяет в существующем пилотном каталоге; новый `prepare` не требуется. Ожидаемая диагностика: 45/45 ответов и `PASS`. Ожидаемый результат старого пилота: `test_contract_unchanged: true`, `test_contract_line_endings: CRLF` (если файл сохранил прежние Windows-переводы строк), 10/10 тестов и `PASS` при неизменённых тестах и исправленной реализации. Если тестовый файл реально менялся, `FAIL` останется правильным результатом.

Проверки пакета на Python 3.13: **19/19 PASS**, включая имитацию `PYTHONIOENCODING=cp1251`, тесты протокола и контроль прежней фикстуры с CRLF. Повторная проверка на Windows и хосте Codex: **NOT_RUN**. Приватный ChatGPT-плагин и публичный репозиторий Toolkit этим выпуском не изменяются.

## v0.1.7: глобальный MCP для рабочего проекта

На корпоративном ПК без записи в рабочий репозиторий используйте `toolkit_prepare_task`.
Он сопоставляет предложенные профили со списками `existing_skills` и `existing_roles`,
которые Codex собрал из доступных уровней проекта/пользователя, и возвращает тексты
необходимых инструкций и роли на текущую задачу. Это динамическое чтение (`GUIDANCE_ONLY`),
а не физическая установка/регистрация навыка или создание субагента.
Полная инструкция: [WORK-LAPTOP.ru.md](WORK-LAPTOP.ru.md).

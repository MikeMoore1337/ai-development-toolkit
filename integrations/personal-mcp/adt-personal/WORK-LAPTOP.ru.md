# AI Development Toolkit MCP 0.1.7: рабочий ноутбук, Codex и локальный проект

> **Linux и macOS:** универсальные инструкции находятся в [`integrations/personal-mcp/README.ru.md`](../README.ru.md). Этот внутренний документ сохраняет подробности первоначальной реализации для Windows.


## Как работает подключение

По умолчанию используется **глобальный MCP пользователя Windows**, а не установка навыков в рабочий репозиторий:

1. Codex открывает конкретную рабочую папку, читает действующие `AGENTS.md`, настройки и доступные имена skills/agents на разрешённых уровнях (проект, родительские каталоги и пользовательский уровень).
2. Глобальный `~/.codex/AGENTS.md` рекомендует для задач разработки/QA автоматически вызвать `toolkit_prepare_task` из `ai-development-toolkit`.
3. MCP выбирает основной профиль + дополнительные (если запрос составной), сравнивает их с перечисленными Codex `existing_skills`/`existing_roles` и возвращает содержимое нескольких недостающих `SKILL.md`/role-файлов **в контекст текущей задачи**.
4. Codex применяет методики, но не записывает их на диск проекта. Это **не установка нативного навыка** и не запуск отдельного субагента. Настоящее применение зависит от решения модели и требует проверки в реальной сессии.
5. Если нужно физически установить навык в проект, это отдельная операция: использовать `skill_manager.py install` (предпросмотр), а `--apply` - только после прямого разрешения владельца проекта.

MCP не получает путь рабочего проекта и не читает его файлы самостоятельно; списки имён поступают от Codex, и полнота списка не доказывается сервером. MCP не выполняет команды и не отправляет код проекта в GitHub. Сам Codex может передавать контекст модели в рамках своей политики и настроек - для рабочих данных это должно быть разрешено организацией.

## Установка на новый Windows-ПК

Требуется: установленный Codex CLI, рабочие команды `git` и `py -3`, разрешённый доступ к GitHub и выполнение пользовательских скриптов, права организации на использование AI-инструментов для рабочих данных. Права администратора для обычной установки в пользовательский профиль не требуются. Если GitHub запрещён, возможно указать уже разрешённую локальную копию Toolkit через `-ToolkitPath`.

1. Распакуй `AI-Development-Toolkit-Personal-MCP-0.1.7.zip` в `Downloads\ADT-Personal-0.1.7`.
2. Из PowerShell выполни:

```powershell
$package = "$HOME\Downloads\ADT-Personal-0.1.7\adt-personal"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$package\Install-ADT-Personal.ps1" -Codex
```

При запрещающей групповой политике запуск сценариев может быть заблокирован; не обходи организационные ограничения. Инсталлятор создаёт/читает `%LOCALAPPDATA%\ADT-Personal\toolkit-source`, кладёт сервер в `%LOCALAPPDATA%\ADT-Personal\mcp`, регистрирует глобальный MCP и обновляет **только принадлежащий ему блок** в `~\.codex\AGENTS.md`, предварительно сохраняя копию существующего файла. Рабочий проект не меняется.

3. Перезапусти Codex и открой **рабочую папку проекта**, не копию Toolkit. Проверь регистрацию:

```powershell
codex mcp get ai-development-toolkit
py -3 "$env:LOCALAPPDATA\ADT-Personal\mcp\adt_mcp.py" --source "$env:LOCALAPPDATA\ADT-Personal\toolkit-source" --check
```

В новом диалоге (однократная проверка) попроси: «Вызови `toolkit_prepare_task` для задачи "Сделай FastAPI и тесты pytest", указав имена уже доступных навыков и ролей. Покажи `primary_profile`, `secondary_profiles`, `loaded_skills` и `loaded_roles`. Ничего в проекте не изменяй».

Ожидаемые профиль: `backend` и дополнительный `qa-python`, а в `loaded_skills` только подходящие недостающие инструкции. При `existing_skills` не переданном результат будет `NOT_PROVIDED` без ложного утверждения, что навыков нет.

4. Дальше ставь обычные задачи Codex. URL Toolkit в каждом запросе не нужен.

## Автообновление содержимого Toolkit (не сервера MCP)

По желанию установи планировщик из того же архива **после** разрешения организации:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$package\Enable-ADT-AutoUpdate.ps1"
Get-ScheduledTask -TaskName ADT-Personal-Toolkit-Update | Select-Object TaskName, State
py -3 "$env:LOCALAPPDATA\ADT-Personal\updater\update_toolkit.py" --status
```

Содержимое Toolkit будет проверяться по расписанию из GitHub. Это не обновляет `adt_mcp.py`: новые версии MCP устанавливаются отдельным проверенным архивом. Перезапусти Codex, чтобы долго работающий MCP перечитал каталог после обновления. Важно: автоматический `git pull` в корпоративной среде разрешён только если политика компании допускает его.

## Безопасность и откат

- Приоритет у правил рабочего репозитория, обязательных проверок и ограничений доступа.
- По умолчанию нет установки `.agents/skills`/`.codex/agents` в рабочую папку, логов и вспомогательных файлов в ней.
- Установленные пользователем навыки не перезаписываются.
- Старый сервер сохраняется как `adt_mcp.py.adt-backup-*`. Глобальный `AGENTS.md` также сохраняется как `AGENTS.md.adt-backup-*` при изменениях.
- При ошибке запуска `toolkit_prepare_task` можно продолжить с уже имеющимися навыками проекта, но нужно указать, что MCP не сработал.

# Toolkit implementation
Start through `toolkit-task-router`. Inspect relevant project guidance and current architecture. Scope the change, list acceptance criteria, choose a narrow profile, and read applicable Toolkit source skills when actually accessible. Preserve public contracts; avoid unnecessary dependencies or wholesale rewrites. Distinguish code you propose in chat from code you have actually changed. Only create or modify files inside an authorized project context. Write targeted positive, negative and regression tests where appropriate. Provide evidence of actual verification, and mark checks `NOT_RUN` or `BLOCKED` when not executed. Default to delivery in chat, not auxiliary files in the user's repository.

## Tool-native creative freedom

The original design tools govern their own work as intended. **No Toolkit-imposed UI/UX style bans or quotas**: hero, cards, SaaS structures, grids, gradients, glass, dark/light palettes, typography, photography, motion and familiar retail layouts may all be used when appropriate. The user may ask for one concept or several. When design alternatives are created, draw and inspect the variants actually produced; never mandate three just to satisfy a checklist. Do not penalize an otherwise attractive design only for using common UI patterns.

Keep the strongest existing visual reference if the user preferred or approved it. Compare an attempted replacement with that actual baseline for layout, typography, imagery, expression and usability; do not discard a richer earlier design because a later one achieves a technical PASS. The user's visual decision is authoritative.

Present genuine relevant previews where tools are available and keep aesthetic judgments separate from code/viewport/accessibility checks. Stop before modifying a target application's unapproved design. No user images/reports belong in Toolkit, no independent installation or invocation is implied by this plugin file, and approvals of merge/release/deploy are separate.

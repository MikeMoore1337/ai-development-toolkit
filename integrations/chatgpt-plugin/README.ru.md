# AI Development Toolkit - плагин ChatGPT

**Для кого:** пользователи ChatGPT, которые хотят описывать задачу обычными словами и получать подходящие навыки Toolkit без настройки локального сервера, терминала и платного API. При выборе плагина маршрутизатор подбирает инструкции по разработке, тестированию, UX/UI и DevOps. Это **плагин с навыками**, а не доступ к компьютеру.

## Поддерживаемые системы

ОС установки не имеет значения: ChatGPT используется на **Windows, Linux, macOS** или мобильном устройстве, если в текущем клиенте доступны пользовательские плагины. Никаких PowerShell, shell-скриптов, Docker или локального MCP для этого не нужно. Возможность самостоятельной загрузки плагинов зависит от возможностей учётной записи и клиента; один только репозиторий не устанавливает его автоматически.

## Установка из репозитория

1. Открой [`integrations/chatgpt-plugin/`](../chatgpt-plugin/) в репозитории. Получи собранный пакет `AI-Development-Toolkit-ChatGPT-Plugin-0.1.2.zip` из проверенного релиза проекта либо собери из клонированного Toolkit (см. ниже). В публичный репозиторий добавляются **исходники**, а не заранее установленный личный плагин.
2. Открой интерфейс создания плагинов ChatGPT, **если он доступен** в твоей учётной записи, и импортируй ZIP. Следуй указаниям интерфейса. При отсутствии возможности импортировать архив используйте [разговорный режим](#другие-чат-боты).
3. В новой беседе явно выбери или упомяни **AI Development Toolkit** и проверь тестовым запросом ниже. Изменение исходников в GitHub **не означает** автоматическое обновление установленного архива плагина.

### Сборка ZIP без API

При наличии локальной копии репозитория:

```bash
python3 integrations/build_packages.py
```

На Windows можно использовать `py -3 integrations/build_packages.py`. В `integrations/dist/` появится ZIP плагина. Папка `dist/` - локальная сборка, её не следует коммитить в репозиторий.

## Как пользоваться

Пример обычного запроса:

> Проведи ревью Python API по навыкам Toolkit: найди риски, предложи проверки и подготовь тест-кейсы. Используй файлы, которые я прикрепил. Не изменяй исходники.

Плагин должен определить нужный профиль и применить **реально доступные** инструкции. Для актуальных навыков при наличии доступа к GitHub читаются файлы согласованной ревизии с проверкой условий из `MANIFEST.json`; при отсутствии доступа применяется встроенный набор (`FALLBACK_BUNDLED`). Не утверждай, что живое чтение произошло, если файлы не были действительно получены. Роль - это руководство, **не** отдельный запущенный субагент.

### Подключение рабочего проекта

Передай файлы проекта в беседу, используй разрешённый доступ к GitHub или другой подключённый источник. Плагин **не читает автоматически** код локального ПК, IDE и установленный на ноутбуке MCP; наличие плагина не снимает корпоративные ограничения. Для работы с конфиденциальным кодом сначала проверь политику работодателя и разрешения источника.

### Обновления

Когда доступны инструменты чтения GitHub, плагин способен запросить инструкции Toolkit при выполнении задачи. Это **не** переустановка самого плагина и не гарантированная фоновая синхронизация. Новые версии оболочки плагина устанавливаются отдельно после выпуска. Не обещайте живое обновление в офлайн-чате.

## Другие чат-боты

Архив ChatGPT-плагина **не является универсальным форматом** для Claude, DeepSeek, Qwen и других чат-клиентов. Там, где нет поддержки этого формата, используется текстовый режим: передай ссылку на [`AGENT_START.ru.md`](../../AGENT_START.ru.md), опиши задачу, дай клиенту разрешённые файлы проекта и попроси выбрать минимальные подходящие навыки. При отсутствии доступа к GitHub предоставь конкретные `SKILL.md` из Toolkit. Нельзя утверждать, что чат-бот установил плагин или прочитал репозиторий, пока этого не произошло.

## Ограничения

- Пользователю **не нужен API-ключ** для пакета навыков, но сама возможность установки зависит от ChatGPT.
- Плагин не создаёт MCP-соединение с ноутбуком и не устанавливает нативные навыки в чужой проект.
- Исходники в репозитории не включают идентификаторы личных плагинов, токены и права доступа.
- Обновление плагина требует действий в самом ChatGPT; сборка ZIP не обновляет действующую личную установку владельца.

## Неформальные запросы и SEO

**Обычный запрос выполняется сразу**: «сделай сайт», «исправь баг» или «проверь SEO» - без промежуточного промпта, который пользователю пришлось бы повторно отправлять. Встроенный `toolkit-seo-audit` формирует проверяемый SEO-отчёт, но не придумывает позиции, индексацию и трафик.

**По прямой просьбе составить промпт** («вот черновик, сделай хороший промпт для Codex») используется отдельный `toolkit-prompt-refinement` и выдаётся один готовый промпт. Доступ к IDE не предполагается. Оба режима работают без платного API и не меняют ограничения на права записи.

## Отличие публикации исходников от личного плагина (#190)

[Закреплённый релиз исходных ZIP](../../docs/ru/INTEGRATION_SOURCE_RELEASES.md) **не** является новой версией установленного личного ChatGPT-плагина. Для приватного плагина отдельно проверяют текущий release и соблюдают правила его обновления; не импортируют публичный архив поверх иной установленной версии автоматически.

# AI Development Toolkit - плагин ChatGPT

**Для кого:** пользователи ChatGPT, которые хотят описывать задачу обычными словами и получать подходящие навыки Toolkit без настройки локального сервера, терминала и платного API. При выборе плагина маршрутизатор подбирает инструкции по разработке, тестированию, UX/UI и DevOps. Это **плагин с навыками**, а не доступ к компьютеру.

## Обычный ChatGPT - основной сценарий без Work и Codex

В обычной беседе выберите установленный плагин **AI Development Toolkit** и опишите реальную задачу. **Work, Codex CLI/Desktop и платный API не требуются**, если эта задача выполнима уже доступными средствами ChatGPT. Пользователю не нужно запускать отдельные Skills, MCP-сервер или скрипты. ChatGPT выбирает маршрут Toolkit и вызывает разрешённые инструменты самостоятельно **в текущем чате**.

В зависимости от возможностей конкретного сеанса ChatGPT может использовать свою Python/контейнерную среду для файлов и браузерного тестирования, подключённый GitHub для работы с репозиториями и CI, другие разрешённые приложения для целевого проекта. Если нужного исполнителя/доступа нет, плагин обязан указать точную границу, а не выдавать чтение инструкций за реальную установку или запуск оригинальных навыков.

**Наблюдаемый тест без Work (01.11.2026):** в стандартном ChatGPT действительно запущены Python, Chromium и Playwright на синтетическом HTML-прототипе, созданы снимки 1440×900 и 390×844 и проверены клики, отсутствие ошибок JavaScript и горизонтального переполнения. Это не доказательство вызова оригинальных Impeccable/Taste/UI UX Pro Max и не гарантия наличия такой среды у всех пользователей.

Источниковый маршрут описан в [NORMAL_CHAT_EXECUTION.md](ai-development-toolkit/skills/toolkit-task-router/references/NORMAL_CHAT_EXECUTION.md). Он не даёт плагину новых прав доступа, не обеспечивает фоновую работу и не отменяет обычные лимиты ChatGPT.

## Альтернативная установка через GitHub для совместимых настольных клиентов

**Публиковать плагин в общем каталоге не нужно.** В репозитории есть `.agents/plugins/marketplace.json`. Пользователь с Codex CLI добавляет GitHub как источник одной командой:

```sh
codex plugin marketplace add MikeMoore1337/ai-development-toolkit
```

**Команда добавляет источник, но не устанавливает сам плагин.** Перезапустите поддерживаемый ChatGPT Desktop Work/Codex, откройте Plugins Directory, выберите **AI Development Toolkit (local)** и установите **AI Development Toolkit**. Проверьте его в новом чате. Альтернатива - открыть локальную копию проекта или добавить её командой `codex plugin marketplace add ./путь/к/ai-development-toolkit`. [Пошаговая инструкция](../../docs/ru/ONE_COMMAND_SETUP.md).

Это не автоматическая установка для браузерного и мобильного ChatGPT. Версия исходников плагина `0.1.5` отличается от персонально установленной версии. Подача на модерацию или публичная публикация не нужны.

## Поддерживаемые системы

В **Windows, Linux и macOS** импорт ZIP (если он поддерживается) выполняется **в самом ChatGPT**. Установка из GitHub через каталог репозитория - отдельный способ для поддерживаемого настольного ChatGPT/Codex. Локальный MCP и платный API не требуются. GitHub сам по себе не устанавливает плагин в чат.

## Установка из репозитория

1. Откройте [исходники плагина](README.md) в репозитории и соберите пакет `AI-Development-Toolkit-ChatGPT-Plugin-0.1.5.zip` из проверенной копии Toolkit (см. ниже). Если такой пакет уже опубликован, можно взять его из проверенного релиза. В репозиторий добавляются **исходники**, а не заранее установленный личный плагин.
2. Откройте интерфейс создания плагинов ChatGPT, **если он доступен** в твоей учётной записи, и импортируй ZIP. Следуй указаниям интерфейса. При отсутствии возможности импортировать архив используйте [разговорный режим](#другие-чат-боты).
3. В новой беседе явно выберите или упомяните **AI Development Toolkit** и проверьте тестовым запросом ниже. Изменение исходников в GitHub **не означает** автоматическое обновление установленного архива плагина.

### Сборка ZIP без API

При наличии локальной копии репозитория:

```bash
python3 integrations/build_packages.py
```

На Windows можно использовать `py -3 integrations/build_packages.py`. В `integrations/dist/` появится ZIP плагина. Папка `dist/` - локальная сборка, её не следует коммитить в репозиторий.

## Как пользоваться

Пример обычного запроса:

> Проведи ревью Python API по навыкам Toolkit: найди риски, предложи проверки и подготовь тест-кейсы. Используй файлы, которые я прикрепил. Не изменяй исходники.

Плагин должен определить нужный профиль и применить **реально доступные** инструкции. Для актуальных навыков при наличии доступа к GitHub читаются файлы согласованной ревизии с проверкой условий из `MANIFEST.json`; при отсутствии доступа применяется встроенный набор (`FALLBACK_BUNDLED`). Не утверждайте, что живое чтение произошло, если файлы не были действительно получены. Роль - это руководство, **не** отдельный запущенный субагент.

### Подключение рабочего проекта

Передайте файлы проекта в беседу либо используйте разрешённый доступ к GitHub или другому подключённому источнику. Плагин **не читает автоматически** код локального ПК, IDE и установленный на ноутбуке MCP; наличие плагина не снимает корпоративные ограничения. Для работы с конфиденциальным кодом сначала проверьте политику работодателя и разрешения источника.

### Обновления

Когда доступны инструменты чтения GitHub, плагин способен запросить инструкции Toolkit при выполнении задачи. Это **не** переустановка самого плагина и не гарантированная фоновая синхронизация. Новые версии оболочки плагина устанавливаются отдельно после выпуска. Не обещайте живое обновление в офлайн-чате.

При совместимом источнике schema 2 клиент загружает только нужные текущему этапу навыки ограниченными порциями и может запрашивать дополнительные на следующих этапах без общего лимита. Клиент сам инициирует вызовы и учитывает инструкции, оставшиеся в контексте. Опубликованный источник schema 1 сохраняет прежний лимит источников на задачу до обновления источника. Это контракт инструкций, а не доказательство автоматического поведения клиента.

## Другие чат-боты

Архив ChatGPT-плагина **не является универсальным форматом** для Claude, DeepSeek, Qwen и других чат-клиентов. Там, где нет поддержки этого формата, используется текстовый режим: передайте ссылку на [`AGENT_START.ru.md`](../../AGENT_START.ru.md), опишите задачу, предоставьте клиенту разрешённые файлы проекта и попросите выбрать минимальные подходящие навыки. При отсутствии доступа к GitHub предоставьте конкретные `SKILL.md` из Toolkit. Нельзя утверждать, что чат-бот установил плагин или прочитал репозиторий, пока этого не произошло.

## Ограничения

- Пользователю **не нужен API-ключ** для пакета навыков, но сама возможность установки зависит от ChatGPT.
- Плагин не создаёт MCP-соединение с ноутбуком и не устанавливает нативные навыки в чужой проект.
- Исходники в репозитории не включают идентификаторы личных плагинов, токены и права доступа.
- Обновление плагина требует действий в самом ChatGPT; сборка ZIP не обновляет действующую личную установку владельца.

## Неформальные запросы и SEO

**Обычный запрос выполняется сразу**: «сделай сайт», «исправь баг» или «проверь SEO» - без промежуточного промпта, который пользователю пришлось бы повторно отправлять. Встроенный `toolkit-seo-audit` формирует проверяемый SEO-отчёт, но не придумывает позиции, индексацию и трафик.

**По прямой просьбе составить промпт** («вот черновик, сделай хороший промпт для Codex») используется отдельный `toolkit-prompt-refinement` и выдаётся один готовый промпт. Доступ к IDE не предполагается. Оба режима работают без платного API и не меняют ограничения на права записи.

## Отличие публикации исходников от личного плагина (#190)

[Закреплённый релиз исходных ZIP](../../docs/ru/INTEGRATION_SOURCE_RELEASES.md) **не** является новой версией установленного личного ChatGPT-плагина. Для приватного плагина отдельно проверяют текущий release и соблюдают правила его обновления; не импортируют публичный архив поверх иной установленной версии автоматически.

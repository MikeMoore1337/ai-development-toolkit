# Оригинальный Issue-Orchestrator - пилот интеграции Toolkit #570

**Состояние на 16.11.2026:** исходный движок успешно запускался в WSL2 через Codex CLI с авторизацией ChatGPT, но завершение Stage 2 остановилось на внутреннем обмене ревью. Задача #20 хранит проверенный код в `recovery-pending`, #21 ещё не запускалась. **Автономная публикация не подтверждена.** Этот каталог - переносимый шаблон и документация интеграции, не включённый планировщик. Сквозная приёмка отделена в [#589](https://github.com/MikeMoore1337/ai-development-toolkit/issues/589).

## Что действительно проверено

В закреплённой версии [issue-orchestrator/issue-orchestrator](https://github.com/issue-orchestrator/issue-orchestrator) 0.10.0 (`d4a79824ccd806089cf3f70ec632d39b8ee255ea`) реализованы очередь GitHub Issues, зависимости, Codex CLI, рабочие деревья Git, quick/publish-проверки, независимые рецензенты и восстановление. Настройка позволяет `WIP=1` и сохраняет человеческое слияние PR. Не нужно дублировать эти механизмы внутри Toolkit.

В первом физическом WSL2-пилоте задачи #7 и #8 закрыты, PR #15, #17 и #18 слиты, соответствующий CI прошёл. Исходный движок выполнил кодирование и последовательный переход #7 -> #8, но публикация PR #17 потребовала ручного исправления Git `stale info`. Поэтому сквозную автоматическую публикацию **не следует считать подтверждённой**.

Сохранённая запись #7 `divergent_validated_heads` была разрешена **оригинальным владельцем записи** после подтверждённого одобрения предложения #19. Физическая проверка дала `RELEASE_APPLIED_BY_ORIGINAL_OWNER=PASS`, `IO570_TERMINAL_RELEASE_VERIFIED=PASS`, состояние `abandoned/operator_abandoned`; GitHub подтвердил снятие `recovery-pending`. После холодного запуска и завершения с кодом 0 повторная проверка сохранения результата также прошла. Это не доказывает полную автономную доставку.

Во втором пилоте используются синтетические Issues **#20 -> #21**, зависимость `Depends-on: #20`. Подготовительный PR #22 и исправление выделенных host-only Git-тестов PR #23 слиты; текущая защищённая ветка пилота имеет SHA `238ab2fdd4128250b10b9856e83ddee1249fbbb4`. Владелец физически запустил оригинальный движок с `WIP=1` и Codex через ChatGPT и восстановил #20 штатным `unblock-retry`.

Агент #20 подготовил `to_rankine`, независимый ревьюер обнаружил переполнение при `9e307`, после чего агент изменил только `converter.py` и `tests/test_converter.py`. Полная исходная проверка `python -m unittest discover -s tests -v` прошла на локальном `cfa666c26a1d17a101b498bdbb1d1115309a7e42`. Однако ревьюер запрашивал новую аттестацию на этом SHA, persistent coder не завершил три цикла обмена (`coder_no_completion`), в журнале были ответы HTTP 401 на `/api/completion/submissions`. Оригинальный движок сохранил работу как `parked` и применил `recovery-pending`; **ни одного автоматически опубликованного PR для #20 нет**. #21 остаётся `blocked-cross-milestone`.

Для причины несовместимости callback-окружения подготовлен черновой PR #24 в изолированном пилоте (ссылка и доказательства в Toolkit Issue #589) с проходящим CI, но физическая приёмка и активация исправления не проводились. Оставшаяся автономная публикация, восстановление и выполнение #21 отслеживаются **только в [#589](https://github.com/MikeMoore1337/ai-development-toolkit/issues/589)**. Нельзя считать source-only интеграцию доказательством E2E.

## Границы безопасности

- **Оригинал закреплён:** SHA `d4a79824ccd806089cf3f70ec632d39b8ee255ea`, версия 0.10.0, лицензия Apache-2.0. Заплатка на Git-публикацию применяется **только по явной переменной** в изолированной копии оригинального исходника для Stage 2. Заплатка проверяет точный SHA удалённого ref, ancestry и CAS через `--force-with-lease=refs/heads/<branch>:<sha>`; не расширяет разрешённые ветки, не отключает хуки и не создаёт альтернативный издатель PR.
- **Провайдер:** только Codex CLI с авторизацией через ChatGPT. Платные API, ключи `OPENAI_API_KEY`/`CODEX_API_KEY`, Claude CLI и автоматические покупки запрещены. Проверки контейнера GitHub Actions не доказывают наличие доверенного runtime и изоляцию токенов на физическом WSL2.
- **Границы Issues:** `filtering.label` в оригинале изменяемый; `filtering.issue` принимает только одну Issue. `max_to_start: 2` ограничивает количество запусков, но **не является неизменяемым списком ID**. В отдельном, контролируемом владельцем синтетическом репозитории дополнительно есть предварительная проверка точных #20/#21 и отсутствия третьей открытой Issue. Она одноразовая и не превращается в непрерывный барьер допуска. Для многопользовательского production такая защита недостаточна.
- **Запуск:** этот шаблон не разрешает новых запусков; отдельный физический пилот уже запускался по специальному согласию владельца. Для повторного запуска необходимы точный source SHA, независимая проверка CI, безопасный WSL2 no-model probe, действующий Codex ChatGPT login, согласованные Git refs, **отдельная команда владельца на активацию**, и только затем исходный движок с `WIP=1`. Слияния PR оставляются за человеком.
- **Недоказанное:** автономная публикация PR от оригинального движка, принятие независимого review на новом SHA, доставка #21 после human merge, штатное восстановление удержанного кода и применение к другим проектам. Эти критерии перенесены в #589; исходная интеграция Toolkit остаётся отключённой по умолчанию.

Сопутствующий документ `docs/ISSUE_ORCHESTRATOR.md` относится к прежнему #565 и **не является** инструкцией запуска нового движка. Не запускай два контроллера одновременно.

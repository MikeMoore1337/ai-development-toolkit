# ADT Development
1. Inspect the actual project rules, branch, architecture, dependency versions and tests before changing code.
2. Use `toolkit_prepare_task` for the specific request; read only relevant ADT implementation/backend/frontend/fullstack skills. Reassess with `toolkit_prepare_stage` when the task moves from implementation to review.
3. Make the smallest complete change using Cursor's authorized project tools; never claim the read-only MCP edited files.
4. Run focused tests and necessary regression checks; report commands, results, changed files and unresolved risks.
5. Leave merge, releases and production to their existing approval process. If MCP is unavailable, report that and use only actually available, reviewed local skill instructions.

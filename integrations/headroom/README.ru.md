# Headroom - экспериментальный офлайн-шлюз приёмки (Issue #336)

**Решение:** не включать компрессию во время реальной работы, пока она не сохраняет доказательства без потерь и не показывает измеримую пользу. Toolkit **не содержит** копии Headroom или нового движка сжатия.

## Исходный проект

- Оригинал: https://github.com/headroomlabs-ai/headroom
- Зафиксированный коммит: `3fef15d376d9899f77a28464e2e91f8b99514930`
- Python package: `headroom-ai==0.41.0`, лицензия Apache-2.0
- Подключение **необязательно** и только для изолированной песочницы.
- Каталог личных сессий, Claude/Codex hooks, глобальную конфигурацию или приватные рабочие файлы не читать и не изменять.

## Подтверждённые измерения: 25.10.2026

Проверены функции **оригинального** Headroom 0.41.0 в изолированном Linux/Docker окружении с памятью 512 MiB. Использовались статичные синтетические данные и локальный tokenizer, без запросов AI. ONNX Runtime в этом окружении недоступен (pure-Python fallback).

**Важно:** все приведённые значения - локальная оценка токенизации синтетических материалов. Не измерены токены по платёжным или подписочным лимитам, cached input/output реального клиента, скорость решения задач и качество ответа модели. Это не экономия по счёту и не свидетельство поддержки Windows.

## Как воспроизвести без платной реализации

Из **временной изолированной** среды с Python 3.10+ после ручной проверки официального wheel/dependencies:

```sh
# Выполняется только внутри disposable sandbox, не в пользовательском Codex.
python3 scripts/headroom_offline_adoption_gate.py
python3 -m unittest discover -s tests -p test_headroom_offline_adoption_gate.py -v
```

При отсутствии оригинального Headroom скрипт выдаёт `BLOCKED/upstream_not_installed`, exit 3. При `NO_GO` - exit 2. Только при **одновременных** `lossless=True`, сохранении критичных доказательств и экономии не меньше 5% - `PILOT_ELIGIBLE`, exit 0. `PILOT_ELIGIBLE` **не разрешает** установку в клиент и не означает готовность production.

Проверяются токены до/после, целостность SHA/approval/deploy/CI и независимая метка Headroom `lossless`. Любая ошибка оригинальной библиотеки скрывает текст исключения, чтобы не раскрыть содержимое tool output.

Скрипт не принимает путь к пользовательскому файлу, не устанавливает hooks и не вызывает Codex CLI. `model='gpt-4o'` используется **только как идентификатор токенизатора**, а не для вызова OpenAI API.

## Решение и дальнейшая эксплуатация

**На текущих данных: NO-GO для активации компрессора в рабочем агенте.** Потенциально полезные 23,14% получены в непроверенном на полную обратимость режиме, а безопасный режим с проверкой обратимости не сэкономил токены.

- Зафиксировать кодовой релиз только как **необязательный offline evaluation gate**.
- Не делать форк Headroom ради изменения метрик. Если в новой официальной версии появится безопасное сжатие для нужных типов данных, достаточно повторить тест с закреплённой новой версией и записать отдельное решение.
- Native Windows-интеграция, реальные пользовательские сессии, A/B на настоящем агенте: `NOT_VERIFIED`; при запрете Codex CLI и отсутствии native Windows доступа не имитировать приёмку.
- Откат источникового изменения - удаление этого независимого шлюза и его теста через обычный PR; работающие службы и клиенты не затронуты.

Результат `NO_GO` следует считать **завершением принятия решения по эксперименту**, а не недоделанной production-интеграцией.
